# v29 系列 · 模型层契约与 native adapter

> 核心：定义模型契约，并把现有 DeepSeek / 豆包包成 native adapter。
> 第三方 provider 接入在 v30。
> 核心 provider 仍是 native，不注册为插件。

```python
class ModelProvider(Protocol):
    name: str
    def capabilities(self) -> set[str]: ...
    async def complete(self, req: ModelRequest) -> ModelReply: ...
```

## 本层插件接口约束（v27 总纲）

> 跨版本总纲：[INTERFACE-PLAN-v27-v44.md](../INTERFACE-PLAN-v27-v44.md)

- 本版只开放**模型层**接口，不把其他层一起搬。
- 能力名：`model.<name>@1`。
- 核心 native（DeepSeek / 豆包）保持 native，**不实现 PluginManifest，不进入插件表**。
- 第三方实现本层 Protocol，通过 v27 `PluginRegistry` 注册。
- 业务只依赖 Protocol；`get()` 拿不到时回落核心 native。
- 敏感资源走 v27 权限三档（0 拒绝 / 1 询问 / 2 允许），默认 1。
- 插件任务、线程池、DB 连接池由 v27 context 提供，不允许裸 `create_task` / 裸连库。
- 插件失败写 `plugin_errors`，连续失败自动停用。
- 插件 DDL 走 `migrations/`，只支持 MySQL/SQLite，表前缀 `plugin_<name>_`。
- 热更采用 worker 进程级快照；已启用插件在新 worker 自动加载。

## v29.3 · 蓝绿发布环境门禁

规则：

```text
任何新版本进入蓝绿 worker 前
→ 必须跑 checks/env_check.py
→ 生成 data/env_report.json
→ 没有报告 / 报告过期 / config hash 不符
→ 禁止 prepare_worker，禁止 supervisor 切换
```

`env_report.json` 至少记录：

```text
生成时间
代码版本
config hash
schema_version
features 可用性
依赖检查结果
```

门禁位置：

- `prepare_worker.py`：拒绝创建新版本目录。
- `nao_supervisor.py`：切换 current 前再校验一次，防止报告在准备后被改坏。
- 现有 `current` 不动，旧 worker 继续服务。

验收：

```text
1. 不跑 env_check 直接 prepare → 非 0，提示先跑环境检测
2. 跑完 env_check → prepare 成功
3. 改 config 但不重跑 env_check → supervisor 拒绝切换
4. 门禁失败时 current 仍指向旧版本
```

不允许用“跳过检查”参数绕过；维护窗口也只能先修好环境再重跑。

## v29.4 · 自动阅读静默入库

### 规则

```text
空闲阅读 / 后台本地阅读
→ 摘要只写 book_memory / reading_queue / 日志
→ 不调用 send_short_reply
→ 不主动发“读了第 X 到 Y 字”

手动 !book next / !book read
→ 只有这种用户命令才返回摘要
→ 自动流程一律不发
```

`!book local` 的首段后台阅读也不再发第二条摘要；命令本身只回“已加入队列”。

更严格的规则：**任何自动流程都不发消息**，包括 idle、启动首读、定时补读；只有用户主动发命令触发的同步回复才允许发送。

### 验收

```text
1. 空闲读到第 3001-4000 字
   → 聊天窗口没有“读了…摘要…”
   → reading_queue / book_memory 有更新

2. !book next
   → 仍然有摘要回复

3. 日志有 [本地阅读] 记录，便于排查
```
