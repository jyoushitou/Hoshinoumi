# v30 系列 · 模型层插件接入

> 前置：v29 模型层契约 + native adapter。  
> 本版只做第三方 模型层实现接入，不重写核心 native。  
> 跨版本总纲：[INTERFACE-PLAN-v27-v44.md](../INTERFACE-PLAN-v27-v44.md)。

## 目标

```text
PluginRegistry 注册 模型 adapter
→ 权限 / 错误 / 任务 / 热更走 v28 运行时
→ 调用方 get() 拿不到时回落 DeepSeek / 豆包
```

## 次版本

| 版本 | 内容 | 验收 |
|---|---|---|
| **v30.0** | 第三方 `ModelProvider` adapter 接入点 + fake 实现 | 不改业务代码即可切换实现 |
| **v30.1** | 权限、错误、任务、热更接入 | 违规调用被拒绝；失败可查 |
| **v30.2** | 回归、文档、停用/回滚 | native 默认不受影响 |

## v30.0 完成记录

- `ModelRouter`：`model.<name>@1` 从 PluginRegistry 取插件；没有就回落 native。
- 插件对象缓存；`invalidate()` 可清缓存。
- 核心 native（DeepSeek/豆包）不注册插件。
- 回归：插件选中、native 回落、缓存失效。

## v30.1 完成记录

- 插件模型调用前 `plugin.call` 权限检查；默认 1 拒绝并回落 native。
- 插件异常写 `plugin_errors`，并清 provider 缓存。
- `invalidate()` 支持热更后失效。
- 任务仍由 PluginContext/PluginTasks 归属。
- 回归：默认权限回落、允许后异常落库、缓存失效。

## 能力与约束

- 能力名：`model.<name>@1`。
- 核心 native（DeepSeek / 豆包）不实现 PluginManifest、不进入插件表。
- 默认仍走 native；插件只能作为候选，除非显式路由/配置切换。
- 插件实现 `ModelProvider`，通过 v27 `PluginRegistry` 注册。
- 插件任务、线程池、DB 连接池由 v28 context 提供。
- 插件失败写 `plugin_errors`，连续失败自动停用。
- 插件 DDL 只允许 `plugin_<name>_` 前缀，MySQL/SQLite。

## 非目标

- 不重新定义 模型层 Protocol（v29 已完成）
- 不把 native 插件化
- 不允许插件改核心默认实现
