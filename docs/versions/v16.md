# v16 · 她会在空闲时读小说

> 前置：v9（她有自己的生活）+ v12（共同的东西）+ v13（主动）｜预估 4 天

## 目标

**主人不找她的时候，她自己去看书**，看完记进度、有想法，之后聊天时能接上剧情。

不是「等她被问才说」，而是「她真的在过自己的时间」。

## 触发时机（关键）

读小说是**空闲行为**，不是定时行为：

| 条件 | 说明 |
|---|---|
| 主人多久没说话 | ≥ 2 小时（可调 `NAO_READ_IDLE_HOURS`） |
| 她现在闲着 | `energy` 不太低、没有正在进行的对话 |
| 今天读得不多 | 每天最多 20 章 / 3 次 |
| 不在深夜 | 01:00~07:00 不读书（她也在睡觉） |

和主动消息共用闸门，但**独立计数**——读书不该抢占「主动聊天」的配额。

## 包含单元

| 单元 | 条目 | 内容 |
|---|---|---|
| U26 | E6 | 番茄 / 起点：拉免费章节，读 + 记进度 |
| U27 | E7 | 聊小说：记得看到哪、喜欢谁、不剧透 |
| U28 | E8 | 主动分享：读到有意思的地方会跟主人提一句 |

## 抓取方案：无头浏览器（已定）

实测结论：

| 平台 | 纯 HTTP 抓取 | 原因 |
|---|---|---|
| 番茄 | 目录/简介可用，**正文被字体加密**（部分字替换成私有区字符） | 站点反爬 |
| 起点 | **HTTP 202 + 空响应** | 需要执行 JS 挑战 |

所以采用 **Playwright + Chromium**，在真实浏览器环境里取渲染后的文本。

### 依赖与安装

```bash
pip install playwright
playwright install chromium          # 约 300 MB
playwright install-deps chromium     # 服务器缺系统库时
```

### 运行方式

- 浏览器**按需启动**，读完立刻关，不常驻
- 单次超时 30 秒，失败即放弃，不重试
- 并发上限 1（同一时间只开一个浏览器）
- 抓取在**线程里跑**（Playwright 同步 API 会阻塞事件循环）

### 成本

| 项 | 值 |
|---|---|
| 首次安装 | ~300 MB |
| 每次抓取 | 3~8 秒，内存峰值 ~200 MB |
| 每天次数 | ≤3 次，每次 1~3 章 |

### 失效处理

| 情况 | 处理 |
|---|---|
| Playwright 未安装 | 自动降级为「浅层在读」（书名/目录/进度） |
| 页面结构变了 | 解析失败 → 记日志 → 当天不再试 |
| 出现验证码 | 直接放弃，不绕过 |
| 抓取超时 | 放弃本次，不影响聊天 |
## 平台与可行性

| 平台 | 能读 | 难点 | 建议 |
|---|---|---|---|
| 番茄小说 | 免费书全本（**用 Playwright 取渲染文本**） | 反爬、结构变动 | ✅ 先做 |
| 起点 | 免费章节、试读（**需要无头浏览器过 JS 挑战**） | 202 空响应、付费章节读不到 | 后做 |

## 读什么、怎么读

```
空闲触发 → 挑一本在追的书 → 拉下一章正文（临时）
        → 生成摘要（≤100字）+ 记进度
        → 正文丢弃，只留摘要
```

**全文只在内存里过一遍，不落库、不进 prompt。**

## 记忆怎么存

```
events(kind='reading'):
  书名 | 平台 | 作者 | 已读章数 | 最近一章摘要(≤100字) | 喜欢的角色
```

每读 3~5 章更新一次摘要；同一本书一人一行。

## 聊小说（E7）

| 场景 | 她的反应 |
|---|---|
| 主人问「你在看什么」 | 说书名 + 一句现在的剧情 |
| 主人看过同一本 | 能聊角色，**先问看到第几章** |
| 主人没看过 | 只讲个开头，不剧透转折 |
| 台词引用 | 最多一句，标明是书里的 |

**剧透保护**：主人没读到的部分，她只能说「后面有转折」这种。

## 主动分享（E8）

读到有意思的地方，**可能**说一句——不是每章都报备。

| 闸门 | 值 |
|---|---|
| 概率 | 20%（读完一章后） |
| 冷却 | 3 小时 |
| 深夜 | 不说 |
| 正在聊天 | 不打断 |

| 失败 | 处理 |
|---|---|
| 章节拉取失败 | 换一本/跳过，不重试轰炸 |

## 实测结论（2026-11-09）

### 番茄：正文 54% 是私有区字符

| 指标 | 值 |
|---|---|
| HTTP 状态 | 200，33 KB HTML |
| 解析出的正文 | 187 字（应该 2000+） |
| 私有区字符（U+E000~U+F8FF） | **101 个，占 54%** |
| 实际汉字 | 59 个 |

样本：

```
“……”，云千珩猛深呼吸，胸腔刺痛…
```

**结论**：番茄把多数字符替换成私有区码点，靠自定义字体渲染。**DOM 里的文本本身就是乱的**，所以 Playwright 渲染后取 `innerText` 一样是乱的——**无头浏览器救不了番茄正文**。

要拿正文只能解 woff 字体映射（下字体、解析 cmap、字形匹配），而且字体轮换。

### 起点：probe.js 是腾讯 chaos VM

| 指标 | 值 |
|---|---|
| HTTP 状态 | 202，209 字节 |
| 内容 | `<script src="/C2WF946J0/probe.js">` |
| probe.js | **95 KB 混淆的腾讯 chaos VM**（`__TENCENT_CHAOS_VM`） |

**结论**：起点是 JS 挑战，**Playwright 能过**（这就是它的价值）；但脚本本身逆不出来，纯 Python 模拟不可行。

### 该怎么办

| 方案 | 番茄 | 起点 |
|---|---|---|
| Playwright | ❌ 救不了（文本本身乱） | ✅ 能过挑战 |
| 纯 HTTP | ❌ 54% 乱码 | ❌ 202 |
| 字体解码 | ⚠️ 可行但重 | 不需要 |

**推荐**：v16 保持「浅层在读 + 你点名」；正文摘要这层**只在装了 Playwright 且目标是起点/免费章节时**才开。番茄正文先不做。

代码已经按这个设计降级：抓不到正文 → 不记摘要、不报错、继续按浅层跑。
## 最终结论（2026-11-10）

### 番茄：OCR 解决，已接入

| 方案 | 结果 |
|---|---|
| 纯 HTTP 解析 | ❌ 正文 54% 私有区字符 |
| 字形比对（思源黑体） | ❌ 命中率 0.3%（字形被扰动） |
| **截图 + tesseract OCR** | ✅ **1480 字，私有区 0** |

OCR 样本（真实输出）：

```
一座老旧的道观里，黑夜带来了阳光未曾给过的冷寂，三座石像立在神龛上，
供台上放着几颗水果，看样子是几天前放的。夜晚的风吹动木门，吱呀吱呀作响…
```

约 5% 错字（`神谨`→`神龛`、`云千瑜`→`云千珩`），对「生成摘要」完全够用。

### 起点：放弃

| 尝试 | 结果 |
|---|---|
| 纯 HTTP | 202 + JS 挑战 |
| Playwright 过首页挑战 | ✅ 首页 8900 字 |
| Playwright 开章节页 | ❌ 「抱歉，页面无法访问」（172 字） |
| 带 cookie 开章节页 | ❌ 同样 172 字（cookie 里无有效登录态，且可能绑 IP） |

**结论**：起点章节页对机房 IP + 未登录状态双重限制，投入产出比太低。**v16 只做番茄**。

### 实现

- `botv/life/ocr.py`：截图 + tesseract + 文本清洗
- `botv/life/novel.fetch_chapter`：私有区 > 5% 或长度 < 200 → 自动转 OCR
- 依赖：`tesseract-ocr`、`tesseract-ocr-chi-sim`、`playwright` + chromium
- 成本：每章 8~12 秒（截图 + OCR）
