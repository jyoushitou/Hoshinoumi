# v40 系列 · 虚拟游乐场（2D）

> 大版本 v40。独立的 2D 虚拟空间客户端：角色、房间、物件、聊天、互动。
> 用游戏引擎构建，但**不把核心逻辑搬进引擎**；仍走 REST/SSE/DeliveryHub。
> 角色走动/动画只在 Unity 自研客户端内生效；QQ/Web/Qt/手机客户端没有这套场景。
> 原 v40 嵌入式前端顺延为 v41。

## 1. 定位

```text
不是第二个后端
不是 3D 元宇宙
是一个可走动的 2D 房间/游乐场
聊天、存钱、书架、人设、插件都能变成场景物件
```

示例场景：

```text
房间：床、书桌、书架、厨房、窗边、存钱罐、镜子、唱片机、猫窝、门口
角色：奈绪 NPC（会自己活动）、主人 avatar
交互：走近 → 按键 → 打开对应面板/对话
```

她当前在做什么：

```text
睡觉   → 床上，呼吸/翻身动画
看书   → 书架/窗边，翻页动画
吃饭   → 厨房/餐桌，进食动画
写东西 → 书桌，敲键盘动画
发呆   → 窗边，望窗外
离开   → 场景变暗/门口状态
主人在线 → 走到门口迎接/看向主人
```

## 2. 引擎选择

首选：

```text
Unity 2D（C#）
  2D 工具链成熟
  桌面 Windows/Linux 打包快
  物理/动画/瓦片地图/UI 都有
```

备选：

```text
UE5 Paper2D
  视觉更强，但包体/启动/学习成本高
  只做技术对比，不在 v40 同时维护两套
```

结论：

```text
v40 只做 Unity 2D
UE5 只做可行性验证，不进入主线
```

## 3. 架构

```text
Unity 2D 客户端
  ├─ 场景/角色/碰撞/动画
  ├─ 聊天 UI/气泡
  ├─ 物件交互
  └─ HTTP/WebSocket 客户端
        ↓
  本机服务 / REST / SSE / DeliveryHub
        ↓
  worker 核心（不嵌入引擎）
```

原则：

```text
引擎只负责表现和输入
聊天/记忆/存钱/人设仍由后端提供
不在 C# 里重写业务
```

## 4. 数据

```sql
playground_scenes (
  id, user_id, name, layout_json, updated_at
)

playground_objects (
  id, scene_id, object_type, x, y, state_json, updated_at
)
```

- `layout_json`：地板/墙/家具摆放
- `object_type`：bookshelf / vault / mirror / jukebox / plant / pet / arcade
- 物件状态只存轻量 JSON
- 聊天记录仍走 `conversation_messages`，不复制到场景表

虚拟货币：

```sql
playground_wallets (
  user_id, balance, updated_at
)

playground_ledger (
  id, user_id, delta, reason, ref, created_at
)

playground_items (
  id, user_id, item_id, kind, owned, equipped, created_at
)
```

- 货币单位可配，例如“星砂”
- 只能通过场景互动/小游戏获得
- 只能买家具/服装/装饰/礼物
- 不能充值、不能提现、不能转账
- 和 `savings_*` 真实存钱完全无关

## 6. 开发思路

### 6.1 先房间，后玩法

```text
空场景 → 走动 → 聊天 → 物件 → 装饰 → 小游戏
```

不要一上来做完整游戏。

### 6.2 她的生活状态

```text
数据来源：
  life 状态（心情/精力/孤独）
  reading 当前书/进度
  cron 当前场景（吃饭/睡觉）
  presence 是否离开
  chat 最近互动
```

快照：

```json
{
  "activity": "reading",
  "location": "bookshelf",
  "animation": "read_page",
  "mood": 0.7,
  "energy": 0.4,
  "since": "2026-11-17T21:00:00+08:00"
}
```

场景：

```text
activity → location → animation
reading → bookshelf/window → read_page
sleeping → bed → sleep
eating → kitchen → eat
idle → window → idle_look
away → door/dim → none
owner_enter → greet → look_at_owner
```

不伪造状态：后端没数据就 `unknown`，不要随机演“她在吃饭”。

### 6.3 仅在自研客户端

```text
Unity 客户端：有场景、角色、走动、动画
QQ/Web/Qt/Android/EMUI：没有场景
  → 只保留聊天/页面，不出现“去房间”入口
```

原因：

```text
走动/动画是本地表现
不写后端位置
不同步到 QQ
不要求其他客户端实现
```

状态：

```text
位置/朝向/动画：本地
物件交互：调后端 API
聊天：走现有消息通道
```

### 6.4 交互与货币

交互：

```text
E 键：说话/摸头/喂食/坐下/送礼/一起玩
不同物件不同动作
有冷却，不刷屏
动作只影响表现和小额货币，不改真实关系数值
```

货币：

```text
获得：小游戏、每日互动、完成场景任务
消耗：家具、服装、装饰、礼物
日上限，防止无限刷
不能充值、不能提现、不能转账
```

与真实存钱：

```text
playground currency：虚拟，只进不出
savings：人民币记录，不参与场景消费
两套表、两套 API，禁止混用
```

### 6.5 物件即入口

```text
存钱罐 → 存钱页
书架   → 阅读/书架
镜子   → 人设
唱片机 → 音乐/语音
猫窝   → 宠物/心情
门口   → 离开/切换场景
```

避免在场景里重写一套 UI。

### 6.6 表现与数据分离

- 场景布局存后端，客户端只渲染。
- 聊天消息不写场景表。
- 小游戏奖励只记轻量结果，不直接改核心数值。

### 6.7 性能

```text
2D 图集
对象池
限制同屏物件/特效
UI 与场景分层
窗口失焦降帧
```

### 6.8 安全

```text
不执行用户上传脚本
资源只从本地包/签名资源加载
网络只走本机服务/HTTPS
不在客户端存长期 token 明文
```

## 7. 验收

```text
1. 独立客户端能登录、进房间、走动
2. 场景能反映她当前在看书/睡觉/吃饭/发呆
3. 场景内能聊天，消息与 QQ/Web 同步
4. 角色能八向走动/走跑/碰撞/待机动画
5. 存钱罐/书架/镜子能打开真实功能
6. 装饰后重进布局保留
7. 小游戏能玩，奖励货币可查
8. 能买东西/装备/摆放
9. 虚拟货币不能兑换现金
10. 包体/内存/帧率达标
11. QQ/Web/Qt/手机不出现场景入口
12. 核心不因引擎客户端崩溃
```
