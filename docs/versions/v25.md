# v25 系列 · 热更新与配置动态化

> 前置：v24 读书修复 / 本地阅读队列｜预估 9 天｜**六个次版本**
>
> 目标：程序不停止，自动加载新版本和最新配置；失败自动回滚。
> **原 v25（内部 TCP/protobuf）顺延为 v26；原 v26（插件接口）顺延为 v27，v27 及以后整体 +1。**

## 边界（先说清楚）

- **不做 `importlib.reload` 业务模块**。Python 的模块全局、事件、协程、连接无法安全热替换，硬 reload 迟早出现半旧半新状态。
- 热更新采用**稳定入口 + 蓝绿 worker**：
  - `nao-ingress` 长期持有 `3001` 和 `27004`
  - 业务 worker 通过 Unix socket 接流量
  - 新版本 worker 起来并通过健康检查后，ingress 切流
  - 旧 worker 停止接新请求，处理完在途请求后退出
- 对 NapCat 的 WebSocket：由 ingress 保持连接，worker 切换时不要求 NapCat 重连。
- 对外的端口仍然只有 `3001` 和 `27004`；worker 不绑定这两个端口。
- 数据库迁移不热更；schema 变更仍需停机窗口，见 v26。

## 热更新的两种对象

| 对象 | 是否停进程 | 生效方式 |
|---|---|---|
| `config.local.json` | 否 | 文件监听 / `!reload`，下一轮生效 |
| 提示词、人设、生活模板 | 否 | 文件监听，下一轮生效 |
| 业务代码 / 新版本 | 否 | 新 worker 启动 → 健康检查 → ingress 切流 |
| 数据库 schema | 是 | 不走 v25 热更新，按迁移窗口 |


## 拒绝热更新（强制）

热更新不是“所有版本都能上”。新版本必须在 `update.json` 声明：

```json
{
  "version": "25.4.0",
  "requires_restart": false,
  "requires_schema": false,
  "schema_version": 29,
  "reason": ""
}
```

只要命中任一条，**拒绝热更新，不启动新 worker，不切换 current**：

```text
requires_restart = true       -> 必须停机重启
requires_schema  = true       -> 必须停机迁移数据库
声明的 schema_version != 当前 -> 必须走迁移流程
启动脚本/文件校验失败         -> 拒绝
健康检查失败                 -> 不切流并回滚
```

提示文案：

```text
这个版本不能热更新：
原因：需要停机迁移数据库 / 必须重启进程。
当前版本继续运行，未切换。
请安排维护窗口后手动升级。
```

规则：

- 拒绝后旧 worker 继续服务，保持 `current` 不变。
- 不允许自动重启、自动迁移来“强行热更”。
- 通过私聊通知主人；写入审计。
- 只有 `requires_restart=false` 且 `requires_schema=false` 且 schema 一致，才允许蓝绿切换。
- 维护窗口升级由 owner 显式执行，不交给自动更新器。

## 配置优先级与默认值

```text
代码默认值（最低，始终存在）
  < config.local.json
  < 环境变量 NAO_*
  < 运行时 !config（只影响当前进程，可选持久化）
```

规则：

- 任何一层缺失/非法/越界，回退上一层；最终回退代码默认值。
- 启动和热加载都打印 `当前值 / 默认值 / 来源`。
- 配置错误只告警，不阻塞启动。
- `!config <键>` 显示当前值、默认值、来源。
- `!config <键> <值>` 立即生效，不重启；非法值拒绝并保留旧值。
- 环境变量修改后仍需重启；`config.local.json` 可热加载。

### 首批参数

| 键 | 环境变量 | 默认 | 范围 |
|---|---|---|---|
| `memory.max_user_round` | `NAO_MAX_USER_ROUND` | 50 | 10–200 |
| `memory.digest_rounds` | `NAO_DIGEST_ROUNDS` | 10 | 1–50 |
| `summary.max_tokens` | `NAO_SUMMARY_MAX_TOKENS` | 1024 | 128–4096 |
| `reading.chunk_chars` | `NAO_READ_CHUNK_CHARS` | 1000 | 200–5000 |
| `context.memory_budget` | `NAO_MEMORY_BUDGET` | 当前值 | 100–4000 |

## 自动加载新版本

版本目录：

```text
release/
  versions/
    24.9.4/
    25.0.0/
  current -> versions/25.0.0
```

流程：

```text
1. 新版本解压到 release/versions/<version>/
2. 校验 VERSION / 文件哈希 / 启动脚本
3. 启动新 worker（不抢 3001/27004）
4. 健康检查 + 一次自检对话/帧
5. ingress 切换到新 worker
6. 旧 worker 停止接新流量，等待在途完成
7. 失败：ingress 切回旧 worker，记录审计
8. 成功后更新 current 软链
```

约束：

- 只监听本机 `release/`，不自动从公网拉代码。
- 新版本必须版本号递增，禁止回退到更旧版本除非显式 `--rollback`。
- 启动失败/健康检查失败自动回滚。
- 不覆盖正在使用的 `current`，先软链切换。

## 验收

```text
1. !config memory.max_user_round 60 -> 下一轮 60，不重启
2. 改 config.local.json -> 下一轮生效
3. 删掉环境变量重启 -> 回到默认 50
4. 非法值 -> 告警，保留旧值
5. 上传新版本 -> 新 worker 起来，旧对话不中断
6. 新版本健康检查失败 -> 自动切回旧版本
7. requires_restart/requires_schema 版本 -> 拒绝热更，旧版本继续服务
8. schema 不一致 -> 拒绝并提示维护窗口
9. 更新期间 QQ 私聊仍能回复
10. 对外仍只有 3001/27004 两个监听端口
11. 旧 worker 退出前完成在途请求
12. 审计记录版本切换/回滚/拒绝原因
```

## 非目标

- 不用 `importlib.reload` 热替换业务代码

## v25.5.2 补丁：蓝绿 drain 窗口

- supervisor 切流后不再立即 SIGTERM 旧 worker。
- 默认保留 `--drain-seconds 60`，旧 worker 继续服务已有 WS/在途 HTTP；新流量走新版本。
- 窗口结束后再终止旧 worker。
- 这避免切换瞬间掐断 NapCat 长连接；旧连接在窗口内自然结束。
- Docker Linux 验证：切换前建立的 WS 在 drain 窗口内仍能 echo；切换后新 WS 走新 worker。

## v25.5.3 补丁：worker 版本目录

- 新增 `scripts/prepare_worker.py`：把源码复制到 `data/workers/versions/<version>/`，并把 `.env`、`config.local.json`、`data`、`personas` 软链回运行目录。
- supervisor 改为 `cwd=version_dir`，`python3 run.py` 真正加载新版本代码。
- 部署顺序：prepare worker -> ingress -> supervisor/worker。

## v25.5.4 补丁：ingress 分离 HTTP/WS 监听地址

- `--http-host` 默认 `127.0.0.1`，27004 不对外。
- `--ws-host` 默认 `0.0.0.0`，NapCat 可连 3001。
- `--host` 保留为同时覆盖两者的兼容参数。

## v25.5.5 补丁：CLIP 只在 NAO_CLIP=1 时加载

- `bootstrap.py` 的 `init_clip_model()` 原来无条件调用，CPU 加载 CLIP 会卡住 worker 启动。
- 现在只有 `NAO_CLIP=1` 才 `tunables.load()` + `init_clip_model()`。
- 默认启动不再加载 CLIP，worker 可正常在健康检查窗口内起来。

## v25.5.6 补丁：current 指针绝对路径

- supervisor 的 `switch_current` 先把 base/target 解析成绝对路径，再写软链。
- 旧逻辑用相对 `--base data/workers` 时，current 指向 `data/workers/versions/...`，ingress 会解析成 `data/workers/data/workers/...`，健康检查 502。
- 已部署实例可手动修复：`ln -sfn "$PWD/data/workers/versions/25.5.5" data/workers/current`。

## v25.5.7 补丁：版本号不再被旧 tag 覆盖

- `get_version()` 改为静态 `VERSION` 优先，git 只负责提交号。
- 避免仓库 tag 停在 v24.9.4 时，25.x 被显示成 `v24.9.4-14-gxxxx`。

## v25.5.8 补丁：supervisor 失败诊断

- `wait_health` 返回具体原因：worker 退出码、socket 路径、超时、最后 health 错误。
- 健康检查失败时自动打印 `worker.log` 最后 20 行和处理提示。
- supervisor 默认 worker 命令改为 `python3 -u run.py`，避免日志缓冲为空。
