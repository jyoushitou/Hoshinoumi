# v25 系列 · 模型层插件接口

> 前置：v23 多用户 API｜预估 4 天｜**四个次版本**
> 目标：把「用哪个模型、怎么调、失败换谁」从 `ai/client.py` 里抽出来，
> 变成一个可注册的 **ModelProvider 插件层**——换模型只改配置，不改业务代码。

## 现在的问题

| 现状 | 问题 |
|---|---|
| `ai/client.py` 里写死 DeepSeek → 豆包 | 加第三个模型要改代码 |
| 两家请求格式/参数不同 | 业务层到处判断 |
| 失败降级写死顺序 | 不能按用户/场景配 |
| 没有统一的超时/健康/能力描述 | 排障只能看日志 |

## 契约

```python
class ModelProvider(Protocol):
    name: str
    def capabilities(self) -> set[str]:      # text / vision / tools / json
        ...
    async def complete(self, req: ModelRequest) -> ModelReply:
        ...
```

- `ModelRequest`：`messages`、`temperature`、`max_tokens`、`tools`、`user_id`、`trace_id`
- `ModelReply`：`text`、`tool_calls`、`usage`、`provider`、`latency_ms`
- `ModelRegistry`：注册/取用/健康/降级链

## 插件接口原则（只扩展 / 增强 / 显式替换；核心不插件化）

> **原有功能不插件化。** DeepSeek / 豆包、BM25、现有命令仍然是
> 核心代码里的第一等实现，不经过插件加载器，不需要 manifest，
> 也不能被 `disable/uninstall`。插件只在外围加东西。

| 模式 | 含义 | 例子 | 约束 |
|---|---|---|---|
| **extend** | 增加新能力 | 新模型 provider、新命令、新的可选记忆后端 | 不改核心行为 |
| **enhance** | 包装/增强 | 日志、指标、缓存、重试、内容过滤 | 必须调用或透传核心 |
| **replace** | 请求路由的显式覆盖 | 本地模型优先于 DeepSeek | 只覆盖路由；核心实现仍在，可随时回退 |

硬规则：

1. **核心功能不注册为插件**：没有 manifest、没有 install/disable/uninstall。
2. `PluginRegistry` 只管理插件条目；核心实现走原生调用路径，不依赖插件注册表。
3. 插件卸载 / 禁用 / 加载失败 → 自动回退核心，功能不能消失。
4. `replace` 只改变请求路由，不删除核心实现；必须显式配置 + 优先级 + 能力匹配。
5. 插件异常不能拖垮主流程；超时、空回复、崩溃都回退核心。
6. **不允许把现有功能改写成插件来“统一架构”**；插件接口只面向新增扩展点。
7. 插件清单只描述插件：name/version/capabilities/priority/mode；核心不出现在 `!plugin list`。

## 关键设计

- **配置**：`models.json`（或 DB）：`providers`、`default`、`fallback`、`per_user`。
- **降级**：按配置顺序；记录每次失败；连续失败熔断 N 秒。
- **能力**：`vision`/`tools` 不支持的 provider 不接对应请求；不静默降级成错答案。
- **多用户**：默认全局模型；`user_id` 可覆盖（owner 可限制可选范围）。
- **可观测**：每次调用记 provider / latency / tokens / 失败原因；`!model` 看健康。
- **不把密钥写日志**；provider 配置里只放 key 引用。

## v25.1.0 · 通用插件注册表（1 天）

| 单元 | 内容 | 验收 |
|---|---|---|
| U1 | `PluginManifest`：name/version/capabilities/priority/mode | 清单可校验 |
| U2 | `PluginRegistry` 只收插件条目；核心 DeepSeek/豆包/BM25/命令**不注册为插件** | `!plugin list` 无核心项 |
| U3 | 三种模式：extend / enhance / replace；replace 只覆盖路由且需显式配置 | 不会静默替换 |
| U4 | 生命周期：install / enable / disable / reload / uninstall | 禁用/卸载后回退核心 |
| U5 | 失败隔离：插件超时/异常/空结果 → 核心 fallback | 主流程不中断 |
| U6 | 测试：删掉插件目录后核心仍可用；核心不经 manifest/loader；坏插件不拖垮启动 | 回归固定 |

**验收**：

```bash
!plugin list                 # 只列插件，不列核心 DeepSeek/豆包/BM25/命令
!plugin disable <name>       # 核心功能仍可用
!plugin enable <name>        # 恢复
!plugin uninstall <name>     # 永久移除插件，核心仍在
```

> 关键断言：
>
> ```text
> 核心不是插件
> 插件不存在 != 功能不存在
> 插件失败 != 核心失败
> ```

## 验收

```bash
!model list          # 列出 provider / 能力 / 健康
!model test doubao   # 发一条测试
!model use deepseek  # owner 切默认
```

- 加一个 OpenAI-compatible provider：只写配置，不改 Python。
- 主 provider 超时/500：自动走 fallback，回复不中断。
- A 用户配了模型 B，不影响 B 用户。
- 禁用/卸载所有插件后：DeepSeek/豆包、BM25、现有命令仍然可用。

## 不做

- 不做本地模型推理/微调；只接 API。
- 不把 provider SDK 塞进业务层；统一走 HTTP/端口。
- 不做流式 UI（后续客户端需要再加）。

## 风险

| 风险 | 处理 |
|---|---|
| 各家 tool/vision 格式不同 | 适配器内归一化；能力不匹配就拒绝 |
| 降级链把慢模型拖长 | 每 provider 独立超时；总预算上限 |
| key 泄露 | 配置只存引用；日志脱敏 |
| 用户乱选模型 | 角色/白名单限制可选 provider |
