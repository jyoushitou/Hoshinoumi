# v25 系列 · 模型层插件接口

> 前置：v23 多用户 API｜预估 3 天｜**三个次版本**
> 目标：把「用哪个模型、怎么调、失败换谁」从 `ai/client.py` 里抽出来，
> 变成一个可注册的 **ModelProvider 插件层**——换模型只改配置，不改业务代码。

## 现在的问题

| 现状 | 问题 |
|---|---|
| `ai/client.py` 里写死 DeepSeek → 豆包 | 加第三个模型要改代码 |
| 两家请求格式/参数不同 | 业务层到处判断 |
| 失败降级写死顺序 | 不能按用户/场景配 |
| 没有统一的超时/健康/能力描述 | 排障只能看日志 |

## 契约

```python
class ModelProvider(Protocol):
    name: str
    def capabilities(self) -> set[str]:      # text / vision / tools / json
        ...
    async def complete(self, req: ModelRequest) -> ModelReply:
        ...
```

- `ModelRequest`：`messages`、`temperature`、`max_tokens`、`tools`、`user_id`、`trace_id`
- `ModelReply`：`text`、`tool_calls`、`usage`、`provider`、`latency_ms`
- `ModelRegistry`：注册/取用/健康/降级链

## 次版本

| 版本 | 内容 | 天数 | 验收 |
|---|---|---|---|
| **v25.0.0** | `ports/model.py` 契约 + `ModelRegistry` + 假 provider | 1 | 业务只依赖端口 |
| **v25.0.1** | DeepSeek / 豆包 / OpenAI-compatible 适配器 + 降级链 | 1 | 主模型失败自动换备用 |

## 关键设计

- **配置**：`models.json`（或 DB）：`providers`、`default`、`fallback`、`per_user`。
- **降级**：按配置顺序；记录每次失败；连续失败熔断 N 秒。
- **能力**：`vision`/`tools` 不支持的 provider 不接对应请求；不静默降级成错答案。
- **多用户**：默认全局模型；`user_id` 可覆盖（owner 可限制可选范围）。
- **可观测**：每次调用记 provider / latency / tokens / 失败原因；`!model` 看健康。
- **不把密钥写日志**；provider 配置里只放 key 引用。

## 验收

```bash
!model list          # 列出 provider / 能力 / 健康
!model test doubao   # 发一条测试
!model use deepseek  # owner 切默认
```

- 加一个 OpenAI-compatible provider：只写配置，不改 Python。
- 主 provider 超时/500：自动走 fallback，回复不中断。
- A 用户配了模型 B，不影响 B 用户。

## 不做

- 不做本地模型推理/微调；只接 API。
- 不把 provider SDK 塞进业务层；统一走 HTTP/端口。
- 不做流式 UI（后续客户端需要再加）。

## 风险

| 风险 | 处理 |
|---|---|
| 各家 tool/vision 格式不同 | 适配器内归一化；能力不匹配就拒绝 |
| 降级链把慢模型拖长 | 每 provider 独立超时；总预算上限 |
| key 泄露 | 配置只存引用；日志脱敏 |
| 用户乱选模型 | 角色/白名单限制可选 provider |
