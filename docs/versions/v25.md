# v25 系列 · 模型层接口实现

> 核心：把现有 DeepSeek / 豆包包成 `ModelProvider` 实现，并暴露第三方 provider 接口。
> 核心 provider 仍是 native，不注册为插件。

```python
class ModelProvider(Protocol):
    name: str
    def capabilities(self) -> set[str]: ...
    async def complete(self, req: ModelRequest) -> ModelReply: ...
```

## 实现步骤

| 次版本 | 内容 | 验收 |
|---|---|---|
| **v25.0** | `ModelRequest` / `ModelReply` / `ModelProvider` 契约 | 业务只依赖接口 |
| **v25.1** | `DeepSeekProvider` native adapter，包现有调用 | 行为与当前 DeepSeek 一致 |
| **v25.2** | `DoubaoProvider` native adapter，包现有降级 | 豆包行为不变 |
| **v25.3** | 第三方 adapter 接入点 + fake provider 测试 | 新 provider 不改业务代码 |

## 关键约束

- DeepSeek / 豆包是核心 native，不走 manifest，不出现在插件表。
- provider 选择由 v32 默认路由决定；v25 只提供实现。
- 第三方 provider 失败时由 v32 回退 native。
- 核心 provider 只能在启动前由 `features.json` / `NAO_FEATURES` 关闭。
