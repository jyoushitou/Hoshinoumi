# v25 系列 · 运维通道（一）bash 只读

> 前置：v17（命令通道 + 线程化）｜预估 2 天｜**风险最高的一版，默认关闭**

## 目标

主人在 QQ 里说一句，就能**查**服务器状态、看日志、看进程——不用 SSH。

**只读，不写**：这一版不做任何会改变系统的操作。

```
你：看下磁盘
她：（执行 df -h）根分区用了 78%，还有 12G

你：后端日志最后 20 行
她：（执行 journalctl/tail）最近 20 行是……
```

## 为什么危险

这等于**把服务器 shell 接到 QQ 上**。风险点：

| 风险 | 后果 |
|---|---|
| QQ 号被盗 | 对方拿到服务器控制权 |
| 模型理解错 | 「清理一下磁盘」→ 执行了 `rm` |
| 命令注入 | 自然语言里的分号/管道被拼进命令 |
| 输出过大 | 一次 `cat` 大文件把 bot 卡死 |
| 长命令 | `sleep 600` 占住 worker |

所以这一版**安全设计比功能重要**。

## 设计：白名单，不是自由 shell

**不做**「把你说的话直接丢给 bash」。做**命令白名单**：

```python
# 只读运维命令：查状态，不改任何东西
COMMANDS = {
    # 系统资源
    "disk":    ["df", "-h"],
    "mem":     ["free", "-m"],
    "load":    ["uptime"],
    "cpu":     ["top", "-bn1", "-o", "%CPU"],          # 只取一帧
    "ps":      ["ps", "-eo", "pid,pcpu,pmem,comm", "--sort=-pcpu"],
    # 进程与服务
    "service": ["systemctl", "status", "{name}", "--no-pager", "-l"],
    "ports":   ["ss", "-tulnp"],
    # 日志（只读，tail 限定行数）
    "log":     ["tail", "-n", "{n}", "{file}"],
    "journal": ["journalctl", "-u", "{name}", "-n", "{n}", "--no-pager"],
    # Docker（只读）
    "docker":  ["docker", "ps", "--format", "{{.Names}}\t{{.Status}}"],
    "dlogs":   ["docker", "logs", "--tail", "{n}", "{name}"],
    # 代码仓库（只读）
    "git":     ["git", "-C", "/app", "status", "--short"],
    "gitlog":  ["git", "-C", "/app", "log", "--oneline", "-n", "{n}"],
    # 基础信息
    "uname":   ["uname", "-a"],
    "date":    ["date"],
}
```

| 规则 | 说明 |
|---|---|
| 只执行白名单里的命令 | 不在表里的一律拒绝 |
| 参数用**正则校验** | `{n}` 只能是 1~200 的数字；`{file}` 只能是白名单路径 |
| **不经过 shell** | `subprocess.run(argv, shell=False)`，天然免疫 `;` `|` `&&` 注入 |
| 输出截断 | 最多 1500 字，超出加「…（已截断）」 |
| 超时 | 20 秒，超时 kill |
| 降权 | 以 bot 用户运行，**不给 sudo** |
| 审计 | 每条命令 + 输出摘要写日志和数据库 |
| 频率 | 每分钟最多 5 条 |
| 默认关闭 | `NAO_SHELL=1` 才启用 |
### 禁止清单（写死在代码里，不在白名单就执行不了）

| 类别 | 例子 | 为什么禁 |
|---|---|---|
| 重启/停止服务 | `systemctl restart`、`docker restart` | 会中断机器人在跑 |
| 文件增删改 | `rm`、`mv`、`cp`、`>` 重定向 | 一误操作就没了 |
| 杀进程 | `kill`、`pkill` | 可能杀掉自己 |
| 装包/改系统 | `apt`、`pip install`、`systemctl enable` | 改变环境 |
| 交互式 | `vim`、`top`（无 `-b`）、`less` | QQ 里没法交互 |
| 网络探测 | `curl`、`wget`、`nc` | 可被用来打内网 |
| 提权 | `sudo`、`su` | 出事没有边界 |

**这一版只做「看」，不做「改」**——查状态、看日志、看进程。想改东西还是 SSH 上去。

## 自然语言怎么接

**两种模式，默认只用第一种**：

| 模式 | 说明 | 风险 |
|---|---|---|
| **A. 命令名 + 参数** | 「看磁盘」→ 匹配关键词 → `disk` → `df -h` | 低 |
| B. 模型自由生成命令 | 模型输出完整命令行 | **高，默认不开** |

模式 A 的实现：关键词表 + 模型只在**白名单里选**（不给它写命令的权限）：

```python
# 模型只输出一个 key，不输出命令
{"action": "disk"}     # → 查表得到 ["df", "-h"]
```

## bash 模式（进出与鉴权）

和「代码模式」同一套交互习惯：`!bash` 进入、`!bash off` 退出、闲置自动退出。
但**多一道鉴权**——因为这条通道能摸到服务器。

### 状态机

```
        !bash <鉴权码>
休眠 ─────────────────→ 已进入（10 分钟倒计时）
  ↑                          │
  │  !bash off / 超时 / 进程重启 / 鉴权失败超限
  └──────────────────────────┘

鉴权失败 3 次 → 锁定 10 分钟（期间不再接受进入请求）
```

### 进入

```
你：!bash 2468
她：🔧 已进入 bash 模式（只读运维）
    可以问：磁盘、内存、负载、服务状态、日志
    10 分钟无操作自动退出，!bash off 退出

你：看下磁盘
她：根分区 78%，剩 12G
```

### 鉴权

| 项 | 说明 |
|---|---|
| 鉴权码来源 | `config.local.json` 的 `bash_key`，或环境变量 `NAO_BASH_KEY` |
| 校验方式 | 常数时间比较，防时序侧信道 |
| 失败处理 | 拒绝 + 计数；**3 次失败锁 10 分钟** |
| 未配置鉴权码 | bash 模式**永远进不去**（不是默认放开） |
| 群里 | **禁止在群里进入**，只允许私聊 |

### 进入时必贴：免责声明 + 实现逻辑

每次进入都要贴（不是首次才贴），**不能跳过、不能省略**。

```
⚠️ bash 模式（只读运维）

【免责声明】
本功能会以机器人进程的权限在你的服务器上执行命令。
虽然只开放只读白名单、不走 shell，但仍可能因误判、
配置错误或账号被盗导致信息泄露。
继续使用即表示你理解并自行承担风险。

【实现逻辑】
1. 只执行白名单命令（df/free/uptime/log/docker ps 等 15 个）
2. 不经过 shell（shell=False），分号/管道注入无效
3. 参数经正则校验；输出截断 1500 字；超时 20 秒
4. 只读：不改文件、不改服务、不装包
5. 每条命令都写审计日志
6. 10 分钟无操作自动退出；!bash off 手动退出

已进入。可以问：磁盘 / 内存 / 负载 / 服务状态 / 日志
```

| 规则 | 说明 |
|---|---|
| 每次进入都贴 | 不缓存、不省略 |
| 贴在「已进入」之前 | 先看风险，再给能力 |
| 日志留痕 | 贴出免责声明这件事本身也记审计 |
| 不可配置关闭 | 没有「不再提示」选项 |

### 进入后的消息怎么处理

```
普通文本 → 关键词匹配 → 命中白名单 → 执行 → 返回结果
                      → 没命中   → 「这个我不能查（不在白名单）」
```

**完全不经过模型**——避免模型「理解」出白名单外的命令。

| 输入 | 处理 |
|---|---|
| 「看下磁盘」 | 关键词命中 `disk` → `df -h` |
| 「后端日志最后 20 行」 | 命中 `log`/`journal`，参数校验 20 |
| 「重启后端」 | 命中禁止词 → 「只能查看，不能修改」 |
| 「今天吃什么」 | 不在白名单 → 「bash 模式只做只读运维，聊天请先 !bash off」 |
| `!` 开头的命令 | 照常走命令通道（`!bash off` 等） |

### 退出条件

| 条件 | 说明 |
|---|---|
| `!bash off` | 手动退出 |
| 10 分钟无操作 | 自动退出（比代码模式的 30 分钟短） |
| 进程重启 | 状态不持久化，重启后回到休眠 |
| 鉴权失败超限 | 锁定期内视为未进入 |

### 与代码模式的区别

| | 代码模式 `!code` | bash 模式 `!bash` |
|---|---|---|
| 鉴权 | 无（仅主人） | **要鉴权码** |
| 能做什么 | 回答问题（知识优先） | 执行白名单只读命令 |
| 走模型 | 是 | **否**（关键词直匹配） |
| 自动退出 | 30 分钟 | **10 分钟** |
| 群里可用 | 是 | **否** |
| 审计 | 无 | **每条都记** |

### 审计

每条执行都写 `events(kind='ops')`：

```
时间 | 原始输入 | 匹配到的命令 | 参数 | 退出码 | 输出摘要(≤120字) | 是否拒绝
```

被拒绝的尝试**也要记**——这样被盗号时能看出对方在试探什么。

### 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `bash_key` | 空（不允许进入） | 鉴权码，放 `config.local.json` |
| `bash_idle_min` | 10 | 无操作自动退出（分钟） |
| `bash_fail_limit` | 3 | 连续鉴权失败上限 |
| `bash_lock_min` | 10 | 锁定时长（分钟） |

## 与 v17 系列的关系

| 依赖 | 为什么 |
|---|---|
| v17.0 并发基础 | 命令执行走专用线程，不阻塞事件循环 |
| v17.2 命令通道 | 这本质是命令，必须绕过 worker 池（池满也要能用） |

## 全局参数（进程级）

| 参数 | 默认 | 说明 |
|---|---|---|
| `shell_enabled` | false | 总开关（`NAO_SHELL=1`） |
| `shell_timeout` | 20 | 单条命令超时（秒） |
| `shell_output_max` | 1500 | 输出截断长度 |
| `shell_rate` | 5 | 每分钟最多几条 |
| `shell_readonly` | true | 强制只读（本版恒为 true，不提供关闭选项） |

## 验收

- [ ] 「看磁盘」能返回 `df -h` 结果
- [ ] 不在白名单的命令被拒绝（回「这个我不能执行」）
- [ ] 注入尝试（`df -h; rm -rf /`）被拒绝——因为参数校验过不了
- [ ] 输出超长自动截断
- [ ] 超时命令被 kill
- [ ] 非主人发命令**完全无响应**（不提示、不报错）
- [ ] `restart`/`rm`/`apt` 这类命令被明确拒绝（回「只能查看，不能修改」）
- [ ] `!bash` 不带给权码进不去；错 3 次锁 10 分钟
- [ ] 群里发 `!bash` 被拒绝（只能在私聊）
- [ ] 进入后 10 分钟无操作自动退出
- [ ] 每条执行都进审计日志

## 红线（写死在代码里）

| 红线 | 原因 |
|---|---|
| 不用 `shell=True` | 免疫注入 |
| 不给 sudo | 出事也有边界 |
| 不开放文件写入/删除类命令 | 只读优先 |
| 不做交互式命令（vim/top） | 无法在 QQ 里交互 |
| 非主人零响应 | 不给探测机会 |
| 默认关闭 | 想用的人自己开 |

## 风险提示

即使做了上面所有事，**QQ 号被盗 = 服务器被看光**。所以：

- 只读命令为主（df/free/uptime/log tail）
- 建议配合 QQ 的设备锁/登录保护
