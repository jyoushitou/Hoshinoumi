### 3.3 文件共享页（新增）

定位：顶级 **文件** 页面，和聊天并列，不塞进 QQ 会话列表。

```text
一个账号下多端共享：
Web / VS Code / DSH / 手机 都能上传和下载
列表、下载、删除、分享链接同一套权限
```

页面：

```text
拖拽 / 多选 / 粘贴上传
上传队列与进度
文件名 / 大小 / 类型 / 时间
搜索与排序
下载 / 删除 / 复制分享链接
图片、文本、音频预览
空间用量
```

后端：

```text
GET  /api/files                 列表（分页/搜索）
POST /api/files/init            初始化上传
PUT  /api/files/{id}/chunk      分片上传
POST /api/files/{id}/complete   完成校验
GET  /api/files/{id}            元数据
GET  /api/files/{id}/download   下载
DELETE /api/files/{id}          删除
POST /api/files/{id}/share      生成限时分享链接
GET  /api/files/share/{token}   公开下载（可选）
```

存储：

```text
data/files/<uuid>
shared_files 表：id/user_id/name/mime/size/sha256/path/created_at/expires_at
owner-only；文件名清洗；不暴露真实路径
默认单文件 ≤ 30MB；大文件分片；账号配额 2GB
```

边界：

```text
分享链接只读、可过期、可限次数
不执行 HTML/SVG；下载带 Content-Disposition
不支持目录树，先做单层文件库
聊天附件和文件库分开，不共用配额
```

版本：

```text
v35.7.28.0  文件存储 + 列表/下载/删除 API
v35.7.28.1  文件页：拖拽/列表/下载/删除
v35.7.28.2  多端同步 + 分享链接
v35.7.28.3  大文件分片/断点续传
```

前置：

```text
gateway 目前只通用转发 GET
文件接口需要 POST/PUT/DELETE 贯通
分片单块 ≤ 4MB，避免超过内部帧 8MB
```

### 3.4 酒馆人设卡兼容（人设导入页）

目标：在 Web 人设导入页直接吃 SillyTavern / 酒馆角色卡，不让用户手工拆 JSON。

支持格式：

```text
V2 JSON：{ spec: "chara_card_v2", data: {...} }
V3 JSON：{ spec: "chara_card_v3", data: {...} }
PNG：tEXt 块 chara（base64 JSON）
PNG：tEXt 块 ccv3（优先）
.charx：后续可选（先不做）
```

字段映射：

```text
name                              → personas/<slug>/
description / personality /
scenario / system_prompt /
post_history_instructions         → prompt.txt
mes_example / creator_notes       → supplement.txt
first_mes / alternate_greetings   → supplement.txt 开场白区
character_book / lorebook         → supplement.txt 世界书区（按条数/字数截断）
state / voice                     → 使用 Hoshinoumi 默认
原始卡                            → personas/<slug>/tavern.json 保留，可回导
```

占位符：

```text
{{char}} → 角色名
{{user}} → 主人 / 用户
其他 {{...}} 保留，不执行、不注入脚本
```

接口：

```text
POST /api/persona/import/tavern/preview
  body: { card: JSON 或 PNG base64, filename? }
  → 解析结果 / 映射字段 / warnings / 建议 slug

POST /api/persona/import/tavern
  body: { card, name?, overwrite?, include_lorebook? }
  → 原子写入 personas/<slug>/，保留 tavern.json
```

页面：

```text
人设导入页 → 选择/拖入 .json / .png
→ 显示原卡名称/版本/字段数
→ 显示映射后的 prompt/supplement 预览
→ 冲突/截断/不支持字段 warning
→ 确认导入 / 覆盖
→ 成功后可选激活
```

安全：

```text
单卡 ≤ 10MB
slug 清洗，禁止 ../ 和绝对路径
不执行 HTML/JS；不把 lorebook 当系统指令
覆盖必须显式确认
解析失败不写目录
```

版本：

```text
v35.7.5.8   后端酒馆卡解析 / 映射 / preview API
v35.7.5.9   人设导入页：JSON/PNG 选择、预览、确认
v35.7.5.10  PNG tEXt / ccv3 / lorebook / charx 兼容增强
```

```text
对话框 / 气泡：背景、文字色、圆角、尾巴、宽度、对齐、边框、阴影
头像：主人头像、角色头像、形状、大小、上传/重置
字体：系统字体、字号、行高
背景：纯色 / 渐变 / 图片、透明度和模糊
主题：浅色 / 深色 / 自定义强调色
预设：保存/命名/切换/导入导出
```

存储：

```text
appearance_profiles 表：user_id / schema_version / profile_json / updated_at
owner-only
未知字段保留
多端读取同一 profile
本地 localStorage 只做缓存
```

接口（API 先行）：

```text
GET  /api/appearance
PUT  /api/appearance
POST /api/appearance/avatar
POST /api/appearance/reset
POST /api/appearance/import
GET  /api/appearance/export
```

实现规则：

```text
前端只应用白名单 CSS 变量
不执行用户提交的 CSS/HTML
头像 ≤ 2MB，存 data/avatars
颜色/尺寸做范围校验
不支持的字段进兼容报告，不静默丢
```

## 6. 多端同步与推送

```text
GET  /api/endpoints/:id/messages?after_seq=
POST /api/endpoints/:id/ack
POST /api/endpoints/:id/read
```

| 客户端 | 入口 | 收消息 | 通知 |
|---|---|---|---|
| Web | nginx 27006 | 拉取 | 页面内未读 / 标题，不做 Web Push |
| 插件 | nginx 27006；同机 27005 | 拉取 | host notification / badge |
| 手机 | nginx 27006 | 前台服务或 ntfy | 系统通知 |
| Qt | nginx 27006 | 拉取 | 托盘 Toast / 系统通知 |

规则：

```text
推送只带 message_id，点开再拉正文
owner-only；免打扰；同 message_id 不重复通知
所有客户端 after_seq + ack/read
QQ 无法判断已读就不上报
```

## 7. 全局规则

```text
一个次次版本一个提交
前端不硬编码命令 / 不伪造后端数据

已完成版本只归档，不在当前计划重复
```
