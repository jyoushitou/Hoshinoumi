# v35 系列 · 多端与客户端

> 大版本 v35。技术栈：
> Vue Web + Vue 套壳（快速多端）+ Qt 桌面（深度优化）+ 原生手机（深度优化）。
> 先做聊天室基础，再做全量可视化/平台增量；每个次版本是验收节点。

## 1. 客户端形态

```text
Web          Vue 3 + Vite，浏览器直接访问
Vue 套壳      TypeScript + Tauri/WebView，只做兼容兜底
Qt 桌面      Qt 6 + QML/C++，原生深度客户端 + 后台小窗
Android 基线 Kotlin + Jetpack Compose，通用安卓
小米 Rust    Rust + JNI/NDK，澎湃 OS 4（HyperOS 4）专项
iOS          先评估，不阻塞 v35
```

共享：

```text
REST / SSE 协议
DeliveryHub endpoint
本机服务
同一套账号/历史/消息
```

不共享：

```text
Qt/原生不强行复用 Vue DOM
套壳只做兼容兜底，不替代深度客户端
深度客户端按平台/厂商单独开发
```

```sql
client_endpoints (
  id, user_id, kind, name, token_hash, enabled,
  last_seen, created_at,
  UNIQUE(user_id, kind, name)

  id, user_id, endpoint_id, message_id, payload,
```

## 7. 聊天室统一验收

```text
1. 登录后能看到最近会话
2. 能拉历史（分页/增量）
3. 能发文本/图片
4. 能实时收消息
5. 断线 5s 内重连，不重复消息
6. 未读/已读正确
7. 退出重进不丢会话
```

Vue Web、Vue 套壳、Qt、Android、澎湃 OS 4 Rust 分别跑同一套；全通过后才能进入对应增量。

## 8. 技术边界

```text
Vue 套壳：兼容兜底，不深度优化
Qt：原生深度客户端；托盘/悬浮小窗/快捷回复；Windows Toast，Linux 系统通知
Android：Kotlin/Compose 通用基线
小米：Rust + JNI/NDK 专项客户端，适配澎湃 OS 4 后台/推送/自启
iOS：先评估骨架，不承诺 v35 全功能
共享协议：REST/SSE、DeliveryHub、本机服务
```

### Qt 原生与小窗

```text
TypeScript/Vue = 兼容层，不承诺极致性能
Qt = 原生层，负责长期挂机/托盘/小窗
```

Qt 小窗：

```text
托盘双击打开/隐藏
无边框悬浮窗
始终置顶
迷你模式：只显示最近消息 + 输入框
快捷回复：不打开主窗
通知按钮：回复/标记已读
多显示器/高 DPI/透明度
```

边界：

```text
小窗不是第二套聊天逻辑
仍走同一 REST/SSE/本地缓存
不抢焦点、不挡全屏
```

### Qt 许可

```text
个人/非商用
Qt 6 LGPLv3：动态链接 + 保留版权/许可声明 + 可替换 Qt 库
不静态闭源链接
发布附 LICENSE/NOTICE
```

不是法律意见；真要商用再评估商业授权。

```text
Qt 6 + Windows App SDK/WinRT

任务栏 badge → 未读数
```

### 个人开发者推送

小米推送需要企业资质；个人环境不要依赖它。

个人可用：

```text
ntfy 自建（推荐）
  worker → ntfy HTTP → 手机 ntfy App → 通知
  不依赖小米开发者账号

前台服务 WebSocket
  App 常驻通知 + 连接
  实时但耗电，HyperOS 可能杀

FCM / OneSignal
  需要 Google 环境，国内/HyperOS 不保证
```

推荐组合：

```text
主：自己的 App 前台服务 + WebSocket
备：ntfy 自建 + ntfy App
可选：厂商推送（xiaomi/Huawei，有资质才接）
```

ntfy 要求：

```text
自建 HTTPS
随机长 topic
访问 token
不进日志
通知只带 message_id，点开再拉内容
```

### 内存预算

以 **PSS** 为准，Release 包、6GB 内存真机、亮屏空闲 5 分钟后测：

```text
后台/空闲     ≤ 100MB
纯文本聊天    ≤ 120MB
图片聊天      ≤ 160MB
硬上限        ≤ 200MB
```

分解：

```text
Kotlin/Java heap   ≤ 48MB
Rust/native        ≤ 30MB
图形/图片缓存      ≤ 32MB
其他               余量
```

手段：

```text
不用 WebView
Kotlin Views，不用 Compose 起步
图片 LRU + 解码尺寸限制
列表虚拟化/懒加载
不做常驻大对象
Release + R8
```

测量：

```bash
adb shell dumpsys meminfo <包名>
```

100MB 是“后台/空闲”目标；图片聊天不可能长期压到 100MB 内。

推送：

```text
可选：华为推送（有资质/账号再评估）
```

### HyperOS 4 极致优化与常驻

```text
不用 WebView
Rust 核心 + Kotlin 薄 UI
图片 LRU/懒加载
心跳指数退避
前台服务 + 常驻通知
电池白名单/自启动引导
Doze/锁屏/重启测试
```

必须承认：

```text
HyperOS 仍可能杀进程
没有厂商推送就无法保证“被杀也收”
ntfy/WebSocket 只能提高存活率
```

### 澎湃 OS 4 约束

```text
目标系统：HyperOS 4（澎湃 OS 4）
架构：arm64-v8a
不以 GMS 为前提
厂商推送/后台限制以 HyperOS 4 实机为准
Rust + JNI/NDK；Android UI 薄层
真机验收：HyperOS 4 小米设备
```

桌面端同理：

```text
Qt 是桌面深度主线
Linux / Windows 分别打包、分别验收
特殊 OEM/硬件再单开 Rust 变体，不混入主线
```

## 9. 风险

- 四套 UI 成本高：Vue/套壳先验证，Qt/原生按验收节点推进。
- 协议不一致：所有客户端共用同一 REST/SSE 契约测试。
- 套壳与深度客户端功能漂移：明确套壳只做基础。
- Qt/原生打包：Linux/Windows/Android 分开验收。
- iOS 不确定：只做评估，不阻塞 v35。
