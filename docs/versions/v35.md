# v35 系列 · 多端与客户端

> 大版本 v35。目标：主动消息能扇出到多端，并做出 Web/桌面/手机客户端。
> 所有客户端复用同一 DeliveryHub 和本机服务，不重写核心。

## 1. 范围

### 要做

```text
Endpoint 注册表
DeliveryHub 主动消息扇出
本机服务（Unix socket + 127.0.0.1）
DSH / Qoder 插件
QQ 命令收敛
Web / Linux 桌面 / Windows 桌面 / 手机
手机离线模式 + 记账
```

### 不做

```text
不重写聊天/记忆/定时核心
不做多租户 SaaS
不把客户端当第二套后端
```

## 2. 总体架构

```text
worker
  ├─ DeliveryHub
  │    ├─ endpoint: qq
  │    ├─ endpoint: web
  │    ├─ endpoint: desktop-linux
  │    ├─ endpoint: desktop-win
  │    └─ endpoint: mobile
  ├─ 本机服务（Unix socket）
  └─ 现有 REST /api

客户端只做：
  连接 → 认证 → 收消息 → 发消息 → 拉历史
```

## 3. 数据模型（schema 33）

```sql
client_endpoints (
  id, user_id, kind, name, token_hash, enabled,
  last_seen, created_at,
  UNIQUE(user_id, kind, name)
)

delivery_outbox (
  id, user_id, endpoint_id, message_id, payload,
  status, attempts, next_retry, created_at, delivered_at
)
```

- `message_id` 幂等键；同一 endpoint 不重复投递。
- `status`: pending / delivered / failed / dropped。
- 客户端 ack 后置 delivered；失败指数退避。

## 5. 开发思路

### 5.1 先 hub，后客户端

- v35.1 先把“一条消息 → 多 endpoint”做对，用测试 endpoint + QQ 验收。
- 客户端在 v35.5+ 接入；不提前写四套发送逻辑。

### 5.2 幂等

```text
message_id = 业务消息唯一 id
outbox 唯一键 = (endpoint_id, message_id)
```

重复投递只更新 attempts，不再发。

### 5.3 本机服务

- 只监听 Unix socket 或 127.0.0.1。
- 复用 `/api/*`；不新写一套业务。
- 客户端认证用 endpoint token；owner 登录仍走 v23。

### 5.4 Web 优先

- Web 是桌面/手机 UI 的共同基础。
- 先只读（history/state），再聊天，再面板。
- SSE 比 WebSocket 简单，先 SSE；需要双向再升级。

### 5.5 手机离线

```text
本地 SQLite：outbox / conversations / accounting
联网：先拉增量，再推 outbox
冲突：服务端 updated_at 胜出
```

不把手机做成第二套记忆库。

## 6. 风险

- 多端重复消息：outbox 幂等 + ack。
- token 泄漏：只存 hash；可撤销。
- Web 安全：HttpOnly、CSRF、限流；不做公网裸奔。
- 客户端范围膨胀：先 Web，桌面/手机按顺序。
- 离线冲突：只允许追加消息/记账，不允许改历史。

## 7. 总验收

```text
1. 一条主动消息，QQ + 测试 endpoint 都收到
2. 断线重连不重复
3. Web 能登录、看历史、发消息
4. Linux/Windows 安装包能启动
5. 手机断网可记账，恢复同步
6. 旧 QQ 长命令有迁移提示
```
