### 2.4 消息撤回

规则：

```text
只允许撤回自己发送的消息
窗口默认 2 分钟，可配置
软删除：标记 recalled，不物理删除
附件保留但不再返回内容，后续清理
撤回幂等；重复撤回不报错
owner-only；群聊/他人 403
```

接口：

```text
POST /api/messages/{message_id}/recall
GET  /api/conversations/{target_id}/events?after_event=...
GET  /api/history?...   # 消息带 recalled 标记
```

同步模型：

```text
conversation_events 表：event_id / user_id / target_id / message_id / type / created_at
撤回写 event
Web 轮询 events + history：
  新消息用 after_seq
  撤回/修改用 after_event
其他客户端拉 events 后把气泡替换成“已撤回”
```

前端：

```text
消息悬浮/右键 → 撤回
移动端长按 → 撤回
二次确认
乐观替换为“已撤回”
失败恢复原消息并提示
多端 5 秒内同步
不展示已撤回原文/附件
```

版本：

```text
v35.5.18.0  API / 事件表 / 权限 / 契约测试
v35.5.19.0  Web 撤回 UI + 多端回显 + 验收
```

## 3. v35.6 桌面套壳运行环境

Electron 内置 Chromium，页面渲染不依赖系统 WebView，避免浏览器差异导致显示 bug：

```text
Windows / macOS / Linux：随安装包带固定 Chromium
         不依赖系统 WebView / WebView2
macOS： WKWebView 属于系统组件，不能内置
         最低版本检测 + 能力检测 + 错误页
Linux： WebKitGTK，AppImage 固定依赖或声明最低版本
```

边界：

```text
不是“内置完整浏览器”
是打包 Chromium 的 Electron 壳
如果要求 Windows/macOS/Linux 完全同一渲染引擎
只能换 Electron/CEF，包体和内存会明显变大
```

### 显示检测与兜底

启动前：

```text
引擎 / 版本：Electron 内置 Chromium
能力探针：CSS grid/flex gap、backdrop-filter、color-mix、
          container queries、ResizeObserver、Intl
运行时心跳：壳 ↔ 页面 bridge
```

分级：

```text
A 完整模式
B 兼容模式：去毛玻璃/动画/复杂渐变，保留布局和聊天
C 安全模式：纯文本 + 基础输入，禁用特效
D 致命：壳加载本地 fallback.html，显示原因/最低版本/处理按钮
```


## 7. 多端同步与推送

```text
GET  /api/endpoints/:id/messages?after_seq=
POST /api/endpoints/:id/ack
POST /api/endpoints/:id/read
```

| 客户端 | 入口 | 收消息 | 通知 |
|---|---|---|---|
| Web | nginx 27006 | 拉取 | 页面内未读 / 标题，不做 Web Push |
| 插件 | nginx 27006；同机 27005 | 拉取 | host notification / badge |
| 手机 | nginx 27006 | 前台服务或 ntfy | 系统通知 |
| Qt | nginx 27006 | 拉取 | 托盘 Toast / 系统通知 |

规则：

```text
推送只带 message_id，点开再拉正文
owner-only；免打扰；同 message_id 不重复通知
所有客户端 after_seq + ack/read
QQ 无法判断已读就不上报
```

## 8. 全局规则

提交粒度：

```text
一个独立业务 = 一个补丁版本 = 一次提交
API 补丁和 UI 补丁分开
文档状态更新跟随对应补丁
不把多个业务塞进同一个 commit
版本号按补丁号区分
```



```text
一个次次版本一个提交
前端不硬编码命令 / 不伪造后端数据
接口失败显示错误 / 空态
缺接口先写进计划，再补后端，再接 UI
已完成版本只归档，不在当前计划重复
```
