### 2.4 消息撤回

规则：

```text
只允许撤回自己发送的消息
窗口默认 2 分钟，可配置
软删除：标记 recalled，不物理删除
附件保留但不再返回内容，后续清理
撤回幂等；重复撤回不报错
owner-only；群聊/他人 403
```

接口：

```text
POST /api/messages/{message_id}/recall
GET  /api/conversations/{target_id}/events?after_event=...
GET  /api/history?...   # 消息带 recalled 标记
```

同步模型：

```text
conversation_events 表：event_id / user_id / target_id / message_id / type / created_at
撤回写 event
Web 轮询 events + history：
  新消息用 after_seq
  撤回/修改用 after_event
其他客户端拉 events 后把气泡替换成“已撤回”
```

前端：

```text
消息悬浮/右键 → 撤回
移动端长按 → 撤回
二次确认
乐观替换为“已撤回”
失败恢复原消息并提示
多端 5 秒内同步
不展示已撤回原文/附件
```

版本：

```text
v35.5.18.0  API / 事件表 / 权限 / 契约测试
v35.5.19.0  Web 撤回 UI + 多端回显 + 验收
```

### 3.4 酒馆人设卡兼容（人设导入页）

目标：在 Web 人设导入页直接吃 SillyTavern / 酒馆角色卡，不让用户手工拆 JSON。

支持格式：

```text
V2 JSON：{ spec: "chara_card_v2", data: {...} }
V3 JSON：{ spec: "chara_card_v3", data: {...} }
PNG：tEXt 块 chara（base64 JSON）
PNG：tEXt 块 ccv3（优先）
.charx：后续可选（先不做）
```

字段映射：

```text
name                              → personas/<slug>/
description / personality /
scenario / system_prompt /
post_history_instructions         → prompt.txt
mes_example / creator_notes       → supplement.txt
first_mes / alternate_greetings   → supplement.txt 开场白区
character_book / lorebook         → supplement.txt 世界书区（按条数/字数截断）
state / voice                     → 使用 Hoshinoumi 默认
原始卡                            → personas/<slug>/tavern.json 保留，可回导
```

占位符：

```text
{{char}} → 角色名
{{user}} → 主人 / 用户
其他 {{...}} 保留，不执行、不注入脚本
```

接口：

```text
POST /api/persona/import/tavern/preview
  body: { card: JSON 或 PNG base64, filename? }
  → 解析结果 / 映射字段 / warnings / 建议 slug

POST /api/persona/import/tavern
  body: { card, name?, overwrite?, include_lorebook? }
  → 原子写入 personas/<slug>/，保留 tavern.json
```

页面：

```text
人设导入页 → 选择/拖入 .json / .png
→ 显示原卡名称/版本/字段数
→ 显示映射后的 prompt/supplement 预览
→ 冲突/截断/不支持字段 warning
→ 确认导入 / 覆盖
→ 成功后可选激活
```

安全：

```text
单卡 ≤ 10MB
slug 清洗，禁止 ../ 和绝对路径
不执行 HTML/JS；不把 lorebook 当系统指令
覆盖必须显式确认
解析失败不写目录
```

版本：


## 7. 多端同步与推送

```text
GET  /api/endpoints/:id/messages?after_seq=
POST /api/endpoints/:id/ack
POST /api/endpoints/:id/read
```

| 客户端 | 入口 | 收消息 | 通知 |
|---|---|---|---|
| Web | nginx 27006 | 拉取 | 页面内未读 / 标题，不做 Web Push |
| 插件 | nginx 27006；同机 27005 | 拉取 | host notification / badge |
| 手机 | nginx 27006 | 前台服务或 ntfy | 系统通知 |
| Qt | nginx 27006 | 拉取 | 托盘 Toast / 系统通知 |

规则：

```text
推送只带 message_id，点开再拉正文
owner-only；免打扰；同 message_id 不重复通知
所有客户端 after_seq + ack/read
QQ 无法判断已读就不上报
```
