# v35 系列 · 多端与客户端

> 大版本 v35。顺序固定：先完成各平台**聊天室基础**，再分平台做增量功能。
> 所有客户端复用同一 DeliveryHub 和本机服务，不重写核心。

## 1. 基础与增量

### 基础（各平台都必须先有）

```text
登录 / 会话列表
历史消息
文本 / 图片发送
实时接收
断线重连
未读/已读
```

和 QQ 现有体验对齐；**不含**计划编辑器、离线记账、托盘、推送等增量。

### 增量（基础全部通过后再做）

```text
Web：状态面板 / 学习计划可视化 / 管理页
桌面：托盘 / 通知 / 快捷键 / 自启
手机：推送 / 离线 / 记账
IDE：DSH / Qoder
```

## 2. 总体架构

```text
worker
  ├─ DeliveryHub
  │    ├─ endpoint: qq
  │    ├─ endpoint: web
  │    ├─ endpoint: desktop-linux
  │    ├─ endpoint: desktop-win
  │    └─ endpoint: mobile
  ├─ 本机服务（Unix socket / 127.0.0.1）
  └─ 现有 REST /api

客户端：
  连接 → 登录 → 拉历史 → 实时收 → 发送
```

## 3. 数据模型（schema 33）

```sql
client_endpoints (
  id, user_id, kind, name, token_hash, enabled,
  last_seen, created_at,
  UNIQUE(user_id, kind, name)
)

delivery_outbox (
  id, user_id, endpoint_id, message_id, payload,
  status, attempts, next_retry, created_at, delivered_at
)
```

- `message_id` 幂等键；同一 endpoint 不重复投递。
- `status`: pending / delivered / failed / dropped。

## 5. 开发顺序

```text
v35.0 hub 基础
→ v35.1 本机服务
→ v35.2 四个平台聊天室
→ 基础验收全部通过
→ v35.3 Web 增量
→ v35.4 桌面增量
→ v35.5 手机增量
→ v35.6 命令/IDE
→ v35.7 收尾
```

禁止在聊天室基础未通过时先做计划编辑器/离线记账/托盘，避免四端同时半成品。

## 6. 基础聊天室验收（统一）

```text
1. 登录后能看到最近会话
2. 能拉历史（分页/增量）
3. 能发文本/图片
4. 能实时收消息
5. 断线 5s 内重连，不重复消息
6. 未读/已读正确
7. 退出重进不丢会话
```

四端各自跑同一套验收；通过后才能进入增量。

## 7. 增量边界

### Web

- 状态面板、历史管理
- 学习计划 7 日网格：新增/删除/编辑/拖拽/完成/跳过/顺延
- 不做离线记账

### 桌面

- 托盘、系统通知、快捷键、自启
- 不复制一套业务逻辑

### 手机

- 推送、离线队列、记账
- 离线只追加，冲突以服务端为准

### IDE

- DSH / Qoder 只做入口
- 优先只读工具；写操作审批

## 8. 风险

- 四端同时铺开：严格按 v35.2 基础优先。
- 重复消息：outbox 幂等 + ack。
- token 泄漏：只存 hash，可撤销。
- Web 安全：HttpOnly、CSRF、限流。
- 离线冲突：只追加消息/记账，不改历史。
