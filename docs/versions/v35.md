# v35 系列 · 多端与客户端

> 大版本 v35。技术栈：
> Vue Web + Vue 套壳（快速多端）+ Qt 桌面（深度优化）+ 原生手机（深度优化）。
> 先做聊天室基础，再做全量可视化/平台增量；每个次版本是验收节点。

## 1. 客户端形态

```text
Web          Vue 3 + Vite，浏览器直接访问
Vue 套壳      Tauri/WebView 包一层，快速覆盖桌面/手机
Qt 桌面      Qt 6 + QML/C++，深度优化
原生手机     Android Kotlin + Jetpack Compose 先行；iOS 后续评估
```

共享：

```text
REST / SSE 协议
DeliveryHub endpoint
本机服务
同一套账号/历史/消息
```

不共享：

```text
Qt/原生不强行复用 Vue DOM
套壳只做快速验证，不替代深度客户端
```

## 7. 聊天室统一验收

```text
1. 登录后能看到最近会话
2. 能拉历史（分页/增量）
3. 能发文本/图片
4. 能实时收消息
5. 断线 5s 内重连，不重复消息
6. 未读/已读正确
7. 退出重进不丢会话
```

Vue Web、Vue 套壳、Qt、Android 分别跑同一套；全通过后才能进入对应增量。

## 8. 技术边界

```text
Vue 套壳：快速覆盖，不深度优化
Qt：桌面深度客户端，QML/C++，不嵌 Vue DOM
Android：Kotlin/Compose 原生，不 WebView 套壳
iOS：先评估骨架，不承诺 v35 全功能
共享：REST/SSE、DeliveryHub、本机服务
```

## 9. 风险

- 四套 UI 成本高：Vue/套壳先验证，Qt/原生按验收节点推进。
- 协议不一致：所有客户端共用同一 REST/SSE 契约测试。
- 套壳与深度客户端功能漂移：明确套壳只做基础。
- Qt/原生打包：Linux/Windows/Android 分开验收。
- iOS 不确定：只做评估，不阻塞 v35。
