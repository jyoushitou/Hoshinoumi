# v35 系列 · 多端与客户端

> 大版本 v35。顺序固定：
> 本机服务 → DSH/Qoder → 四端聊天室 → Web 全量可视化 → 平台增量。
> DSH/Qoder 只依赖本机服务，不需要客户端 UI，所以先做。

## 1. 基础与增量

### 最先做：IDE 插件

```text
v35.1 本机服务
v35.2 DSH / Qoder
```

原因：

```text
只做本机 HTTP + 工具注册
不需要聊天 UI
不改核心
最容易先验收
```

### 然后：四端聊天室基础

```text
登录 / 会话列表
历史消息
文本 / 图片发送
实时接收
断线重连
未读/已读
```

### 最后：可视化与平台增量

```text
Web 全量可视化
桌面托盘/通知
手机推送/离线/记账
命令收敛
```

## 2. 总体架构

```text
worker
  ├─ DeliveryHub
  ├─ 本机服务（Unix socket / 127.0.0.1）
  └─ 现有 REST /api

DSH/Qoder
  → 本机 HTTP
  → 只读工具优先

客户端
  → 登录 → 历史 → 实时收 → 发送
```

## 3. 数据模型（schema 33）

```sql
client_endpoints (
  id, user_id, kind, name, token_hash, enabled,
  last_seen, created_at,
  UNIQUE(user_id, kind, name)
)

delivery_outbox (
  id, user_id, endpoint_id, message_id, payload,
  status, attempts, next_retry, created_at, delivered_at
)
```

```text
v35.0 hub
→ v35.1 本机服务
→ v35.2 DSH / Qoder
→ v35.3 四端聊天室（18 个次次版本）
→ 聊天室验收全通过
→ v35.4 Web 全量可视化
→ v35.5 桌面增量
→ v35.6 手机增量
→ v35.7 命令增量
```

不允许跳过：

```text
本机服务没通过 → 不做 IDE
聊天室没通过 → 不做可视化
可视化没全 → 不做平台增量
```

## 6. 聊天室统一验收

```text
1. 登录后能看到最近会话
2. 能拉历史（分页/增量）
3. 能发文本/图片
4. 能实时收消息
5. 断线 5s 内重连，不重复消息
6. 未读/已读正确
7. 退出重进不丢会话
```

四端各自跑同一套；v35.3 共 18 个次次版本，全通过后才能进入 v35.4。

拆解原则：

```text
每个平台：登录 → 历史 → 发送/接收 → 重连/打包
Web 额外拆 UI 与协议
桌面额外拆壳与安装包
手机额外拆生命周期
```

## 9. 命令增量

### 目标

```text
QQ：只留短命令
客户端：命令面板/自动补全
同一 handler，不复制业务
```

### 命令元数据

```text
name / aliases
args / usage
permission
risk: read / write / dangerous
client_visible
```

### 客户端命令面板

```text
!help 的分类 → 面板分组
输入框 / 自动补全
执行结果回到聊天
危险命令二次确认
```

### 迁移

```text
旧长命令 → 提示新位置
!db / !usage / !hooks / !cron / !plugins
→ 客户端对应页面
```

### 验收

```text
1. QQ 短命令可用
2. 客户端面板能执行同一命令
3. 危险命令必须确认
4. 旧命令提示迁移
5. !help 与面板一致
```

## 10. 风险

- IDE 插件越权：只读工具优先，写操作审批。
- 四端同时铺开：严格聊天室优先。
- 重复消息：outbox 幂等 + ack。
- Web 安全：HttpOnly、CSRF、限流。
