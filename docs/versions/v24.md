# v24 系列 · 插件接口实现（含 v24.4–v24.8 书籍链路修复）

> 核心：实现第三方插件接入所需的接口和注册表。
> **本层不实现任何功能**：只定义契约和注册表，不提供任何实现；具体 provider / channel / tool / storage 由核心或第三方开发者实现。
> 现有功能仍是核心 native；没有插件时核心默认链路照常工作。
> 欢迎其他开发者按契约提交实现。

```python
class PluginManifest(Protocol):
    name: str
    version: str
    capabilities: set[str]
    priority: int


class PluginRegistry(Protocol):
    def register(self, manifest: PluginManifest, factory) -> None: ...
    def get(self, capability: str, name: str): ...
    def list(self) -> list[PluginManifest]: ...
```

## 实现步骤

| 次版本 | 内容 | 验收 |
|---|---|---|
| **v24.0** | `PluginManifest` / `PluginRegistry` 契约 + 内存注册表 | 能注册/查找/列出测试插件 |
| **v24.1** | 能力字符串规范 + 版本校验 + 冲突检测 | 同名/同能力冲突可解释 |
| **v24.2** | 第三方 adapter 加载入口（只加载，不实现具体插件） | 加载失败不影响核心 |
| **v24.3** | 核心 native 不注册测试 + 文档/收尾 | 核心不出现在插件表 |

## 关键约束

- 核心实现不实现 `PluginManifest`，不进入 `PluginRegistry`。
- `get()` 找不到插件时返回 `None`，由调用方走核心。
- 插件注册失败只记录，不阻塞启动。
- 核心功能只能通过启动前 `config/features.json` / `NAO_FEATURES` 关闭。

## v24.8 · 番茄移动端读取（Linux 服务器 Android 容器，实验性）

> 前提：手机 App 端没有网页的 SVIP 付费墙。
> 采用原因：**网页端无法稳定读取全文**——SVIP 付费墙 + 字体加密，cookie 登录后也只能拿到预览；所以改为在 Linux 内运行 Android App，由用户自备 APK 读取。
> APK 约定：用户自行提供，放在本地 `APK/`；本仓库不提供、不再分发任何 APK。
> 约束：**不接外部手机、不接外部 ADB**；在 Linux 服务器内跑 Android 容器/模拟器。
> 说明：Waydroid 用 `waydroid shell`，redroid/AVD 用**本机 localhost adb** 作为容器控制通道，不是外接手机。若连 localhost adb 也不能用，就只能走 App API，风险更高。

### 本地 APK

```text
APK/fanqie.apk   # 用户自备，不入库
```

### 先跑预检

```bash
bash scripts/check_android_worker.sh
```

重点看：

```text
/proc/filesystems 有没有 binder
/dev/kvm 在不在
内存 / CPU
waydroid / redroid / docker / adb / weston 是否安装
```

### 方案优先级（Linux 服务器）

| 顺序 | 方案 | 条件 | 评价 |
|---|---|---|---|
| 1 | Waydroid | binder + Wayland/Weston | 最接近“Linux 跑 Android”，资源较低 |
| 2 | redroid（Docker） | binder + 特权容器 | 无头服务器常用；需要内核支持 |
| 3 | Android AVD | /dev/kvm | 最重；反模拟器风险高 |
| 4 | App API | 不需要容器 | 只在接口稳定、无需破解签名时考虑 |
| 5 | 轻量 VM：Bliss OS / Android-x86 + libhoudini | QEMU/KVM；镜像 1–2GB | 比 AVD 更接近真机，内置 ARM 转译；待验证 |

### 转译层前置（v24.8.1）

```text
Android 11 x86_64 AVD（userdebug）
Magisk / root（system overlay）
libndk_translation 或 libhoudini 模块
ro.dalvik.vm.native.bridge 生效
abi list 包含 arm64-v8a
```

注意：普通 AVD 的 `/system` 是只读的，`adb remount` 会报 `bootloader unlocked`；必须先 root/overlay，不能只 push 一个 .so。转译层和 App 都可能检测 root/模拟器，失败就回退。

### WSL 验证结果（2026-11-15，仅验证环境）

```text
WSL2 Ubuntu / kernel 6.18 / 16 vCPU / 15GB
/dev/kvm: 存在，emulator -accel-check = KVM usable
binder: 无
Android 14 AOSP x86_64 headless: 启动成功
sys.boot_completed=1: 约 24 秒
uiautomator dump: 成功，Settings 页面解析到 13 个文本节点
Waydroid/redroid: 未验证（WSL 没有 binder）
番茄 APK / 登录: 未验证（还没有 APK）
```

结论：**KVM + Android AVD 在 WSL 可跑**，但不是生产方案；Linux 服务器必须有 `/dev/kvm`，没有 binder 时 Waydroid/redroid 不可用。

### APK 实测（2026-11-15）

```text
APK/fanqie.apk: 125,723,616 bytes
native libs: 只有 arm64-v8a（115 个 .so）
WSL x86_64 Android 14 AVD 安装:
  INSTALL_FAILED_NO_MATCHING_ABIS
  Failed to extract native libraries, res=-113
```

结论：**x86_64 服务器不能直接装这个 APK**。要么：

1. 用 ARM64 Android 镜像 + QEMU TCG（能跑但很慢，不适合 1496 章全量）
2. Waydroid + ARM 翻译层（libhoudini / ndk translation，复杂且可能被检测）
3. 换 ARM 服务器（Ampere / 鲲鹏 / Apple Silicon Linux VM）
4. 真机（本次约束排除）
5. App API（不依赖容器，但需逆向/签名，风险更高）

### ARM64 AVD 实测（2026-11-15）

```text
emulator 37.3.9.0
AVD abi=arm64-v8a
启动报错：
FATAL | Avd's CPU Architecture 'arm64' is not supported by the QEMU2 emulator on x86_64 host.
       System image must match the host architecture.
```

结论：**这台 x86_64 主机不能用 ARM64 AVD**。要么给 AVD 装转译层（需要 Magisk/root），要么换 ARM 主机。

### 放弃条件

```text
截图被 FLAG_SECURE

```

### 边界

- 只用自己的账号，不共享、不卖账号。
- 不做破解签名/绕过 DRM；只做正常 App 的 UI 自动化。
- 优先 Waydroid/redroid；AVD 最后。
- 失败就明确报错或回退现有文本解析，不阻塞聊天。
- 云手机/手机农场不在本项目默认方案内。
