# v39 系列 · 手机 App 独立模式

> 前置：v38 手机 App｜预估 4 天｜**四个次版本**
>
> 定位：手机 App 默认仍连后端；**只有连不上后端时**，才切换到直连模型。
> 这是降级模式，不是替代后端，也不改变其他前端的协议。

## 原则

```text
默认：App -> 后端 -> 模型 / 记忆 / 状态
降级：App -> DeepSeek（仅当后端不可达）
```

- 后端可达时，绝不直连模型。
- 直连只使用与其它前端相同的消息结构，不另造一套协议。
- 直连不写后端记忆，不冒充完整功能。
- 用户必须显式同意“离线直连”，并自己提供 API Key。
- 后端恢复后自动回到后端模式，不静默同步离线对话。

## 触发条件

满足全部条件才进入直连：

1. 后端健康检查连续失败 3 次，或单次超时 ≥ 5 秒；
2. 本地已配置 DeepSeek API Key（安全存储）；
3. 用户在设置里允许“后端不可用时直连”；
4. 当前网络可访问模型 API。

界面上必须显示：

```text
离线模式：后端不可达，当前直连 DeepSeek
```

## 能力边界

| 能力 | 后端模式 | 直连模式 |
|---|---|---|
| 聊天 | ✅ | ✅ 基础对话 |
| 长期记忆 | ✅ | ❌ 只用本地最近 N 条 |
| 关系/生活状态 | ✅ | ❌ |
| 定时/主动消息 | ✅ | ❌ |
| QQ 通道 | ✅ | ❌ |
| 多端同步 | ✅ | ❌ |
| Token 统计 | ✅ | 本地显示本次估算 |

## 接口

请求体与其它前端保持一致：

```json
{
  "message": "在吗",
  "target_id": "__owner__",
  "client": "mobile-offline"
}
```

直连时只把同一份 `messages` 发给 DeepSeek：

```text
system: 本地缓存的人设快照
user:   本地最近 N 条对话 + 当前消息
```

不发送数据库里的隐私字段，不上传本地记忆。

## 次版本

| 版本 | 内容 | 验收 |
|---|---|---|
| **v39.0** | 后端连通性探测 + 3 次失败/5s 超时触发降级 + 离线横幅 | 后端挂了才进离线 |
| **v39.1** | DeepSeek 直连客户端 + API Key 安全存储 + 用户开关 | 没 Key 不静默失败 |
| **v39.2** | 本地最近 N 条对话缓存 + 人设快照 + token 估算 | 离线可连续对话 |
| **v39.3** | 后端恢复切回 + 不静默同步 + 测试/文档 | 恢复后不重复写记忆 |

## 验收

```text
1. 后端正常：所有请求只走后端，直连客户端零调用
2. 后端关闭：3 次失败后提示离线模式，可直连回复
3. 无 API Key：提示配置，不自动切直连
4. 后端恢复：自动回后端，离线对话不自动入库
5. 离线模式不显示记忆/定时/QQ 等功能为“可用”
6. API Key 不进日志、不进普通配置、不上传
```

## 不做

- 不在后端可用时直连模型
- 不做离线长期记忆
- 不做离线 QQ / 定时 / 主动消息
- 不做离线对话自动同步（避免重复记忆）
- 不把 API Key 写进明文配置文件
