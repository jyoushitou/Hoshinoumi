# v39 系列 · 运维与嵌入式

> 大版本 v39。目标：后端常驻可自愈，嵌入式屏能常亮显示对话。

## 1. 范围

### 要做

```text
systemd 单元 / 自启 / 看门狗
worker + ingress 健康检查
崩溃拉起、重启恢复
嵌入式前端：树莓派/平板 + Chromium kiosk
触摸/软键盘/断网恢复
```

### 不做

```text
不新起第二套后端
不做硬件定制驱动
不做离线全功能客户端
```

## 2. 架构

```text
systemd
  ├─ hoshinoumi-ingress.service
  ├─ hoshinoumi-worker.service
  └─ hoshinoumi-watchdog.timer

嵌入式：
  Chromium kiosk
    → http://127.0.0.1:5492（Web UI）
    → 复用 v35 hub/本机服务
```

## 4. 开发思路

### 4.1 常驻

- unit 只负责拉起；业务仍由 supervisor 管蓝绿。
- watchdog 不做业务逻辑，只查 health/ready。
- 重启必须保留 `data/` / `logs/`。

### 4.2 嵌入式

- 不写原生 App；Chromium kiosk 直接加载 Web UI。
- 断网时显示最后缓存 + “重连中”，不假装在线。
- 触摸目标 ≥ 44px；软键盘不能遮输入框。

### 4.3 恢复

```text
启动 → 读 last_conversation_cache
→ 连本机服务
→ 拉增量 history
→ 失败显示离线提示
```

## 5. 风险

- systemd 与 supervisor 抢进程：unit 只启动 supervisor/ingress，不直接起 worker。
- 看门狗误杀：连续 3 次失败才重启。
- 嵌入式性能：限制动画/图片；先文本。
- 断电损坏：SQLite WAL + 只读缓存。

## 6. 总验收

```text
1. 重启机器后自动恢复
2. kill worker 后 30s 内拉起
3. 嵌入式开机进入对话
4. 断网显示离线，不白屏
5. 触摸/软键盘可用
6. 统计报告可查
```
