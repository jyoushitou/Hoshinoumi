# v39 系列 · 运维

> 大版本 v39。目标：后端常驻可自愈。
> 嵌入式前端顺延为 v41；v40 是虚拟游乐场。

## 1. 范围

```text
systemd 单元 / 自启
worker + ingress 健康检查
崩溃拉起、重启恢复
日志轮转/崩溃留痕
```

不做：

```text
不新起第二套后端
不做嵌入式前端（v41）
```

## 2. 架构

```text
systemd
  ├─ hoshinoumi-ingress.service
  ├─ hoshinoumi-worker.service
  └─ hoshinoumi-watchdog.timer
```

## 3. 次次版本

| 版本 | 内容 | 开发思路 | 验收 |
|---|---|---|---|
| **v39.0.0.0** | systemd 单元 + 自启 | 两个 unit；EnvironmentFile；Restart=always | 开机自启 |
| **v39.0.1.0** | 健康检查 + 看门狗 | timer 每 30s 查 `/readyz`；失败重启 worker | 崩溃 30s 内拉起 |
| **v39.0.2.0** | 日志轮转/崩溃留痕 | journald + 本地 crash 摘要 | 崩溃可查 |
| **v39.1.0.0** | 统计 + 修 v39 遗留 bug | 只修 bug | 测试全绿；P0/P1 清零 |

## 4. 约束

- unit 只负责拉起；业务仍由 supervisor 管蓝绿。
- watchdog 不做业务逻辑，只查 health/ready。
- 重启必须保留 `data/` / `logs/`。

## 5. 风险

- systemd 与 supervisor 抢进程：unit 只启动 supervisor/ingress。
- 看门狗误杀：连续 3 次失败才重启。

## 6. 总验收

```text
1. 重启机器后自动恢复
2. kill worker 后 30s 内拉起
3. 崩溃日志可查
4. 统计报告可查
```
