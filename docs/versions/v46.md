# v46 系列 · 视频（二）抖音

> 前置：v35（B 站框架）｜预估 3 天
>
> 把 v35.0（B 站）的「刷视频」框架接到抖音上——**同一套逻辑，换一个数据源**。

## 目标

## 为什么单独一版

| 维度 | B 站（v35.0） | 抖音（v36.0，本版） |
|---|---|---|
| 公开接口 | 有 | **没有稳定接口** |
| 反爬 | 中等 | **强**（签名、设备指纹） |
| 风险 | 低 | 高（账号/IP 可能被风控） |
| 正文信息 | 标题/简介/字幕/弹幕 | 基本只有标题和作者 |

所以抖音**不能照抄 B 站的抓法**，要单独适配，风险也单独评估。

## 触发时机（与 v35.0 一致）

| 条件 | 说明 |
|---|---|
| 主人 ≥2 小时没说话 | 可调 |
| 每天最多 3 条 | 与 B 站**分开计数** |
| 01:00~07:00 不刷 | 深夜 |

## 能力范围

| 层级 | 能力 | 可行性 |
|---|---|---|
| L1 看 | 拉推荐/关注流，拿标题、作者、话题标签 | ⚠️ 需要登录态 + 反爬对抗 |
| L2 转 | 群里 @ 主人 + 链接 + 她的一句话 | ✅ 完全可行 |
| L3 评 | 在视频下**发评论** | ❌ **不做**（签名复杂、风控极强） |

**明确不做 L3**——抖音的写接口签名经常变，投入产出比太低。

## 两种实现路线

### 路线 A：无登录抓公开页（优先）

```
https://www.douyin.com/discover      → 推荐页 HTML
https://www.douyin.com/user/xxx      → 作者主页
```

用 Playwright 打开、等渲染、取标题和链接。
**优点**：不需要你的账号。
**缺点**：抖音对无登录访问限制多，可能只拿到少量内容或空白。

### 路线 B：注入登录 cookie（备选）

```
data/cookies.json → {"douyin": [...]}
```

有 cookie 后能拿到「关注」流，但**风险转移到账号上**：

- 用**小号**，不要主号
- 别高频访问（每天 ≤3 次）
- 出现验证码立刻停，别硬刚

## 内容安全

| 项 | 做法 |
|---|---|
| 关键词屏蔽 | 政治/攻击/引流/低俗，命中丢弃换下一条 |
| 频率 | 每天 ≤3 条，冷却 1 小时 |
| 深夜 | 01:00~07:00 不刷 |
| 内容长度 | 只取标题（≤60 字），不摘要长文案 |

## 涉及文件

- 新建 `bot/life/douyin.py`（数据源适配器，接口与 `bilibili.py` 一致）
- 改 `bot/life/watch.py`（数据源可插拔：`NAO_VIDEO_SOURCE=bilibili|douyin|both`）
- 复用 `bot/life/cookies.py`（已支持 `douyin` 域名）

## 验收

- [ ] 挂机两小时后，日志出现「刷抖音」记录
- [ ] 能在群里 @ 主人分享，链接可点开
- [ ] 同一视频不重复推
- [ ] 无 cookie 时自动跳过（不报错）
- [ ] 出现验证码时当天停用

## 红线

| 红线 | 原因 |
|---|---|
| 不做发评论 | 签名对抗成本过高 |
| 默认关闭，需显式开启 | 风险最高的一环 |
| 只用小号 | 封号不牵连主号 |
| 每天 ≤3 次访问 | 高频必被标记 |
| 不下载视频 | 流量 + 版权 |

## 降级

| 失败 | 处理 |
|---|---|
| 无 cookie | 完全不启动这条链路 |
| 页面空白/验证码 | 当天停用，日志告警 |
| 解析失败 | 跳过本次，不影响 B 站那条 |
| 连续失败 2 次 | 停用 24 小时 |

---

## 系列风险

| 风险 | 处理 |
|---|---|
| 平台反爬升级 | 每层都降级到「只记书名/标题」，不报错 |
| 账号被风控 | L3 发评论只用小号，连续失败即停 |
| 抓取拖慢聊天 | 走 v17 的 P2 队列，聊天走 P0 |
