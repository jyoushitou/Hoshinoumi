# v23 系列 · 运维通道（四）可写体系

> 前置：v21（有限写）｜预估 3 天｜**最高风险，默认关闭**

## 原则

**先备份 → 再执行 → 可回滚**。三步缺一不可。

```
你：把日志级别改成 DEBUG
她：即将修改 config.local.json（log_level: INFO → DEBUG）
    已备份到 backups/20261110-1432/config.local.json
    回复「确认」在 60 秒内生效

你：确认
她：✅ 已修改。如需回滚：!rollback 20261110-1432
```

## 为什么不能直接放开

| 直接放开 | 后果 |
|---|---|
| `sed -i` 改错一行 | 配置坏了，机器人起不来 |
| 迁移脚本跑一半 | 数据半新半旧 |
| 重启失败 | 服务长时间不可用 |

**备份 + 回滚是让「写」变得可接受的前提。**

## 写操作分级

| 级别 | 操作 | 备份方式 | 回滚方式 |
|---|---|---|---|
| **W1** | 改配置文件（`config.local.json`、`data/tunables.json`） | 复制原文件 | 拷回原文件 |
| **W2** | 重启服务/容器 | 记状态快照（`docker inspect` / `systemctl status`） | 重新拉起旧容器/服务 |
| **W3** | 更新代码（`git pull` / 切 tag） | 记当前 commit hash | `git reset --hard <hash>` |
| **W4** | 数据库迁移 | **先 dump 相关表** | 用 dump 恢复 |

**不支持的**（永远禁止）：

| 禁止 | 原因 |
|---|---|
| `rm` / `mv` 任意文件 | 无法可靠回滚 |
| 改系统文件（`/etc/*`） | 影响面太大 |
| 装/卸软件包 | 副作用不可控 |
| 改数据库结构（手工 DDL） | 必须走迁移脚本 |
| 关防火墙/开端口 | 安全风险 |

## 备份实现

### 目录结构

```
data/backups/
  20261110-1432/
    manifest.json          # 这次改了什么、为什么、谁触发
    config.local.json      # 文件快照
    db_tables.sql          # 表 dump（W4 才有）
    service_state.json     # 服务快照（W2 才有）
```

`manifest.json`：

```json
{
  "id": "20261110-1432",
  "level": "W1",
  "session": "822891053-1762753920-ab12",
  "target": "config.local.json",
  "before": "INFO",
  "after": "DEBUG",
  "created_at": "2026-11-10 14:32:05",
  "restored": false
}
```

### 保留策略

| 项 | 值 |
|---|---|
| 最多保留 | 10 份 |
| 单份上限 | 50 MB（DB dump 单独限制） |
| 超限 | 删最旧的（**已回滚过的优先删**） |

### DB 备份

复用已有的 `scripts/backup_table.py`（v7 就写了，支持 `--restore --wipe`）。

```
python3 scripts/backup_table.py --table events --out data/backups/<id>/events.sql
```

## 回滚

```
!rollback <id>          # 回滚指定备份
!rollback last          # 回滚最近一次
!backups                # 列出可用备份
```

回滚流程：

```
读 manifest → 按 level 选恢复方式 → 执行 → 验证 → 标记 restored
```

| 级别 | 回滚动作 |
|---|---|
| W1 | 拷回文件 → 重启或热加载 |
| W2 | 用快照重新拉起旧容器 |
| W3 | `git reset --hard <hash>` → 重启 |
| W4 | 还原表 → 重启 |

## 二次确认（写操作必须）

```
她：即将修改 X（A → B），已备份到 <id>
    回复「确认」在 60 秒内生效，其他内容视为取消
```

| 规则 | 说明 |
|---|---|
| 确认词 | 精确匹配「确认」 |
| 有效期 | 60 秒 |
| 超时 | 自动取消，备份保留（可手动清理） |
| 取消 | 任何其他消息 |
| agent 模式 | **同样要确认**，模型不能自己确认 |

## 与前后版本的关系

| 版本 | 关系 |
|---|---|
| v20.0/v20.1 | 复用只读白名单；本版新增「写白名单」 |
| v23 | 本版把 v20.2 的「单步写 + 备份」扩展成完整体系（分级/回滚/统计） |
| v20.1 agent | 可以调用写工具，但**必须先请求确认**，不能自批 |

**agent 不能自己确认**——这是硬约束：模型只能发起，人类才能批准。

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `write_enabled` | false | 写操作总开关 |
| `write_confirm_sec` | 60 | 确认有效期 |
| `backup_keep` | 10 | 保留备份份数 |
| `backup_max_mb` | 50 | 单份上限 |

## 验收

- [ ] 改配置前自动生成备份（文件 + manifest）
- [ ] 60 秒内没回「确认」→ 自动取消
- [ ] `!rollback last` 能把配置改回去
- [ ] 重启失败后能重新拉起旧容器
- [ ] W4 迁移前有表 dump，回滚能还原
- [ ] `rm`/`apt`/`/etc` 类操作被拒绝
- [ ] agent 发起的写操作也要人确认
- [ ] 每条写操作进审计（含 backup id）

## 风险

| 风险 | 处理 |
|---|---|
| 备份本身失败 | **备份失败 = 拒绝执行**（不允许无备份的写） |
| 回滚也失败 | 提示「需要 SSH 手动处理」+ 给出备份路径 |
| 磁盘被备份占满 | 保留 10 份 + 单份上限 |
| 备份里含密钥 | 备份目录权限 700，不进版本库 |
| 误确认 | 60 秒窗口 + 明确写出「A → B」 |

## 系列风险

| 风险 | 处理 |
|---|---|
| 账号被盗 | 鉴权 + 失败锁定 + 群里禁用 + 默认关闭 |
| 误操作 | 只读优先；写操作强制备份 + 二次确认 |
| 注入 | `shell=False` + 参数正则校验 |
| 模型幻觉 | agent 结论必须引用工具输出 |
| 备份占满磁盘 | 保留 10 份 + 单份上限 |
