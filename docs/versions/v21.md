# v21 系列 · 网关（二）owner 鉴权

> 前置：v20（核心与代理）｜预估 4.5 天｜**三个次版本**
>
> v21 只做 owner 一个账号的鉴权。多用户 `users` / role / 邀请码在 v23 才引入；
> 届时 v23.3 再把网关鉴权升级为 JWT `sub=user_id`。

## 目标

- 公网请求必须带 token，否则 401
- `owner_secret` 登录 → access + refresh
- access 过期可刷新，刷新不换 subject
- 失败 3 次锁 5 分钟
- 客户端 body/query 里的 `user_id` 一律忽略，只信 token 的 `sub`

## 不做什么

- 不查 `users` 表（v23 才有）
- 不做注册/邀请码
- 不做限流/TLS/审计（v22）
- 不做多用户/role

| 版本 | 内容 | 天数 |
|---|---|---|
| v21.0 | 登录 + JWT 中间件 + 注入 owner | 2 |

## v21.0 · 登录与中间件（2 天）

| 单元 | 内容 | 验收 |
|---|---|---|
| U1 | `POST /api/login`：`owner_secret` → access + refresh | 缺少/错误 secret 401 |
| U2 | JWT 签发/校验；`sub=owner`、`role=owner` | 无 token 401 |
| U3 | 中间件把 `sub=owner` 注入 gRPC metadata | 后端收到 owner |
| U4 | 客户端 body/query 的 `user_id` 覆盖无效 | 改 body 也越不了权 |

## v21.1 · 刷新与锁定（2 天）

| 单元 | 内容 | 验收 |
|---|---|---|
| U1 | `POST /api/refresh`；刷新不换 `sub` | 过期可换新 |
| U2 | 失败 3 次锁 5 分钟（按 IP） | 第 4 次 429 |
| U3 | token 24h 过期；secret 只从环境/配置读 | 日志不出现 secret/token 全文 |
| U4 | 401/403 错误格式统一 | 客户端能区分过期/无权限 |

## v21.2 · 网关对话入库（0.5 天）

> 现状：QQ 私聊/群聊会写 `conversation_messages`，但通过网关
> `POST /api/chat` 的对话只返回回复，不落库；`!history` / `/internal/history`
> 看不到网关对话。v21.2 在鉴权完成后补齐，写入身份直接取 JWT 的 `sub`。

| 单元 | 内容 | 验收 |
|---|---|---|
| U1 | `/internal/chat` 成功拿到回复后，写 user + assistant 两条 `conversation_messages` | 网关对话能在 history 里看到 |
| U2 | `user_id` 取 JWT `sub=owner`，`target_id` 取请求目标；`source=gateway` | body 里的 `user_id` 不能越权 |
| U3 | `!history` 和 `/internal/history` 都能读到网关对话，保持时间顺序 | QQ 与网关混合排序正确 |
| U4 | AI 报错/空回复不写半条；重试不产生重复记录 | 失败不污染历史 |
| U5 | 网关对话只入库，不触发 QQ 发送；QQ 自己的入库逻辑不重复 | API 调用不导致 QQ 多一条 |
| U6 | 测试：带 token POST `/api/chat` → `conversation_messages` +2；再查 history 能看到 | 回归测试固定 |
| U7 | 未带 token / 坏 token 时仍 401，不能靠对话接口写入 | 鉴权优先于入库 |

**验收命令**：

```bash
TOKEN=$(curl -s -X POST http://127.0.0.1:27005/api/login \
  -H 'Content-Type: application/json' \
  -d '{"secret":"'$NAO_GATEWAY_OWNER_SECRET'"}' | jq -r .data.access)

curl -s -X POST http://127.0.0.1:27005/api/chat \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"message":"网关测试","target_id":"__owner__"}'

curl -s 'http://127.0.0.1:27004/internal/history?target_id=__owner__&limit=10'
```

期望 history 中出现：

```text
user      : 网关测试
assistant : 在。
```

> 说明：当前 v20 的 `/api/chat` 只返回 JSON，不会主动发 QQ；
> 入库是新增副作用。v23 多用户后 `sub` 换成真实 `user_id`，写入路径不变。

## 验收

```bash
# 登录
TOKEN=$(curl -s -X POST http://127.0.0.1:27005/api/login \
  -H 'Content-Type: application/json' \
  -d '{"secret":"'$NAO_GATEWAY_OWNER_SECRET'"}' | jq -r .data.access)

# 带 token
curl -s http://127.0.0.1:27005/api/state -H "Authorization: Bearer $TOKEN"

# 不带 token
curl -i http://127.0.0.1:27005/api/state        # 401
```

- 无 token/坏 token/过期 token 都是 401。
- 连续错 3 次后第 4 次 429。
- body 里写别人的 `user_id` 不影响服务端身份。

## 与 v22/v23 的边界

- **v22**：限流、审计、TLS、`!gw`、压测。
- **v23**：`users` 表、角色、邀请码；v23.3 把 `/api/login` 改成查 users，
  JWT `sub=user_id` + `role`，owner-only 模式退役。
