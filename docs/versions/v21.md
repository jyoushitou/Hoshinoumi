# v21 系列 · 网关（二）owner 鉴权

> 前置：v20（核心与代理）｜预估 4 天｜**两个次版本**
>
> v21 只做 owner 一个账号的鉴权。多用户 `users` / role / 邀请码在 v23 才引入；
> 届时 v23.3 再把网关鉴权升级为 JWT `sub=user_id`。

## 目标

- 公网请求必须带 token，否则 401
- `owner_secret` 登录 → access + refresh
- access 过期可刷新，刷新不换 subject
- 失败 3 次锁 5 分钟
- 客户端 body/query 里的 `user_id` 一律忽略，只信 token 的 `sub`

## 不做什么

- 不查 `users` 表（v23 才有）
- 不做注册/邀请码
- 不做限流/TLS/审计（v22）
- 不做多用户/role

## 次版本拆分

| 版本 | 内容 | 天数 |
|---|---|---|
| v21.0 | 登录 + JWT 中间件 + 注入 owner | 2 |
| v21.1 | refresh + 失败锁定 + 测试 | 2 |

## v21.0 · 登录与中间件（2 天）

| 单元 | 内容 | 验收 |
|---|---|---|
| U1 | `POST /api/login`：`owner_secret` → access + refresh | 缺少/错误 secret 401 |
| U2 | JWT 签发/校验；`sub=owner`、`role=owner` | 无 token 401 |
| U3 | 中间件把 `sub=owner` 注入 gRPC metadata | 后端收到 owner |
| U4 | 客户端 body/query 的 `user_id` 覆盖无效 | 改 body 也越不了权 |

## v21.1 · 刷新与锁定（2 天）

| 单元 | 内容 | 验收 |
|---|---|---|
| U1 | `POST /api/refresh`；刷新不换 `sub` | 过期可换新 |
| U2 | 失败 3 次锁 5 分钟（按 IP） | 第 4 次 429 |
| U3 | token 24h 过期；secret 只从环境/配置读 | 日志不出现 secret/token 全文 |
| U4 | 401/403 错误格式统一 | 客户端能区分过期/无权限 |

## 验收

```bash
# 登录
TOKEN=$(curl -s -X POST http://127.0.0.1:27005/api/login \
  -H 'Content-Type: application/json' \
  -d '{"secret":"'$NAO_GATEWAY_OWNER_SECRET'"}' | jq -r .data.access)

# 带 token
curl -s http://127.0.0.1:27005/api/state -H "Authorization: Bearer $TOKEN"

# 不带 token
curl -i http://127.0.0.1:27005/api/state        # 401
```

- 无 token/坏 token/过期 token 都是 401。
- 连续错 3 次后第 4 次 429。
- body 里写别人的 `user_id` 不影响服务端身份。

## 与 v22/v23 的边界

- **v22**：限流、审计、TLS、`!gw`、压测。
- **v23**：`users` 表、角色、邀请码；v23.3 把 `/api/login` 改成查 users，
  JWT `sub=user_id` + `role`，owner-only 模式退役。
