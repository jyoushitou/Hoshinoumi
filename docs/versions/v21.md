# v21.0.0 · systemd 服务化

## 现状的问题

| 问题 | 现状 | 目标 |
|---|---|---|
| 开机启动 | 手动 `screen -r bot` | `systemctl enable` 自启 |
| 崩溃恢复 | 进程挂了自己发现 | `Restart=always` 3 秒拉起 |
| 日志 | `botv.log` 文件，轮转靠手动 | journald 统一收集 |
| 多实例 | 靠单实例锁 | 由 systemd 保证 |

## unit 文件

```ini
# /etc/systemd/system/nao-bot.service
[Unit]
Description=TomoriNao QQ Bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=naoyou
WorkingDirectory=/opt/nao-bot
Environment="PYTHONUNBUFFERED=1" "PYTHONIOENCODING=utf-8" "TZ=Asia/Shanghai"
ExecStart=/opt/nao-bot/venv/bin/python /opt/nao-bot/run.py
Restart=always
RestartSec=3
# 崩溃循环保护：10 分钟内超过 5 次就不再重启
StartLimitIntervalSec=600
StartLimitBurst=5
# 资源边界
MemoryMax=800M
CPUQuota=150%
# 日志
StandardOutput=journal
StandardError=journal
SyslogIdentifier=nao-bot

[Install]
WantedBy=multi-user.target
```

## 关键取舍

| 参数 | 值 | 为什么 |
|---|---|---|
| `Restart=always` | 总是重启 | 宁可重启也不静默挂掉 |
| `RestartSec=3` | 3 秒 | 太快会打爆 API；太慢用户能感知 |
| `StartLimitBurst=5` | 10 分钟 5 次 | 防止「配置错→崩溃→重启」死循环 |
| `MemoryMax=800M` | 硬上限 | 泄漏时被杀而不是拖垮整机 |

## 验收

- [ ] `systemctl start nao-bot` 能起来
- [ ] `kill -9` 后 3 秒自动重启
- [ ] 配置写错导致连续崩溃时，10 分钟内停手（不无限重启）
- [ ] `journalctl -u nao-bot -f` 能看实时日志
- [ ] 重启机器后自动启动

# v21.0.1 · 看门狗与自愈

## 三层看门狗

| 层 | 检测什么 | 动作 |
|---|---|---|
| **系统层** | 进程不存在 | systemd `Restart=always` |
| **应用层** | 心跳线程卡住（> 90 秒没跳） | 主动 `sys.exit(1)`，让 systemd 重启 |
| **业务层** | 连续 N 次模型调用失败 | 降级到兜底回复 + 告警，不退出 |

## 应用层看门狗

已有心跳机制（`heartbeat.py`），但**心跳停了没人管**。补一个：

```python
async def watchdog(interval=30, timeout=90):
    while True:
        await asyncio.sleep(interval)
        if time.time() - last_beat > timeout:
            log_system("看门狗：心跳超时，主动退出让 systemd 重启")
            os._exit(1)      # 不能用 sys.exit（可能卡在 await 里出不来）
```

**为什么用 `os._exit`**：`sys.exit()` 在协程里只是抛异常，可能被上层吞掉；`os._exit` 直接结束进程。

## 业务层降级（不重启）

| 情况 | 动作 |
|---|---|
| 模型连续失败 3 次 | 回兜底文案，记告警 |
| 数据库连不上 | 降级为「无记忆模式」跑 5 分钟，再试重连 |
| 磁盘 > 90% | 停写日志文件，只走 journald |

## 验收

- [ ] 杀掉心跳线程 → 90 秒内进程退出并被拉起
- [ ] 断网时模型失败 → 回兜底不崩
- [ ] 数据库停掉 → 5 分钟内自动重连
- [ ] 看门狗动作都进日志（能查「为什么重启了」）

# v21.1.0 · LITE 模式

## 为什么需要

Chromium（~400 MB）+ tesseract 在小机器上吃不住。**关掉它们，核心功能仍然可用**：

| 功能 | 完整模式 | LITE 模式 |
|---|---|---|
| 文字聊天 | ✅ | ✅ |
| 记忆 / 检索 | ✅ | ✅ |
| 生活事件 / 主动消息 | ✅ | ✅ |
| 看图（多模态） | ✅ | ⚠️ 只记「收到一张图」 |
| 读小说正文 | ✅ OCR | ❌ 只记书名/目录/进度 |
| 刷视频 | ✅ | ❌ 关闭 |
| 语音合成 | ✅ | ❌ 只发文字 |
| 语音转写 | ✅ | ❌ 回「听不清，打字吧」 |

## 开关

```bash
NAO_LITE=1        # 一键进入精简模式
```

实现：启动时按 LITE 决定**注册哪些能力**，不做运行期 if-else 遍地。

```python
CAPABILITIES = {
    "vision": not LITE,
    "novel_body": not LITE,
    "video": not LITE,
    "tts": not LITE,
    "asr": not LITE,
}
```

## 验收

- [ ] `NAO_LITE=1` 启动后，不会 import playwright / tesseract
- [ ] 内存占用比完整模式低 50% 以上
- [ ] 聊天、记忆、主动消息全部正常
- [ ] 遇到被关掉的能力时，给一句自然的回应（不是报错）

# v21.1.1 · ARM / 树莓派适配

## 要验证的

| 项 | 风险 |
|---|---|
| Python 3.12 是否有 ARM wheel | 大多有 |
| `pymysql` / `jieba` / `Pillow` | 纯 Python 或预编译，OK |
| `playwright` | ARM 无官方 Chromium 构建 → **LITE 模式必须**
| `tesseract` | apt 有，但慢 |
| 内存 | 4 GB 设备跑完整模式会 OOM |

## 推荐配置（树莓派 4B / 4 GB）

```
NAO_LITE=1
NAO_TASK_THREADS=2        # 别把 CPU 占满
MemoryMax=600M
```

## 验收

- [ ] 树莓派 4B 上 `NAO_LITE=1` 能跑 24 小时不 OOM
- [ ] 响应延迟 < 5 秒（本地网络）
- [ ] `systemctl status` 内存稳定（无持续增长）

# v21.1.2 · 一键安装脚本

## 做什么

```bash
curl -fsSL https://.../install.sh | bash
```

脚本内容：

| 步骤 | 动作 |
|---|---|
| 1 | 检查 Python ≥ 3.10、git、systemd |
| 2 | 装依赖（LITE 模式跳过大包） |
| 3 | 创建用户 `naoyou`（非 root 运行） |
| 4 | 写 unit 文件 + `systemctl enable` |
| 5 | 生成 `config.local.json` 模板（权限 600） |
| 6 | 提示「填完配置后 systemctl start」 |

## 升级 / 回滚

```bash
nao-bot upgrade      # git pull + pip install + restart
nao-bot rollback     # 回到上一个 tag
nao-bot status       # systemctl status + 最近 20 行日志
```

## 验收

- [ ] 全新机器上一条命令装完
- [ ] 装完不用 root 就能启停
- [ ] `upgrade` 失败能自动回滚
- [ ] 配置文件权限 600

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `NAO_LITE` | 0 | 精简模式 |
| `NAO_WATCHDOG_SEC` | 90 | 心跳超时（秒） |
| `MemoryMax`（unit） | 800M | 内存硬上限 |

## 风险

| 风险 | 处理 |
|---|---|
| systemd 反复重启打爆 API | `StartLimitBurst` 限制 |
| 看门狗误杀 | 超时 90 秒（远大于正常卡顿） |
| LITE 模式功能缺失被当成 bug | 启动日志明确列出关闭的能力 |
| ARM 上依赖装不上 | 安装脚本检测架构，自动切 LITE |
| 一键脚本 curl|bash 的风险 | 提供 `install.sh` 可下载先读再跑 |
