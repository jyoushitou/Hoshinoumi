# v32 系列 · 跨层扩展接口与回退契约

> 前置：v24 插件管理 / v25–v31 七层接口｜预估 4 天｜**四个次版本**
>
> 定位：在 v31 之后插入的**跨层大版本**，不重排 v33+ 编号。
>
> **这一版不写任何插件。** 只把“插件以后可以接进来”的接口、注册点和
> fallback 契约做出来；核心功能保持 native，先按原路径运行。
> **这一版本身是核心开发计划**，实现的是第三方插件接入能力，不是插件。
>
> **核心范围**：v23 之前（含当前 bot）的聊天、记忆、命令、定时、语音、视觉、
> 读书、OCR、备份、主动消息全部是核心功能。它们只能在启动前通过
> `config/features.json` / `NAO_FEATURES` 关闭；插件不能 disable/uninstall 核心，
> 也不能在运行时把核心从候选链里删掉。

## 一句话

```text
这一版不写插件，只写插件能插进来的接口。
现在核心自己走；
以后插件可用时改变路径；
插件不可用，回到核心。
```

## 不是什么

- 不是实现具体插件
- 不是插件市场/插件包
- 不是把核心功能改写成插件
- 不是卸载/删除核心实现
- 不是自动把未知插件提升为默认

## 接口模型

每层已有接口（`ModelProvider` / `MemoryStore` / `Channel` / `Tool` /
`StorageBackend` / `Scheduler` / `Transport`）。v32 只统一“候选链”的形状：

```text
RouteKey = layer + capability + user_id + scene

Candidate = {
    origin: "native" | "plugin",   // v32 只产生 native
    name: str,
    priority: int,
    health: "ok" | "down" | "unknown"
}

resolve(RouteKey) -> [candidate, ..., native_fallback]
```

规则：

1. `native_fallback` 是核心实现，必须存在，且永远排在最后。
2. 核心实现不走 manifest / install / disable / uninstall。
3. v32 只注册 native；`origin="plugin"` 的分支先留空，由 v24 的插件管理器以后接入。
4. 调用按候选链尝试；失败/超时/异常/空结果 → 下一个候选。
5. 最后一定回到核心；核心不可用才算整体失败。
6. 同一请求不允许路由递归；每个候选只调用一次。
7. 没有插件时，行为必须和 v31 完全一致。

## 次版本

| 版本 | 内容 | 天数 | 验收 |
|---|---|---|---|
| **v32.0** | `RouteKey` / `RouteRegistry` / `FallbackChain` 契约 + native 注册 | 1 | 无插件时行为与 v31 一致 |
| **v32.1** | 七层 adapter 统一接入 + 候选链元数据（priority/health） | 1 | 每层都能返回 native 候选 |
| **v32.2** | 路由配置 + `!route` 只读视图 + 决策日志 | 1 | 能解释“为什么走 native” |
| **v32.3** | 测试替身 + 故障注入 + 七层回归 | 1 | 替身失败能回退 native；不发布插件 |

> 测试替身只存在于 tests/，不是发布插件；用于证明接口和 fallback 契约成立。

## 七层接入

| 层 | 核心 native | 本版只做 | 以后插件可接 |
|---|---|---|---|
| 模型 | DeepSeek / 豆包 | native 候选 + fallback | 新 provider |
| 记忆 | BM25 | native 候选 + fallback | 向量库 / 外部检索 |
| 通道 | QQ / NapCat | native 候选 + fallback | Web / 微信 / Webhook |
| 工具 | 现有工具 | native 候选 + fallback | 外部 MCP / 新工具 |
| 存储 | MySQL / SQLite | native 候选 + fallback | 外部 backend / 只读副本 |
| 调度 | asyncio | native 候选 + fallback | 外部 trigger / 队列 |
| 出站 | WebSocket | native 候选 + fallback | HTTP / Webhook / MQ |

## 配置示例

```jsonc
{
  "routing": {
    "model": {
      "prefer": ["native"],
      "fallback": "native",
      "allow_plugin": false
    },
    "memory": {
      "prefer": ["native"],
      "fallback": "native",
      "allow_plugin": false
    }
  }
}
```

- v32 只接受 `native` 候选；`allow_plugin=false` 是默认值。
- 以后插件接入时，才允许配置插件名；但 `fallback` 永远必须是 `native`。
- 不提供“删除 native”的配置。

## 验收

```bash
!route list                 # 七层候选链，只有 native
!route test model           # 走一次，显示命中 native / 耗时
!route log                  # 最近决策，能解释 fallback
```

必须成立：

- 完全不装插件：七层行为与 v31 一致。
- 核心 native 永远在候选链末尾。
- 测试替身失败/超时/空结果：回退 native。
- 路由递归：拒绝并报错。
- 核心不出现在插件列表，也没有 install/disable/uninstall。

## 关键测试

```text
1. 无插件：七层行为与 v31 完全一致
2. native 候选：每层都能被 RouteRegistry 找到
3. fallback：替身失败后回到 native
4. 递归：RouteKey 自调用被拒绝
5. 配置：allow_plugin=false 时插件候选不生效
6. 观测：!route log 能看到候选链和命中原因
```

## 不做

- 不实现任何发布插件
- 不做插件安装/升级/市场
- 不删除、不改写核心实现
- 不把核心注册成插件
- 不做跨用户路由/越权选择

## 与 v33+ 的关系

v33 多端推送、v34 IDE 插件、v35+ 客户端都建立在同一套接口上：

- v32 提供“可插接口 + 回退契约”
- v33+ 才决定具体入口和客户端
- 具体插件实现放到后续版本，不在 v32 里写

> 这一版是“留接口”，不是“写插件”。
> 核心是保底，不是备胎代码；它必须一直可运行、可回退、可验证。
