# v32 系列 · 记忆层插件接入

> 前置：v31 记忆层契约 + native adapter。  
> 本版只做第三方 记忆层实现接入，不重写核心 native。  
> 跨版本总纲：[INTERFACE-PLAN-v27-v44.md](../INTERFACE-PLAN-v27-v44.md)。

## 目标

```text
PluginRegistry 注册 记忆 adapter
→ 权限 / 错误 / 任务 / 热更走 v28 运行时
→ 调用方 get() 拿不到时回落 SQLMemoryStore / BM25
```

## 次版本

| 版本 | 内容 | 验收 |
|---|---|---|
| **v32.0** | 第三方 `MemoryStore / Retriever` adapter 接入点 + fake 实现 | 不改业务代码即可切换实现 |
| **v32.1** | 权限、错误、任务、热更接入 | 违规调用被拒绝；失败可查 |
| **v32.2** | 回归、文档、停用/回滚 | native 默认不受影响 |
| **v32.3** | 读取现有钩子并批量追加补充话术 | 不新建重复提醒；按关键词/场景批量改 |
| **v32.4** | 多行命令输入：按行拆分、逐条执行、分别输出 | 每行一条命令；每条单独回复；可配置上限 |

## v32.0 完成记录

- `MemoryRouter`：`memory.store.<name>@1` / `memory.retriever.<name>@1` 从 PluginRegistry 取。
- 取不到回落 SQLMemoryStore / BM25Retriever。
- 缓存 + invalidate。
- 回归：插件选中、native 回落、缓存失效。

## v32.1 完成记录

- 插件记忆调用前 `plugin.call` 权限检查；默认 1 回落 native。
- 插件异常写 plugin_errors 并清缓存；操作回落 native。
- store/retriever 操作：add/delete/recent/search。
- 停用 DB 记录时回落 native。
- 回归：默认权限、异常落库、缓存失效。

## 能力与约束

- 能力名：`memory.store.<name>@1 / memory.retriever.<name>@1`。
- 核心 native（SQLMemoryStore / BM25）不实现 PluginManifest、不进入插件表。
- 默认仍走 native；插件只能作为候选，除非显式路由/配置切换。
- 插件实现 `MemoryStore / Retriever`，通过 v27 `PluginRegistry` 注册。
- 插件任务、线程池、DB 连接池由 v28 context 提供。
- 插件失败写 `plugin_errors`，连续失败自动停用。
- 插件 DDL 只允许 `plugin_<name>_` 前缀，MySQL/SQLite。

## 非目标

- 不重新定义 记忆层 Protocol（v31 已完成）
- 不把 native 插件化
- 不允许插件改核心默认实现

## v32.3 · 钩子批量修改

### 场景

```text
用户：提醒我吃饭的时候，让我少吃点，我要减肥
```

当前错误行为：

```text
重新建一条提醒，或者只回人设话术
已有的“提醒点外卖/提醒晚餐”钩子没有改
```

正确行为：

```text
读取现有 cron_tasks
→ 匹配“吃饭”相关钩子（提醒点外卖、提醒晚餐）
→ 批量追加补充话术
→ 不改变原时间、不新建重复提醒
```

### 数据

`cron_tasks` 增加一列：

```sql
suffix VARCHAR(200) NULL
```

- `content` / `scene:` 保持原样，不破坏 `_scene_of` 和当天覆盖。
- 执行提醒时：`content + ("，" + suffix if suffix)`。
- 旧的 `content` 不动，方便回滚。

需要 schema 31（当前 30）；迁移脚本新增列，旧数据 suffix 为 NULL。

### 意图

```text
“提醒我吃饭的时候，让我少吃点”
→ keyword=吃饭
→ action=append
→ suffix=少吃点
```

匹配规则：

```text
先匹配 scene 标签：提醒点外卖 / 提醒晚餐
再匹配 content 包含关键词
只处理 enabled 的任务
```

如果匹配到多条：

```text
列出 #id 时间 内容
批量更新
回复：已给 2 条吃饭提醒加上“少吃点”
```

如果 0 条：

```text
不偷偷新建；先问“要新建一条吃饭提醒吗？”
```

### 命令

```text
!cron append <关键词> <补充话术>
!cron suffix <id> <补充话术>
!cron suffix <id> clear
```

自然语言入口只做“追加”，不做删除/改时间；改时间仍走原有 `!cron`/当天覆盖。

### 验收

```text
1. 已有 2 条吃饭提醒
2. 说“提醒我吃饭的时候，让我少吃点”
3. 两条 task 的 suffix 都更新
4. 时间/next_ts/场景不变
5. 到点提醒文本包含“少吃点”
6. 没有匹配时不新建重复任务
```

## v32.4 · 多行命令输入

### 场景

一条 QQ 消息里写：

```text
!ping
!version
!cron
```

当前会把它当成一条命令解析，后半段变成参数。  
v32.4 要按行拆开，逐条执行，分别回复。

### 规则

```text
从第一行开始扫描
以 ! / ！ 开头的行 = 一条命令
不以 ! 开头的行 = 上一条命令的续行参数
没有当前命令时，普通聊天原样
```

示例：

```text
!say 今天想说三句话
第一句
第二句
```

拆成：

```text
命令 1：!say 今天想说三句话
第一句
第二句
```

示例：

```text
!ping
!version
```

拆成两条命令，分别回两条。

### 输出

```text
每条命令独立执行
每条命令独立发送回复
不合并成一条长消息
一条失败不影响下一条
中间没有回复的命令跳过
```

### 限制

```text
单条消息最多 10 条命令
每条命令走原有 15s 超时
超过上限只执行前 10 条并提示
群聊仍要求前缀/@，权限不变
```

### 验收

```text
1. !ping
!version → 两条回复
2. !ping
!help plugin → 两条回复
3. !say 多行内容 → 续行归入 !say
4. 第 2 条失败，第 1/3 条仍执行
5. 超过 10 条有明确提示
```
