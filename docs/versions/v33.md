# v33 系列 · 通道层契约与 native adapter

> 核心：把 QQ / NapCat 包成 `Channel` 实现，第三方通道接入在 v34。
> QQ / NapCat 是核心 native，不注册为插件。

```python
class Channel(Protocol):
    name: str
    async def start(self) -> None: ...
    async def stop(self) -> None: ...
    async def send(self, target: str, text: str) -> bool: ...
    def on_message(self, handler) -> None: ...
```

## 本层插件接口约束（v27 总纲）

> 跨版本总纲：[INTERFACE-PLAN-v27-v44.md](../INTERFACE-PLAN-v27-v44.md)

- 本版只开放**通道层**接口，不把其他层一起搬。
- 能力名：`channel.<name>@1`。
- 核心 native（QQ / NapCat）保持 native，**不实现 PluginManifest，不进入插件表**。
- 第三方实现本层 Protocol，通过 v27 `PluginRegistry` 注册。
- 业务只依赖 Protocol；`get()` 拿不到时回落核心 native。
- 敏感资源走 v27 权限三档（0 拒绝 / 1 询问 / 2 允许），默认 1。
- 插件任务、线程池、DB 连接池由 v27 context 提供，不允许裸 `create_task` / 裸连库。
- 插件失败写 `plugin_errors`，连续失败自动停用。
- 插件 DDL 走 `migrations/`，只支持 MySQL/SQLite，表前缀 `plugin_<name>_`。
- 热更采用 worker 进程级快照；已启用插件在新 worker 自动加载。

## 实现步骤

| 次版本 | 内容 | 验收 |
|---|---|---|
| **v33.0** | `Channel` / `Inbound` 契约 | 业务只依赖接口 |
| **v33.1** | `QQChannel` native adapter，包现有 NapCat 收发 | QQ 行为不变 |
| **v33.2** | 入站解析 adapter 化，现有私聊/群聊走同一接口 | 现有消息不丢 |

> 第三方通道层实现见 [v34.md](v34.md)。

## 关键约束

- QQ / NapCat 是核心 native，不注册为插件。
- 第三方通道只新增入口，不接管 QQ。
- 第三方通道失败由 v43 回退 QQ。
- 核心通道只能启动前通过 `features.json` / `NAO_FEATURES` 关闭。
