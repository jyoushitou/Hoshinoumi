# v33 系列 · 调度层接口实现

> 核心：把进程内 asyncio 调度器包成 `Scheduler` / `Trigger` 实现。
> asyncio 调度器是核心 native，不注册为插件。

```python
class Trigger(Protocol):
    name: str
    async def next_at(self, now): ...


class Scheduler(Protocol):
    name: str
    async def start(self) -> None: ...
    async def stop(self) -> None: ...
    async def schedule(self, trigger: Trigger, callback) -> str: ...
    async def cancel(self, task_id: str) -> None: ...
```

## 本层插件接口约束（v27 总纲）

> 跨版本总纲：[INTERFACE-PLAN-v27-v35.md](../INTERFACE-PLAN-v27-v35.md)

- 本版只开放**调度层**接口，不把其他层一起搬。
- 能力名：`scheduler.<name>@1 / schedule.trigger.<name>@1`。
- 核心 native（asyncio 调度器）保持 native，**不实现 PluginManifest，不进入插件表**。
- 第三方实现本层 Protocol，通过 v27 `PluginRegistry` 注册。
- 业务只依赖 Protocol；`get()` 拿不到时回落核心 native。
- 敏感资源走 v27 权限三档（0 拒绝 / 1 询问 / 2 允许），默认 1。
- 插件任务、线程池、DB 连接池由 v27 context 提供，不允许裸 `create_task` / 裸连库。
- 插件失败写 `plugin_errors`，连续失败自动停用。
- 插件 DDL 走 `migrations/`，只支持 MySQL/SQLite，表前缀 `plugin_<name>_`。
- 热更采用 worker 进程级快照；已启用插件在新 worker 自动加载。

## 实现步骤

| 次版本 | 内容 | 验收 |
|---|---|---|
| **v33.0** | `Scheduler` / `Trigger` 契约 | 业务只依赖接口 |
| **v33.1** | `AsyncioScheduler` native adapter | 现有定时行为不变 |
| **v33.2** | 现有 cron / items 收口到 Scheduler | 任务不重复/不漏 |
| **v33.3** | 第三方 trigger adapter + fake 测试 | 新触发器不改业务 |

## 关键约束

- asyncio 调度器是核心 native，不注册为插件。
- 第三方调度失败由 v35 回退 asyncio。
- 核心调度只能启动前通过 `features.json` / `NAO_FEATURES` 关闭。
