## 对话消息表（v19 核心）

> 目的：给“多方面的对话同步”准备一份**短期、可重放**的消息流；长期记忆仍走 `memories`。

```sql
conversation_messages (
  id          BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id     VARCHAR(64)  NOT NULL DEFAULT '__owner__',
  target_id   VARCHAR(64)  NOT NULL,          -- 私聊=用户；群=群号；Web=thread
  thread_id   VARCHAR(64)  NULL,              -- 同一会话的稳定 ID（多端同步用）
  channel     ENUM('qq','web','api','desktop','mobile') NOT NULL DEFAULT 'qq',
  role        ENUM('user','assistant','system') NOT NULL,
  content     TEXT         NOT NULL,
  message_id  VARCHAR(64)  NULL,              -- 渠道消息 ID，用于去重
  meta        TEXT         NULL,              -- JSON：图片/引用/语音等
  created_at  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_channel_msg (channel, message_id),
  KEY idx_target_time (target_id, created_at),
  KEY idx_user_time (user_id, created_at)
)
```

**保留策略**：

- 每个 `(user_id, target_id)` 保留**最近 1 天**且最多 **100 条**。
- 每天 04:00 由 `minute_tick` 清理；清理只删短期表，不动 `memories`。
- 同一个 `channel + message_id` 只写一次；机器人发出的消息用返回的 `message_id` 去重。

**写路径**：

- 入站：`chat.handler` 解析后写 `role=user`（图片/引用写 `meta`）。
- 出站：`chat.send` 成功发送后写 `role=assistant`（只记文本与气泡序号）。
- 失败不阻塞聊天；写库失败只告警。

**读路径**：

- QQ：`!history [n]`（默认 20，最多 100），按当前 `target_id` 倒序取最近 n 条。
- 内部 API：`GET /internal/history?target_id=&limit=&before=` 读同一张表。
- Web/手机：后续接同一张表，不另存一份。

## 功能启用清单与环境监测（v19.0）

> 目标：`run.py` 不再持有环境监测能力。谁检查、谁记录、谁读结果，三者分开。

### 文件分工

| 文件 | 所有者 | 作用 |
|---|---|---|
| `config/features.json` | 人 | 功能启用清单：哪些能力要开、哪些是必需 |
| `data/env_report.json` | `scripts/preflight.py` 生成 | 最近一次检查结果：检查时间、配置哈希、每项能力是否可用 |
| `scripts/preflight.py` | **唯一实现** | 所有环境检查仍在这里；新增 `--report` / 功能过滤 |
| `环境监测.py` | 人执行 | **薄入口**，只调用 `scripts.preflight.main()`，不复制任何检查逻辑 |
| `run.py` | 人执行 | 只读清单 + 报告；**保留网络/人设运行时探测**；不探测依赖/数据库/密钥/模型 |

> **复用原则**：不新建第二套检查代码。`环境监测.py` 是根目录的便捷入口，
> 实际实现、检查顺序、错误文案全部留在 `scripts/preflight.py`；
> 旧入口 `python3 scripts/preflight.py` 继续可用，行为一致。

### `config/features.json`（示例）

```json
{
  "schema_version": 1,
  "environment": {
    "required": true,
    "report": "data/env_report.json",
    "max_age_hours": 24,
    "network_required": true
  },
  "features": {
    "chat":     { "enabled": true, "required": true },
    "vision":   { "enabled": true },
    "voice":    { "enabled": true },
    "reading":  { "enabled": true },
    "ocr":      { "enabled": true },
    "backup":   { "enabled": true },
    "proactive":{ "enabled": true }
  }
}
```

- `required: true` 的能力不可用时，**拒绝启动**（如 `chat`）。
- 非必需能力不可用时，**标记不可用并关闭该能力**，启动继续。
- `enabled: false` 的能力不检查、不加载、不 import 重依赖。

### `data/env_report.json`（示例）

```json
{
  "schema_version": 1,
  "checked_at": "2026-11-13T11:30:00+08:00",
  "config_hash": "sha256:...",
  "ok": true,
  "checks": {
    "python": true,
    "deps": {"ok": true, "missing": []},
    "config": true,
    "db": true,
    "schema": true,
    "vision": {"ok": false, "reason": "HTTP 404，模型 ID 不存在"}
  },
  "features": {
    "chat":   { "available": true },
    "vision": { "available": false, "reason": "视觉模型不可用，已降级为纯文字" },
    "voice":  { "available": true }
  }
}
```

- 报告**原子写**（先写 `.tmp` 再 rename），权限 600。
- `config_hash` 对应 `features.json` + 连接配置；清单改了，旧报告自动失效。
- 超过 `max_age_hours` 也失效。

### `scripts/preflight.py` 的检查边界（`环境监测.py` 只转发）

- **核心必需**：Python / 必需依赖 / 配置 / 数据库连接 / v18 表结构 / 人设 / 密钥 / 网络。
- 网络与人设探测由 `botv/app/runtime_checks.py` 提供；`preflight.py` 写报告，`run.py` 启动时再快速探测一次。
- **按启用项检查**：
  - `vision`：生成测试图，真实调用视觉模型；失败 **WARN**，不阻塞，报告写“不可用”。
  - `voice`：`edge-tts` 可用性 + 一次合成试听；失败 WARN。
  - `reading` / `ocr`：Playwright / tesseract / PaddleOCR；失败 WARN。
  - `backup`：`mysqldump` / SQLite 可读；失败 WARN。
- 核心项失败 → 报告 `ok:false`，退出非 0；可选能力失败 → 退出 0，但报告标不可用。

### `run.py` 只保留必要检查

- 读 `config/features.json`；缺失或 JSON 非法 → 退出。
- 读 `data/env_report.json`；缺失 / `ok:false` / 过期 / `config_hash` 不匹配 → 拒绝启动：
  ```
  ❌ 还没有有效的环境监测报告
  先运行：python3 环境监测.py
  ```
- `required` 能力不可用 → 拒绝启动。
- 非必需能力不可用 → 日志警告，运行时不启用。
- **网络探测保留**：启动时探测模型 API / 必要外网端口；`environment.network_required=true` 时
  失败直接拒绝启动（默认 true，可显式放宽为只告警）。
- **人设探测保留**：加载角色卡 / 补充文本 / `get_system_prompt()`；失败直接拒绝启动。
- 网络/人设探测与 `preflight.py` 共用同一实现（`botv/app/runtime_checks.py`），
  不复制两套代码；`preflight.py` 仍会把结果写进 `env_report.json`。
- 单实例锁、时区锁定保留（进程级必要动作）。
- 删除 `run.py` 里的依赖扫描/自动安装、数据库检查、密钥检查、视觉/语音实测；
  **网络和人设不删**。

## v19.3 · 语音分段（2 天）

> 现在的 bug：语音只念第一句，和第一条文字重复。改成 AI 自己决定表达方式。

| 单元 | 内容 | 验收 |
|---|---|---|
| U1 | prompt 输出契约：要念的段用 `【语音】…【/语音】` 包住；文字段可选 `【文字】…【/文字】`；不加标记 = 纯文字 | AI 能输出三种模式 |
| U2 | 解析器按顺序切成 `text/voice` 段；未闭合/空段降级为文字，标记绝不外泄 | 纯文字、纯语音、混合都能解析 |
| U3 | 发送：文字段走分条（≤4 气泡），语音段走 TTS；混合时保持原顺序 | 不再出现“首句文字 + 首句语音”重复 |
| U4 | 纯语音：只发 record，不发文字气泡；TTS 失败自动把该段转文字 | 失败不静默丢内容 |
| U5 | 群聊/代码模式/超长/冷却仍走原限制；显式语音被限制时降级文字 | 边界可预期 |
| U6 | 测试：三种模式、乱序、未闭合、TTS 失败、代码模式 | 全绿 |

**标记示例**：

```text
纯文字：
今天不想说话。

纯语音：
【语音】今天好累啊，想早点睡。【/语音】

混合：
【文字】我先说结论：【/文字】
【语音】今天不去了，我想在家躺着。【/语音】
```

**降级规则**：

- 语音段为空 / TTS 返回 None → 把该段文本按普通文字发。
- 标记未闭合 → 整段按文字发，去掉残留标记。
- 代码模式 / 群聊 → 不合成语音，标记内容转文字。
- 冷却只限制“自动语音”；AI 明确标记的语音优先，但仍受最长 120 字限制。

## 与 v20 的关系

v19 的消息表默认 `user_id='__owner__'`，只服务单用户；v20 再把 `user_id` 变成真实账号并做隔离。
这样多用户改造只改“归属/过滤”，不重写消息模型。
