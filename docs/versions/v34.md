# v34 系列 · 学习规划

> 大版本 v34。次版本从 1 开始，次次版本从 1 开始，补丁从 1 开始。
> 目标：把“本周计划表”做成可导入、可执行、可顺延、可复盘的一等能力。
> 同时让机器人知道主账号当前在做什么，回复/主动消息能贴合情境。
> v34 只做 JSON/API；可视化增删在 v35 自研客户端。

## 1. 范围

### 要做

```text
一张 study_plans 表：一周一行，周一到周日 7 列
每列是 JSON 数组，每天节数可变
周计划导入/查看
任务完成/跳过/顺延
到点提醒（只提醒一次）
周复盘/统计
```

### 不做

```text
不接教务系统
不做课程表 OCR（后续可加）
不强制番茄钟
不建 plans/items/events 多表
不占 cron_tasks
```

## 2. 数据模型

```sql
CREATE TABLE study_plans (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id     VARCHAR(64) NOT NULL DEFAULT '__owner__',
    week_start  DATE NOT NULL,
    title       VARCHAR(128) NOT NULL DEFAULT '',
    monday      TEXT NULL,
    tuesday     TEXT NULL,
    wednesday   TEXT NULL,
    thursday    TEXT NULL,
    friday      TEXT NULL,
    saturday    TEXT NULL,
    sunday      TEXT NULL,
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
                ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_study_week (user_id, week_start)
);
```

情境表：

```sql
CREATE TABLE owner_presence (
    user_id     VARCHAR(64) PRIMARY KEY,
    activity    VARCHAR(32) NOT NULL DEFAULT 'unknown',
    detail      VARCHAR(200) NOT NULL DEFAULT '',
    idle_min    INT NOT NULL DEFAULT 0,
    source      VARCHAR(32) NOT NULL DEFAULT 'manual',
    updated_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
                ON UPDATE CURRENT_TIMESTAMP
);
```

`activity` 只存粗粒度：

```text
coding / meeting / video / gaming / reading / eating / away / unknown
```

不存按键、不截屏；窗口标题默认不上传，开启 `raw_title` 才存 detail。

每格 JSON：

```json
{
  "no": 1,
  "time": "09:00",
  "subject": "Linux",
  "task": "文件系统",
  "kind": "review",
  "status": "todo",
  "estimate_min": 45,
  "actual_min": 0,
  "note": "",
  "notified_at": null
}
```

规则：

```text
week_start 必须是周一
no 只是当天顺序，不要求连续
time 每天可不同
空/NULL 表示当天没安排
status: todo / done / skipped / moved
notified_at 用于去重，不另建提醒日志表
```

## 3. 命令

```text
!plan                       本周概览
!plan today                 今天
!plan week 2026-11-16       指定周
!plan import <json>         导入周计划（当前手动 JSON）
!plan export                导出 JSON
!plan add <day> <时间> <内容>
!plan done <day> <no>
!plan skip <day> <no>
!plan move <day> <no> <to_day> <to_no>
!plan export                导出
!plan stats                 本周完成率
!doing <状态>               手动设置当前情境
!doing clear                清除情境
!presence                   查看当前情境
```

## 5. 开发思路

### 5.1 当前阶段与后续客户端

```text
v34：手动 JSON / API
v35：Web 可视化编辑器
v35 桌面/手机：复用同一编辑器
```

v34 不提前写前端，避免和 v35 客户端重复；但 API/JSON 结构必须稳定。

### 5.1 单表而不是多表

- 周计划是“读多写少”的个人数据，一周一行足够。
- 不拆 items：避免 join、避免跨天移动时多表事务。
- 所有修改是“读 JSON → 改 → 写回”，用 `updated_at` 做冲突提示。
- 提醒去重也放 JSON，避免新增表。

### 5.2 当前手动 JSON

v34 没有可视化编辑器：

```text
用户/脚本生成 JSON
→ !plan import 或 POST /api/plan/import
→ 校验 → upsert
```

同时预留给 v35 客户端的 CRUD API：

```text
GET    /api/plan?week_start=...
PUT    /api/plan/{week_start}
PATCH  /api/plan/{week_start}/item
DELETE /api/plan/{week_start}/item
```

v34 不做前端；只保证 API 和数据格式稳定。

### 5.3 导入

```text
JSON 文本
→ json.loads
→ 校验 week_start 是周一
→ 校验每天数组、no 唯一、time HH:MM
→ upsert
→ 返回导入条数
```

不做 OCR；截图/表格先由用户或脚本转 JSON。

### 5.4 提醒

```text
每 60s：
  取本周 plan
  取今天
  找 todo 且 time <= now
  且 notified_at 为空
  → 发送
  → 写 notified_at
```

不在 `cron_tasks` 建几十条；避免污染钩子列表。

### 5.5 顺延

```text
move(day,no,to_day,to_no)
→ 源数组删除
→ 目标数组插入/追加
→ 保留 note="moved from ..."
```

不自动把所有未完成任务堆到第二天；由用户决定。

## 6. 主账号情境

### 数据流

```text
Windows/Linux reporter
  → 前台应用 / 空闲分钟
  → 映射粗类
  → POST /internal/presence（仅本机）
  → owner_presence
  → build prompt / proactive policy
```

### 规则

```text
手动 !doing 优先级最高
reporter 30s 一次；超过 5 分钟未更新视为 unknown
会议/离开：不主动发消息
写代码：少打扰，短句
吃饭：可以贴合“少吃点”等提醒
默认不保存窗口标题
```

### 回复注入

```text
当前情境：主人在写代码，已连续 40 分钟
→ 回复别问“在忙吗”，直接说事
```

### 主动消息

```text
meeting / away → 静默
coding → 降频/短句
eating → 可提醒
unknown → 回退原策略
```

## 7. 风险

- JSON 并发写覆盖：单主人低并发；加 updated_at 比较，冲突提示重读。
- 时区：统一 Asia/Shanghai。
- 提醒重复：notified_at 必须持久化。
- QQ 文本过长：按天分页/截断。

## 8. 总验收

```text
1. 导入一周计划，7 天可读
2. 空白天不显示
3. done/skip/move 正确
4. 到点只提醒一次
5. 重启后不重复提醒
6. 周日统计完成率
7. 不增加 cron_tasks 行
8. 主账号在开会时，主动消息静默
9. 主账号在写代码时，回复贴合情境且不打扰
10. 默认不保存窗口标题
```
