# v28 系列 · 工具层插件接口

> 前置：v23 多用户 API / v24 模型层｜预估 3 天｜**三个次版本**
> 目标：把「她能调用什么」从 `ai/tools.py` 里抽出来，
> 变成可注册的 **Tool 插件层**：manifest 声明、权限、超时、审计。
> 以后接 DSH/Qoder/WorkBuddy 的工具，或外部 MCP，只加 manifest/适配器。

## 现在的问题

| 现状 | 问题 |
|---|---|
| 工具写死在 `ai/tools.py` | 加工具要改代码、发版 |
| 没有权限模型 | 任何用户都可能触发危险工具 |
| 没有统一 schema/超时 | 模型乱传参、工具跑飞 |
| 没有审计 | 谁调了什么查不到 |

## 契约

```python
class Tool(Protocol):
    name: str
    schema: dict                       # JSON Schema
    def permissions(self) -> set[str]: # read/write/admin
        ...
    async def run(self, args: dict, ctx: ToolContext) -> ToolResult:
        ...
```

- `ToolContext`：`user_id`、`role`、`channel`、`trace_id`
- `ToolResult`：`ok`、`data`、`error`、`elapsed_ms`
- `ToolRegistry`：manifest 加载、按权限过滤、调用/超时/审计

## 次版本

| 版本 | 内容 | 天数 | 验收 |
|---|---|---|---|
| **v28.0.0** | 契约 + Registry + 假工具 | 1 | 模型只看到已注册工具 |
| **v28.0.1** | manifest（JSON）+ 内置工具（chat/remember/recall/notify） | 1 | 加工具不改 Python |
| **v28.0.2** | 权限（按 role/user）+ 超时/审计 + `!tools` | 1 | 越权拒绝；慢工具被超时 |

## 关键设计

- **manifest**：`tools/<name>/tool.json` + `handler.py`（或 HTTP 端点），注册时校验 schema。
- **权限**：`read`（查）/ `write`（记）/ `admin`（运维）三档；`user` 默认只读自己的。
- **不默认给 shell**：命令/运维工具必须显式 `admin` + 白名单，沿用 v31 的只读策略。
- **超时/重试**：每工具独立超时；写操作不自动重试。
- **审计**：`tool_calls(user_id, tool, args_digest, ok, elapsed)`；不记敏感原文。
- **多用户**：工具拿到的 `ctx.user_id` 决定数据范围；跨用户工具默认不存在。

## 验收

```bash
!tools               # 列出工具 / 权限 / 健康
!tools test recall   # 用当前用户跑一次
```

- 加一个 manifest 工具：不改 `ai/tools.py`，重启即生效。
- 普通 user 调 admin 工具：403，不执行。
- 工具超时：返回可读错误，不拖死聊天。

## 不做

- 不做任意代码执行/shell 默认开放。
- 不接外部 MCP（v29 插件层再做适配）。
- 不让工具绕过 `user_id` 直接查库。

## 风险

| 风险 | 处理 |
|---|---|
| manifest 写错导致启动失败 | 启动校验；坏工具跳过并告警 |
| 工具越权 | 默认拒绝；权限白名单；审计 |
| 模型乱传参 | JSON Schema 校验；错误回给模型 |
| 慢工具拖垮 worker | 独立超时；熔断；写操作不重试 |
