# v28 系列 · 插件运行时（审批 / 加载 / 错误 / DDL）

> 前置：v27 注册表基础。  
> 本层只做插件运行时，不实现具体 provider / channel / tool / storage。  
> 具体能力层从 **v29 模型层** 开始，每层两版：契约 + native、插件接入。

完整跨版本总纲：[INTERFACE-PLAN-v27-v44.md](../INTERFACE-PLAN-v27-v44.md)。

## 目标

```text
核心 DB pool 统一
manifest-first 加载 + 热更快照
权限三档 + 安装审核 + 命令修改
plugin_errors + 连续失败自动降级/停用
任务 / 线程池 / DB 连接池统一 context
插件 stop 跟随 worker 生命周期
插件 DDL 独立迁移
```

## 插件目录与快照

```text
plugins/
  models/
  channels/
  memory/
  tools/
  storage/
    <plugin>/
      plugin.json
      plugin.py
      migrations/
        001_init.sql
```

`prepare_worker` 负责：

```text
读注册表启用清单
→ 复制启用插件到 data/workers/versions/<version>/plugins/
→ 生成 plugin-lock.json（name/version/sha256/capabilities）
→ 新 worker 只读本版本快照
```

旧 worker 不读新插件文件；已启用插件在新 worker 启动时自动加载。

## 核心 registry 表

以下表属于**核心 schema**，不是插件表：

```text
plugin_registry      插件安装/启用状态
plugin_approvals     安装/权限审批
plugin_permissions   权限三档
plugin_errors        错误记录
plugin_schema_version 插件迁移版本
```

迁移方式：

```text
schema_version 29 → 30
scripts/migrate_v28.py
```

## 权限与审批

权限点：

```text
config.read / config.secret
db.read / db.write
file.read / file.write
network.outbound
event.read / event.emit
plugin.call
```

三档：

```text
0 = 拒绝
1 = 调用时询问主账号
2 = 直接允许
默认 = 1
```

scope 格式：

```text
config: <key>
db: <table>
file: <glob path>
network: <host suffix>
event: <kind>
plugin: <capability>
```

流程：

```text
!plugin install <path>
→ 进入 pending
→ 主账号 !plugin pending
→ !plugin approve <id> / reject <id>
→ 逐权限点询问 0/1/2
→ 写 plugin_permissions
→ 后续 !plugin permission <name> <permission> <0|1|2>
```

## 错误与自动停用

```text
plugin_errors(plugin, version, capability, phase, error, traceback, created_at)
```

阈值：

```text
5 分钟内 3 次失败 → degraded
10 分钟内 5 次失败 → disabled
disabled 时 cancel 该插件全部 tasks，调用 plugin.stop
!plugin enable <name> 手动恢复
```

traceback 脱敏，不写 token/cookie/正文。

## 任务 / 线程 / 连接池

插件工厂收到 `ctx`：

```python
ctx.tasks.spawn(name, coro, owner="plugin:...")
await ctx.pool.run_blocking(fn, timeout=...)
with ctx.db.cursor() as c: ...
ctx.on_stop(fn)  # 可选清理回调
```

- `TaskManager` 持有任务，worker 关闭/插件停用时按 owner cancel。
- 线程池复用 `infra/blocking`。
- DB 连接池统一到 `infra/pool`；插件禁止直接 `infra.conn`。

## 插件 stop 生命周期

**跟随 worker，不跟随 ingress。**

触发：

```text
worker SIGTERM / drain
插件 disable / 自动 disabled
插件版本升级（旧 worker 退出）
```

顺序：

```text
停止接新调用
→ TaskManager.cancel(owner="plugin:...")
→ plugin.stop(ctx)，最多 5 秒
→ 关闭插件游标/连接
→ registry.unregister(plugin)
→ 写一条 lifecycle 日志
```

stop 超时/失败只记录，不阻塞核心退出；ingress 重启不触发插件 stop。

## DDL

```text
plugins/<layer>/<name>/migrations/001_init.sql
```

规则：

```text
只支持 MySQL + SQLite
表前缀 plugin_<name>_
不允许改核心表
启动不建表
!plugin migrate <name> 先 dry-run，主账号确认后执行
每个 migration 在事务内执行，失败回滚
记录 plugin_schema_version
```

## 次版本

| 版本 | 内容 | 验收 |
|---|---|---|
| **v28.0** | 核心 repo_* 统一切到 `infra/pool`；conn 仅兼容 | 现有 DB 行为不变；SQLite/MySQL 都过 |
| **v28.1** | 权限三档 + 审批表 + install/pending/approve/reject/permission 命令 | 默认 ask；0/1/2 可改 |
| **v28.2** | manifest-first loader + prepare_worker 快照 + 自动加载 | 坏插件不影响核心；旧 worker 不读新文件 |
| **v28.3** | plugin_errors + degraded/disabled + 自动停用 | 故障可查；停用生效 |
| **v28.4** | TaskManager + ctx.db/ctx.pool + plugin.stop 生命周期 | 插件不裸 create_task/裸连库；stop 跟随 worker |
| **v28.5** | 核心 registry 表迁移 + 插件 migrations + `!plugin migrate` | 只建插件表；dry-run/回滚可用 |
