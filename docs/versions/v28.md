## 核心 registry 表

```text
plugin_registry        插件安装/启用/auto_start/hash/author/layer
plugin_approvals       安装/权限审批
plugin_permissions     权限三档 + scope
plugin_errors          错误记录
plugin_schema_version  插件迁移版本（v38 使用）
plugin_registry_generation 当前 generation
```

迁移：

```text
schema_version 29 → 30
scripts/migrate_v28.py
```

## 安装与 hash

```text
!plugin install <package>
→ manifest: name/author/layer/version/api_version/capabilities
→ 计算包 hash
→ 复制到 plugins/<layer>/<name>/
→ 同名 hash 相同：重复安装；hash 不同：拒绝
→ 进入 pending
```

包文件名不参与身份判断：插件身份 = manifest `name`，hash 只做完整性和同名覆盖判断。
同 name 同 hash 视为重复安装；同 name 不同 hash 拒绝覆盖。
layer 只能是 `models/channels/memory/tools/storage`。

## 权限

```text
0 拒绝 / 1 调用时询问 / 2 直接允许，默认 1
scope: config:key / db:table / file:glob / network:host / event:kind / plugin:capability
```

任何越权表、越界路径、未授权 host 直接抛 `PermissionDenied`，不执行副作用。

## PluginContext

完整接口见 [PLUGIN-RUNTIME-DESIGN.md](../PLUGIN-RUNTIME-DESIGN.md)：

```text
ctx.manifest / registry / config / db / files / network / events
ctx.ai / memory / storage / tasks / pool / logger / permissions / lifecycle
ctx.on_stop(fn)
```

插件禁止裸 `create_task`、裸连 DB、裸 requests。

## 生命周期

```text
worker SIGTERM / drain
插件 disable / 自动 disabled
版本升级旧 worker 退出

→ 停止接新调用
→ cancel owner tasks
→ plugin.stop(ctx)，最多 5s
→ 关闭游标/连接
→ registry.unregister
→ generation +1
```

不跟随 ingress；运行中 disable 立即 stop，下一次 worker 不再加载。
自动停用不自动恢复；`auto_start=true` 且 enabled 的插件在 worker 启动时加载。

## 卸载

`uninstall(ctx)` 只是开发者接口，**核心不自动调用**。

`!plugin uninstall <name>` 只做：

```text
停止插件（plugin.stop）
移除插件文件
移除注册表记录
```

不 drop 表、不执行开发者清理逻辑；插件数据由开发者自行维护删除。

## v28.7 · 自然语言提醒交互回归

> 触发：用户说「提醒我明天早上八点复习linux」后，机器人回：
> `好，2026-11-16 08:00 提醒你...（#12，不想要就说 !cron del 12）`
> 又补一条 `标准命令：!cron once ...`。
> 这不是人设/语境回复，是把内部命令直接甩给用户。

规则：

```text
自然语言提醒成功
→ 用人设确认：时间 + 事情 + 到点提醒
→ 不附 !cron 标准命令
→ 不附 task_id / 删除命令
→ task_id 只写日志

时间没解析
→ 自然语气问清楚
→ 不教命令语法

未知命令 / 拼写错误
→ 写日志（原文、uid、时间）
→ 不给“你是不是想用 !cron”提示
→ 用角色语气说没看懂，或静默
```

验收：

```text
「提醒我明天早上八点复习linux」
→ 好，明早八点提醒你复习 Linux。到点叫你。

「! corn」
→ 日志有 unknown command: corn
→ 回复不出现 “你是不是想用 !cron”
```

## v28.8 · cron 对账清理

### 触发场景

```text
08:00 的一次性任务
→ 08:00 时 worker 不在/钩子丢失
→ 08:38 仍然显示 ✅，next=08:00（已经过去）
→ 04:00 对账只 set_enabled(False)，变成 ⏸️，不会删除
```

### 规则

```text
schedule_all()（启动 / 04:00）
→ 只处理 enabled 的 once 任务
→ once_at <= now
→ 不补发、不通知
→ 直接 cron.remove()
→ 日志：[定时] 过期一次性任务已删除 #<id> <once_at> <content>
```

- 不再把过期 once 改成停用后留在列表里。
- 删除只针对 `schedule_type=once` 且 `once_at <= now`。
- 未来时间的一次性任务、daily/weekly/rule 任务不动。
- 删除失败退回 `set_enabled(False)` 并记错误日志。

### 重复任务

同一 `user_id + target_id + schedule_type + at_time/weekdays/once_at + content`
存在多条 enabled 时：

```text
只告警，不自动删
日志：[定时] 重复任务 #5/#9 内容相同，保留 #5，建议 !cron del 9
```

原因：重复可能是用户故意留的；自动删会误伤。

### 验收

```text
1. 造一条 once_at 已过期的 enabled 任务
2. 重启 worker / 触发 04:00 对账
3. 任务从 cron_tasks 删除
4. !cron 不再显示
5. 日志有“过期一次性任务已删除”
6. 重复任务不自动删，只告警
```
