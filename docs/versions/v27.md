# v27 系列 · 插件接口实现（含 v27.0 代码审查与重构）

> 核心：实现第三方插件接入所需的接口和注册表。
> **本层不实现任何功能**：只定义契约和注册表，不提供任何实现；具体 provider / channel / tool / storage 由核心或第三方开发者实现。
> 现有功能仍是核心 native；没有插件时核心默认链路照常工作。
> 欢迎其他开发者按契约提交实现。
>
> 完整跨版本约束见 [INTERFACE-PLAN-v27-v35.md](../INTERFACE-PLAN-v27-v35.md)。

```python
class PluginManifest(Protocol):
    name: str
    version: str
    api_version: int
    requires_core: str
    capabilities: set[str]
    entrypoint: str
    priority: int


class PluginRegistry(Protocol):
    def register(self, manifest: PluginManifest, factory) -> None: ...
    def get(self, capability: str, name: str): ...
    def list(self) -> list[PluginManifest]: ...
```

## 已确认设计（2026-11-15）

- 6 个注册表：命令、事件、生活、AI、插件、注册表管理器；第 6 个是静态的注册表管理器。
- 插件层目录：`models/`、`channels/`、`memory/`、`tools/`、`storage/`。
- 插件启用状态在注册表，不在 `features.json`；`features.json` 只管核心内置开关。
- 敏感权限默认“调用时询问”；安装时审核一次，之后用命令改 0/1/2 三档。
- 插件热更跟 worker 版本快照走；已启用插件新 worker 自动加载。
- 插件故障写 `plugin_errors`，连续失败自动停用。
- 任务、线程池、DB 连接池由插件 context 统一提供。
- 插件可带 `migrations/`，只支持 MySQL/SQLite；`!plugin migrate` dry-run 后主账号确认。

## v27.0 · 代码审查与架构重构（优化升级）

> 先审后改，不改行为；先跑基线，再重构；一个主题一个提交，方便回滚。
> 这一版不实现插件、不接第三方 adapter，只把底座收拾干净。

### 审查清单

| 方向 | 看什么 |
|---|---|
| 模块边界 | `bot/`、`server/`、`gateway/` 的依赖方向是否单向 |
| 循环依赖 | 模块级 import 环、函数内 import 是否遮住环 |
| 入口收敛 | `app/bootstrap`、`server/http_api`、`gateway/router` 是否职责过多 |
| 异常与日志 | 裸 `except`、异常吞掉、日志泄漏 token/cookie |
| 阻塞调用 | 浏览器/OCR/DB/网络是否都走线程池或异步 |
| 数据库 | N+1、重复查询、缺索引、事务边界 |
| 配置 | 环境变量/配置文件/默认值是否分散、是否可回滚 |
| 死代码 | 未使用函数、重复实现、旧版兼容分支 |
| 测试 | 关键路径是否有回归；测试是否依赖真实网络 |
| 依赖与安全 | 过期依赖、已知漏洞、许可证、未使用依赖 |

### 重构范围

```text
1. 收敛入口：启动、HTTP、网关、命令注册
2. 明确 ports/adapters 边界：先画依赖，不搬业务
3. 统一配置读取与默认值
4. 统一错误映射与日志字段
5. 去掉明显重复/死代码
6. 性能优化：启动、查询、缓存、阻塞调用
7. 依赖升级单独提交，不和重构混在一起
```

### 优化目标


## 插件目录与加载

```text
plugins/<layer>/<name>/plugin.json
plugins/<layer>/<name>/plugin.py
plugins/<layer>/<name>/migrations/
```

`prepare_worker` 把启用插件快照进 `data/workers/versions/<version>/plugins/`；worker 启动时只读本版本快照。

## 权限 / 审批

```text
config.read / config.secret
db.read / db.write
file.read / file.write
network.outbound
event.read / event.emit
plugin.call
```

```text
0 = 拒绝
1 = 调用时询问主账号
2 = 直接允许
默认 = 1
```

安装时主账号审核一次，写入 `plugin_permissions`；后续：

```text
!plugin permission <name> <permission> <0|1|2>
```

## 错误 / 自动停用

```text
plugin_errors(plugin, version, capability, phase, error, traceback,
              created_at)
```

连续失败达到阈值自动停用；主账号可：

```text
!plugin errors
!plugin disable <name>
!plugin enable <name>
```

## 插件 DDL

```text
plugins/<layer>/<name>/migrations/001_init.sql
```

```text
只支持 MySQL / SQLite
表前缀 plugin_<name>_
不允许改核心表
启动不建表
!plugin migrate <name> 先 dry-run，确认后执行
记录 plugin_schema_version
```

## 任务 / 线程 / 连接池

插件工厂收到 `ctx`：

```python
ctx.tasks.spawn(name, coro, owner="plugin:...")
await ctx.pool.run_blocking(fn, timeout=...)
with ctx.db.cursor() as c: ...
```

任务由 TaskManager 持有，worker 关闭统一 cancel；线程池复用 `infra/blocking`；连接池复用统一 DB pool。

## 关键约束

- 核心实现不实现 `PluginManifest`，不进入 `PluginRegistry`。
- `get()` 找不到插件时返回 `None`，由调用方走核心。
- 插件注册失败只记录，不阻塞启动。
- 核心功能只能通过启动前 `config/features.json` / `NAO_FEATURES` 关闭。
