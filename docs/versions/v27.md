# v27 系列 · 通道层接口实现

> 核心：把 QQ / NapCat 包成 `Channel` 实现，并暴露第三方通道接口。
> QQ / NapCat 是核心 native，不注册为插件。

```python
class Channel(Protocol):
    name: str
    async def start(self) -> None: ...
    async def stop(self) -> None: ...
    async def send(self, target: str, text: str) -> bool: ...
    def on_message(self, handler) -> None: ...
```

## 实现步骤

| 次版本 | 内容 | 验收 |
|---|---|---|
| **v27.0** | `Channel` / `Inbound` 契约 | 业务只依赖接口 |
| **v27.1** | `QQChannel` native adapter，包现有 NapCat 收发 | QQ 行为不变 |
| **v27.2** | 入站解析 adapter 化，现有私聊/群聊走同一接口 | 现有消息不丢 |
| **v27.3** | 第三方通道 adapter 接入点 + fake channel 测试 | 新通道不改业务 |

## 关键约束

- QQ / NapCat 是核心 native，不注册为插件。
- 第三方通道只新增入口，不接管 QQ。
- 第三方通道失败由 v32 回退 QQ。
- 核心通道只能启动前通过 `features.json` / `NAO_FEATURES` 关闭。
