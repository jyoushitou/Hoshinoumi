## 目标

```text
第 1：命令注册表        bot/cmd/registry.py
第 2：事件注册表        bot/events/registry.py
第 3：生活能力端口      bot/core/lifeport.py
第 4：AI 文本端口       bot/core/ai_port.py
第 5：插件注册表        bot/registry/plugins.py
第 6：注册表管理器      bot/registry/master.py
```

第 6 个是**静态的注册表管理器**：启动时登记 5 个注册表，不支持运行时动态新增。

固定初始化顺序：

```text
command → events → life → ai → plugin（最后）
```

插件注册表最后初始化，避免看到半空的核心注册表。前 4 个保留现有实现，由 master 做 adapter，不重写。

## v27.2 · Manifest / Capability

```python
class PluginManifest(Protocol):
    name: str
    author: str
    layer: str          # models/channels/memory/tools/storage
    version: str
    api_version: int
    requires_core: str
    capabilities: set[str]
    entrypoint: str
    auto_start: bool
    priority: int
```

能力名：

```text
model.<name>@1
memory.store.<name>@1
memory.retriever.<name>@1
channel.<name>@1
tool.<name>@1
storage.backend.<name>@1
storage.repository.<name>@1
scheduler.<name>@1
schedule.trigger.<name>@1
transport.<name>@1
route.<layer>.<name>@1
```

冲突规则：

```text
name 重复 → 拒绝
同一 capability 同 priority 多个 → 拒绝并列出
version 不满足 requires_core → 拒绝
capability 格式非法 → 拒绝
capability 要求 @2 但核心只有 @1 → 抛 PluginLoadError，拒绝加载
```

## v27.5 修复：延迟日记自检导致 10 分钟后进程退出

- 根因：v27.0 删除 `bot/db.py`，但 `run.py` 的 `check_diary()` 仍 `from bot.db import get_cursor`。
- 600 秒后触发导入失败；`except` 中又引用尚未 import 的 `log_system`，二次异常逃出，取消 main_task，进程退出。
- 修复：改用 `bot.infra.conn.get_cursor`；`get_cursor/MASTER_QQ/log_system` 在 `try` 之前导入。
- 回归：禁止 `from bot.db`；直接调用 `check_diary()` 不崩。

## v27.6 修复：心跳任务拿到的永远是 None

- `heartbeat_monitor("QQ", cfg.active_ws_qq)` 在启动时传入 None，之后不会更新。
- 改为 `heartbeat_monitor("QQ", lambda: cfg.active_ws_qq)`。
- `heartbeat_monitor` 兼容 callable/对象；每轮重新读取连接。
- 回归：callable 先 None 后连接、旧对象入参两条。

## v27.7 修复：上线提醒每进程只发一次

- 原来 `claim_online_notice()` 用 60 秒冷却；心跳重连超过 60 秒会再次弹“上线了”。
- 改为 `cfg.online_notice_sent`：每个 worker 进程只发一次。
- 同进程重连只记日志，不再发上线通知；新进程/热更新仍发一次。

## v27.8 修复：worker 日志写到根 logs

- `prepare_worker` 的 `SKIP` 含 `logs`，`SHARE` 不含 `logs`，导致 worker 在版本目录下新建 `logs/`。
- 根 `logs/` 看不到热更后的日志。
- 修复：`SHARE` 加入 `logs`，并在 prepare 时创建根 `logs/`；版本目录软链回根目录。
- `worker.log`（stdout）仍在版本目录，这是 supervisor 的重定向目标。
