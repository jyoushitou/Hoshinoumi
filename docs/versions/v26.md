# v26 系列 · 运维通道（二）agent

> 前置：v19（bash 只读）｜预估 3 天｜**风险第二高，默认关闭**

## 目标

你说一句「怎么又挂了」，她**自己去看**：查进程、看日志、看内存，然后告诉你结论。

```
你：!agent 2468
她：🤖 Agent 模式（只读运维）
    你说问题，我自己去查。10 分钟无操作自动退出。

你：机器人好像不回消息了
她：（查进程）→（看日志）→（看内存）
    进程还在，但日志里 12:03 开始一直报数据库连接超时，
    内存用了 92%，可能是 MySQL 那边的问题。
```

和 v26.0 的区别：

| | v26.0 bash 模式 | v21 agent 模式 |
|---|---|---|
| 谁决定查什么 | **你**（关键词匹配） | **她**（模型规划） |
| 执行几轮 | 1 轮 | 最多 5 轮 |
| 输出 | 命令原文 | 结论 + 依据 |
| 风险 | 中 | **中高**（模型可能乱查） |

## 核心设计：她只能调工具，不能写命令

**关键约束**：模型不生成 shell，只生成**工具调用**。

```json
{"tool": "log", "args": {"file": "/app/bot.log", "n": 50}}
```

代码侧：
1. 查白名单 → 得到 argv
2. 参数校验（`shell=False`）
3. 执行、截断输出
4. 把结果喂回模型
5. 最多 5 轮，然后必须给结论

**模型永远碰不到 shell**（和 v26.0 共用同一个执行器）。

## 模式进出

| 项 | 规则 |
|---|---|
| 进入 | `!agent <鉴权码>`（和 `bash_key` 共用，或单独的 `agent_key`） |
| 退出 | `!agent off` |
| 自动退出 | 10 分钟无操作 |
| 群里 | **禁止**，只允许私聊 |
| 与 bash 模式 | **互斥**：进入 agent 自动退出 bash，反之亦然 |
| 未配置 key | 永远进不去 |

## 鉴权（和 bash 模式同一套机制）

两个模式都要鉴权，**共用同一套逻辑**，只是计数分开。

| 项 | 规则 |
|---|---|
| 鉴权码来源 | `config.local.json` 的 `agent_key`（独立），没配就退回 `bash_key` |
| 都没配 | **永远进不去**（不是默认放开） |
| 校验方式 | 常数时间比较（`hmac.compare_digest`），防时序侧信道 |
| 失败处理 | 拒绝 + 计数；**连续 3 次失败锁 10 分钟** |
| 锁定期内 | 不再校验、不再响应，只回一句「已锁定」 |
| 成功进入 | 清零失败计数 |
| 群里 | **禁止进入**，只接受私聊 |
| 审计 | 进入成功/失败都记 `events(kind='ops')`，含 QQ 号、时间、结果 |

### 和 bash 模式的互斥

```
!agent 2468  → 退出 bash（如果在），进入 agent
!bash 2468   → 退出 agent（如果在），进入 bash
```

两个模式**不能同时存在**——避免「以为在 bash，其实 agent 拿着工具在跑」。

### 进入时的会话

每次进入生成一个 `session_id`：

```
session_id = f"{qq}-{int(time.time())}-{random4}"
```

作用：

- 审计里能串起「这次会话都干了什么」
- 超时退出时按 session 收尾
- 错误信息里带上 session，方便排查

### 鉴权失败的样子

```
你：!agent 0000
她：❌ 鉴权失败（还可尝试 2 次）

你：!agent 0000
她：❌ 鉴权失败（还可尝试 1 次）

你：!agent 0000
她：🔒 已锁定 10 分钟（连续 3 次失败）
```

**锁定期间任何口令都不再校验**——防止用锁定当探测器穷举。

### 进入时必贴：免责声明 + 实现逻辑

```
⚠️ Agent 模式（只读运维）

【免责声明】
本模式下模型会自己决定查什么，并以机器人进程的权限
在你的服务器上执行命令。
虽然只开放只读白名单、不走 shell、有轮数限制，
但仍可能因模型误判导致查询方向错误或信息泄露。
继续使用即表示你理解并自行承担风险。

【实现逻辑】
1. 模型只能从只读白名单里选工具，**不能写命令**
2. 最多 5 轮工具调用；单轮输出截断 1500 字；总超时 60 秒
3. 不经过 shell（shell=False），注入无效
4. 只读：没有重启/删除/安装类工具
5. 每一轮工具调用都写审计日志（带 session_id）
6. 结论必须引用工具输出，查不清就说查不清
7. 10 分钟无操作自动退出；!agent off 手动退出

已进入。说说哪里不对，我自己去查。
```

| 规则 | 说明 |
|---|---|
| 每次进入都贴 | 和 bash 模式一致 |
| 明确「模型决定」 | 让用户知道不是关键词匹配 |
| 明确「最多 5 轮」 | 预期管理 |
| 明确「查不清就说查不清」 | 降低幻觉被当成事实的概率 |

## Agent 循环

```
用户的话
   ↓
[模型] 决定调用哪个工具（或直接回答）
   ↓ 有工具调用
[执行器] 白名单 → argv → 执行 → 截断
   ↓
[模型] 看结果，决定下一步（最多 5 轮）
   ↓ 没工具调用 / 轮数用完
给出结论
```

| 限制 | 值 | 原因 |
|---|---|---|
| 最大轮数 | 5 | 防止无限查 |
| 单轮输出预算 | 1500 字 | 防止撑爆上下文 |
| 总耗时 | 60 秒 | 防止卡住 |
| 总输出预算 | 6000 字 | 控制 token |

## 提示词要点（写死）

```
你是运维助手。你只能通过提供的工具查看服务器状态。
规则：
1. 不要编造命令或输出。看到什么说什么。
2. 每次只调用一个工具，等结果再决定下一步。
3. 不能做任何修改操作（重启/删除/安装）——你没有这些工具。
4. 最多 5 步。查不清就直说「查不出来，可能需要 SSH」。
5. 结论里要说明依据（哪个命令的输出）。
```

## 安全

| 措施 | 说明 |
|---|---|
| 只读白名单 | 复用 v26.0 的 `COMMANDS`，没有写操作 |
| 不生成 shell | 模型只输出工具名 + 参数 |
| 轮数/时间/输出三重上限 | 防跑飞 |
| 审计 | 每一轮工具调用都记 `events(kind='ops')`，带 `session_id` |
| 失败即停 | 工具连续失败 2 次 → 终止并报告 |
| 与 bash 互斥 | 避免状态混乱 |

## 涉及文件

- 新建 `botv/ops/agent.py`：循环、工具协议、预算控制
- 复用 `botv/ops/whitelist.py`（v26.0 建）：命令表 + 参数校验 + 执行
- 改 `botv/core/state.py`：`AGENT_MODE`、会话 id、轮数计数
- 改 `botv/cmd/admin.py`：`!agent` 进出（对照 `!code` 的写法）
- 改 `botv/ai/client.py`：agent 模式走独立 prompt，不走人设

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `agent_key` | 空（回退 bash_key） | agent 模式专用鉴权码 |
| `agent_fail_limit` | 3 | 连续鉴权失败上限 |
| `agent_lock_min` | 10 | 锁定时长（分钟） |
| `agent_idle_min` | 10 | 无操作自动退出 |
| `agent_max_rounds` | 5 | 最大工具调用轮数 |
| `agent_timeout` | 60 | 单次任务总超时（秒） |

## 验收

- [ ] `!agent <码>` 能进入，错码进不去，3 次锁 10 分钟
- [ ] 「看下为什么没回消息」→ 她**连续调用 2~3 个工具**再给结论
- [ ] 结论里引用具体输出（不是编的）
- [ ] 尝试「帮我重启」→ 她回答「我没有修改权限」
- [ ] 工具连续失败 2 次 → 自动终止并说明
- [ ] 5 轮用完还没结论 → 说明「查不出来了」
- [ ] 群里发 `!agent` 被拒绝
- [ ] 锁定期间任何口令都不再校验（不能穷举）
- [ ] 进入/失败都有审计记录
- [ ] 进入 agent 会自动退出 bash（互斥）
- [ ] 每条工具调用都有审计记录

## 风险

| 风险 | 处理 |
|---|---|
| 模型编造输出 | 提示词禁止 + 结论必须引用工具结果 |
| 无限查询 | 5 轮硬上限 |
| 上下文爆炸 | 每轮输出 1500 字截断 + 总预算 6000 |
| 被诱导做写操作 | **根本没有写工具** |
| 和 bash 模式状态冲突 | 互斥，进入一个自动退出另一个 |
| 卡住不返回 | 60 秒总超时 |
