# v26 系列 · 记忆层插件接口

> 前置：v23 多用户 API / v24 模型层｜预估 3 天｜**三个次版本**
> 目标：把「怎么存、怎么召回、怎么重排」从 `memory/` 里抽出来，
> 变成可注册的 **MemoryStore / Retriever / EmbeddingProvider** 插件层。
> 默认仍是现在的 BM25；以后加向量库/外部记忆服务只加适配器。

## 现在的问题

| 现状 | 问题 |
|---|---|
| `memory/retrieval.py` 写死 BM25 + jieba | 换向量/混合检索要改核心 |
| `infra/repo_memory` 直接写 SQL | 换存储要动业务 |
| 召回/重排/预算混在一起 | 无法按层替换 |
| 多用户刚加 `user_id` | 插件必须强制带 namespace |

> 插件原则沿用 v25：BM25 是**核心实现，不是插件**，不注册到插件表；
> 插件只能 extend / enhance / 显式 replace，卸载或失败自动回退核心。

## 契约

```python
class MemoryStore(Protocol):
    async def add(self, user_id: str, item: MemoryItem) -> str: ...
    async def search(self, user_id: str, query: str, top_k: int) -> list[MemoryHit]: ...

class EmbeddingProvider(Protocol):
    async def embed(self, texts: list[str]) -> list[list[float]]: ...

class Reranker(Protocol):
    async def rerank(self, query: str, hits: list[MemoryHit]) -> list[MemoryHit]: ...
```

- `MemoryItem`：`summary`、`tags`、`weight`、`kind`、`created_at`
- `MemoryHit`：`item`、`score`、`source`（bm25/vector/rerank）
- 所有方法**必带 `user_id`**，没有默认 owner

## 关键设计

- **默认不引入外部向量库**：BM25 适配器就是现在的实现；向量是可选插件。
- **降级**：向量/rerank 不可用 → 自动退回 BM25，不阻塞聊天。
- **namespace**：`user_id` 必填；群聊用 `user_id` + `speaker_id` 过滤事实。
- **预算**：沿用 `memory/inject.py` 的分层预算，插件只负责召回，不拼 prompt。
- **可观测**：每次召回记 source / top_k / 耗时 / 是否降级；`!memory` 看统计。
- **迁移**：现有 `memories` 表不动；适配器包一层，不双写。

## 验收

```bash
!memory stats        # 各 source 命中/耗时/降级
!memory search 早八  # 看召回与重排
```

- 加一个假 embedding：只注册，不改 `memory/context.py`。
- 向量服务挂掉：自动 BM25，聊天不报错。
- A 的检索结果里不出现 B 的记忆。

## 不做

- 不强制上向量库/Redis；默认 BM25 就够。
- 不把记忆写入路径改成异步消息（仍同步入库）。
- 不做跨用户共享记忆（除非显式 public 标记）。

## 风险

| 风险 | 处理 |
|---|---|
| 向量维度/模型变更 | embedding 版本号 + 重建索引脚本 |
| 混合检索变慢 | 每层超时；总预算；降级 BM25 |
| namespace 漏传 | 端口层断言；单测覆盖 A/B |
| 召回质量下降 | 保留旧 BM25 开关；A/B 对比 |
