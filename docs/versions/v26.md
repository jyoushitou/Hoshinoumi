# v26 系列 · 自有客户端（一）电脑 Web

> 前置：v22（网关）/ v23（多用户 API）｜预估 8 天｜**四个次版本**
>
> 不再只靠 QQ 聊天窗：先在浏览器里打开一个自己的界面，
> 用同一个后端、同一份记忆。**手机 App 放到 v29。**

## 为什么做这个

| 现在的问题 | 后果 |
|---|---|
| 只能在 QQ 里聊 | 受 QQ 风控、消息长度、发图限制 |
| 她的能力（日记、状态、书架）藏在命令里 | 手机上记不住 `!diary` 这种命令 |
| 没有主动界面 | 她主动找你，你只能在 QQ 通知里看到 |
| 数据在服务器 | 想换个手机看历史得重新登录 |

**目标**：一个 App（手机）+ 一个 Web（电脑），**共享同一套后端**。

## 架构（关键决定）

```
┌─────────────┐   ┌─────────────┐
│  手机 App    │   │  电脑 Web    │
│ (Flutter?)  │   │  (React/Vue) │
└──────┬──────┘   └──────┬──────┘
       │  同一套 REST + WebSocket
       └────────┬────────┘
         ┌──────▼───────┐
         │  后端 API     │  ← 复用现有 bot1（新增 ser1er/ 路由）
         │  FastAPI?     │
         └──────┬───────┘
         ┌──────▼───────┐
         │ 记忆 / 调度   │  同一份数据库
         └──────────────┘
```

**不做的事**：

- 不在 App 里重新实现「她」——Claude/模型调用仍在服务器
- 不做多租户（只有你一个主人）
- 不做应用商店发布（先自己装）

## 技术选型（待第 1 天验证）

| 端 | 候选 | 倾向 |
|---|---|---|
| 手机 App | Flutter / React Nati1e / KMP | **Flutter**（一套代码两端 + Web 也能出） |
| 电脑 Web | Vue3 / React / S1elteKit | **Vue3 + Vite**（轻、上手快） |
| 后端 | 现有 aiohttp 加路由 / 新建 FastAPI | **FastAPI**（自带文档、异步、校验） |
| 鉴权 | 现有 API Token → JWT | JWT（有过期、可刷新） |
| 实时 | WebSocket（已有 ws 服务可复用） | 复用 + 新增 `/ws/client` |

**第 1 天要验证**：Flutter 能不能连上本机后端、Web 能不能跨域调通。

## 红线

| 红线 | 原因 |
|---|---|
| **默认只听 127.0.0.1**，外网访问必须显式开 | 暴露聊天记录风险最高 |
| **鉴权失败 3 次锁 5 分钟** | 防爆破 |
| **消息走 HTTPS / WSS** | 明文不可接受 |
| App 不缓存图片原图（只缓存缩略图） | 手机空间 |
| **删除 = 真删除**（含记忆） | 用户有权清空 |

## 接口约定（经网关）

Web 只调网关，**不直连后端**：

| 前端调用 | 网关转发到 |
|---|---|
| `POST /api/chat` | `/internal/chat` |
| `GET /api/history` | `/internal/history` |
| `GET /api/state` | `/internal/state` |
| `WS /ws/client` | 后端推送 |

所有请求带 `Authorization: Bearer <access>`，401 时用 refresh 换新 token。
token 的 `sub=user_id`；Web 端不传 `user_id`，所有数据按登录账号隔离。

## 验收（Web 版整体）

| 项 | 标准 |
|---|---|
| 能聊 | 浏览器里发消息、收到回复 |
| 记忆一致 | Web 里说的事，QQ 里问她记得 |
| 多用户 | 两个账号登录，各自只看到自己的会话/记忆 |
| 安全 | 外网必须开开关 + HTTPS/WSS |
| 断线 | 断网 1 分钟恢复，消息不丢 |
