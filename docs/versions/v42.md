# v42 系列 · 手机 App 独立模式

> 前置：v41 手机 App｜预估 4 天｜**四个次版本**
>
> 定位：手机 App 默认仍连后端；**只有连不上后端时**，才切换到直连模型。
> 这是降级模式，不是替代后端，也不改变其他前端的协议。
>
> **后端恢复的第一刻立即同步离线数据**，不是丢弃，也不是等用户手动操作。

## 原则

```text
默认：App -> 后端 -> 模型 / 记忆 / 状态
降级：App -> DeepSeek（仅当后端不可达）
恢复：立即把离线对话同步回后端，再回到正常模式
```

- 后端可达时，绝不直连模型。
- 直连只使用与其它前端相同的消息结构，不另造一套协议。
- 直连不写后端记忆，不冒充完整功能；数据先写本地 outbox。
- 用户必须显式同意“离线直连”，并自己提供 API Key。
- 后端恢复后立即同步；同步完成前显示“正在同步”，不静默丢弃。
- 同步本身幂等：重试不产生重复记忆。

## 触发条件

满足全部条件才进入直连：

1. 后端健康检查连续失败 3 次，或单次超时 ≥ 5 秒；
2. 本地已配置 DeepSeek API Key（安全存储）；
3. 用户在设置里允许“后端不可用时直连”；
4. 当前网络可访问模型 API。

界面上必须显示：

```text
离线模式：后端不可达，当前直连 DeepSeek
```

## 能力边界

| 能力 | 后端模式 | 直连模式 |
|---|---|---|
| 聊天 | ✅ | ✅ 基础对话 |
| 长期记忆 | ✅ | ❌ 只用本地最近 N 条 |
| 关系/生活状态 | ✅ | ❌ |
| 定时/主动消息 | ✅ | ❌ |
| QQ 通道 | ✅ | ❌ |
| 多端同步 | ✅ | 恢复后立即补同步 |
| Token 统计 | ✅ | 本地显示本次估算 |

## 接口

请求体与其它前端保持一致：

```json
{
  "message": "在吗",
  "target_id": "__owner__",
  "client": "mobile-offline"
}
```

直连时只把同一份 `messages` 发给 DeepSeek：

```text
system: 本地缓存的人设快照
user:   本地最近 N 条对话 + 当前消息
```

不发送数据库里的隐私字段，不上传本地记忆。

## 离线 outbox

直连模式下的每轮对话立刻写入本地 outbox，带稳定 id：

```json
{
  "client_msg_id": "uuid",
  "target_id": "__owner__",
  "role": "user",
  "content": "在吗",
  "created_at": "2026-11-13T22:00:00+08:00"
}
```

assistant 回复也写一条，`reply_to=client_msg_id`。  
outbox 是同步的唯一来源，不依赖内存队列。

## 恢复后的立即同步

后端健康检查第一次成功时：

```text
1. 进入 SYNCING 状态，停止直连
2. 立刻 flush outbox（不等待用户操作）
3. 按 created_at + client_msg_id 排序分批上传
4. 后端按 client_msg_id 幂等去重
5. ack 后删除本地已同步项
6. 全部 ack 后进入 ONLINE，恢复后端模式
```

同步接口：

```http
POST /internal/mobile/sync
Content-Type: application/json

{
  "client_id": "device-uuid",
  "target_id": "__owner__",
  "messages": [
    {"client_msg_id": "uuid", "role": "user", "content": "在吗",
     "created_at": "..."},
    {"client_msg_id": "uuid", "role": "assistant", "content": "在。",
     "created_at": "...", "reply_to": "上一条 uuid"}
  ]
}
```

规则：

- 同步中不允许新的离线直连；新消息先入 outbox。
- 同步失败保留 outbox，退避重试；不丢数据。
- 同步只传对话内容，不传 API Key、不传设备密钥。
- 后端已有更新的消息时以服务端为准，不覆盖；只追加缺失项。
- 同步完成前显示“正在同步”；完成后才隐藏离线横幅。

## 离线记账（v41.3 联动）

记账写入也走 outbox，类型分开，不要混进对话：

```json
{
  "type": "ledger",
  "client_id": "uuid",
  "amount": "25.00",
  "currency": "CNY",
  "category": "餐饮",
  "note": "午饭",
  "occurred_at": "2026-11-14T12:30:00+08:00"
}
```

- 后端恢复后先 flush 对话，再 flush 账目；两者都按 `client_id` 幂等。
- 同步接口增加 `ledger` 数组；不接受客户端指定别人的 `user_id`。
- 金额用字符串传，避免浮点误差；后端转 `DECIMAL(12,2)`。
- 同步失败保留本地账目，不重复扣款/重复记账。
- 离线只允许新增账目；编辑/删除需联网，避免冲突合并。

## 次版本

| 版本 | 内容 | 验收 |
|---|---|---|
| **v42.0** | 后端连通性探测 + 3 次失败/5s 超时触发降级 + 离线横幅 | 后端挂了才进离线 |
| **v42.1** | DeepSeek 直连客户端 + API Key 安全存储 + 用户开关 | 没 Key 不静默失败 |
| **v42.2** | 本地 outbox + 人设快照 + 最近 N 条 + token 估算 + 离线账目 | 离线对话/账目可恢复、可同步 |
| **v42.3** | 恢复即同步：flush/ack/幂等/重试/切回 | 后端恢复第一刻开始同步 |

## 验收

```text
1. 后端正常：所有请求只走后端，直连客户端零调用
2. 后端关闭：3 次失败后提示离线模式，可直连回复
3. 无 API Key：提示配置，不自动切直连
4. 后端恢复：第一刻进入 SYNCING，立即上传 outbox
5. 同步完成：后端 conversation_messages 有离线对话，且每条只出现一次
6. 同步中断：本地 outbox 保留，重试后仍只写一次
7. 同步中：不能继续直连，新消息进入 outbox
8. 离线模式不显示记忆/定时/QQ 等功能为“可用”
9. API Key 不进日志、不进 outbox、不上传
10. 离线记的账恢复后只入账一次；金额精度不变
```

## 不做

- 不在后端可用时直连模型
- 不做离线长期记忆
- 不做离线 QQ / 定时 / 主动消息
- 不在同步失败时丢弃 outbox
- 不做无 ack 的“假装同步”
- 不把 API Key 写进明文配置文件
