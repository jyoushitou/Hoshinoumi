# v20 系列 · 多用户（账号、身份、隔离）

> 前置：v19（架构基线 + `conversation_messages` + 单用户内部 API + 语音分段 + 架构重构）｜预估 11 天｜**四个次版本**
>
> v20 才引入真正的多用户：`users` / `identities` / `roles`，所有业务表加 `user_id`，
> 两个用户互相看不到对方的记忆、历史、日程、日记、书架、对话。
> 登录/JWT/公网入口仍然不做——那是 v21 网关。

## 多用户模型

| 概念 | 定义 |
|---|---|
| `user_id` | 账号/租户：一个人类用户 |
| `identity` | 绑定到 user 的渠道身份：QQ 号 / Web 账号 / 桌面设备 / 手机 |
| `target_id` | 会话：私聊 = `user_id`；群 = 群号；Web = `thread_id` |
| `role` | `owner` / `admin` / `user` |

**规则**：

- 每个请求必须带 `user_id`；没有“不传就是主人”的默认。
- v20 仍不做登录，但只信任**本机/网关**传入的 `user_id`；本机直连按 owner。
- QQ 私聊首次消息自动建 `user`（role=user），owner 可封禁；群聊归 owner/租户。
- 存量数据全部回填到 owner。
- **验收红线**：A 的 token/请求拿不到 B 的任何数据。

## 验收（系列整体）

```bash
python3 scripts/migrate.py --apply
python3 scripts/preflight.py
python3 run.py
```

- 两个测试用户 A/B：A 的 `!memory`、`!history`、`!cron`、日记、书架都看不到 B 的内容。
- 老库升级后，原 owner 数据全部在 `user_id='__owner__'`。
- QQ 私聊首次消息自动建 user；owner 可封禁。
- `conversation_messages` 的 `user_id` 与 `target_id` 不混用。

## 与 v21 的关系

v20 只做“后端多用户 + 隔离 + 内部 API”；**公网入口、JWT、限流、审计、TLS 全部留给 v21 网关**。
v21 网关负责把真实登录用户映射成 `user_id`，再调用 v20 的后端 API。
