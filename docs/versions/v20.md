# v20 系列 · 网关（一）核心与代理

> 前置：v19（架构/对话底座 + 单用户内部 API + proto 骨架）｜预估 7 天｜**六个次版本**
>
> 网关拆成三个大版本：
> **v20 核心与代理** → v21 owner 鉴权 → v22 限流/审计/TLS。
> v20 只解决“公网能进来、能转到后端”，不碰登录和多用户。

## 为什么必须有网关

| 没有网关 | 有网关 |
|---|---|
| 每个客户端自己写鉴权 | 一处鉴权，所有客户端受益 |
| 谁都能直连后端 | 只有网关能连后端 |
| 限流写在各处 | 统一限流 |
| 没有访问审计 | 每个请求都有记录 |
| 加客户端要改后端 | 只改网关路由 |

## 架构位置

```
   手机 App        电脑 Web        以后：小程序 / CLI
      │               │                  │
      └───────┬───────┴──────────────────┘
              ↓  HTTPS / WSS
   ┌──────────────────────────┐
   │  网关（v20）              │
   │  REST ↔ gRPC · 路由       │
   └──────────┬───────────────┘
              ↓  只走 127.0.0.1
   ┌──────────────────────────┐
   │  后端 API（v19）          │
   └──────────┬───────────────┘
              ↓
        bot 核心 / 记忆 / 调度
```

**硬规则**：后端 API **不监听外网**；外网只能打到网关。

## 这一版只做什么

| 做 | 不做（留给 v21/v22） |
|---|---|
| C++/Drogon 工程 + 构建 | owner 登录/JWT |
| REST/JSON ↔ gRPC/protobuf 转换 | 限流 |
| 路由表：`/api/chat` → `/internal/chat` 等 | TLS |
| `/healthz` `/readyz` | 审计 |
| 单二进制部署 | 多用户/roles |
| **交互配置向导**：`scripts/configure.py`（API 密钥 + 网关监听/后端） | owner secret（v21）、TLS 路径（v22） |

## 配置向导

用户不手写 JSON：

```bash
python3 scripts/configure.py
```

菜单：

```text
1. API 密钥（DeepSeek / 豆包 / ALAPI，复用 v19 configure_api.py）
2. 网关监听地址 / 端口
3. 后端地址（默认 127.0.0.1:7070）
4. 日志级别
5. 查看当前配置
6. 测试后端连通
0. 保存退出
```

写入：

```text
config/gateway.json   # 网关配置，chmod 600
```

规则：

- 直接回车保留当前值；`-` 清空可选项
- 监听地址默认 `127.0.0.1`，显式改 `0.0.0.0` 才对外
- 后端地址只允许 `127.0.0.1`（v20 硬规则）
- v21 在同一向导加 owner secret 登录项
- v22 在同一向导加 TLS 证书路径 / 限流参数

## 验收

```bash
# 先配置
python3 scripts/configure.py

# 网关起来
./nao-gateway --config config/gateway.json

# 健康
curl -s http://127.0.0.1:8080/healthz
curl -s http://127.0.0.1:8080/readyz

# 代理（v20 还没有鉴权，只在本机测试）
curl -s -X POST http://127.0.0.1:8080/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"user_id":"__owner__","text":"你好"}'
```

- `python3 scripts/configure.py` 能生成 `config/gateway.json`，用户不用手改 JSON。
- 后端只监听 127.0.0.1；外网直连后端失败。
- 网关能转发 chat/history/state，返回 JSON。
- 没有 JWT/限流/TLS 是**预期**，v21/v22 补。

## 与 v21/v22 的边界

- **v21**：owner secret → JWT、token 中间件、刷新、失败锁定。
- **v22**：按 owner/IP 限流、审计 `gateway_log`、TLS、`!gw`、压测。
- **v23**：多用户 users/roles，升级 JWT `sub=user_id`。
