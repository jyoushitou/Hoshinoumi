# v38 系列 · 生态接入

> 大版本 v38。目标：接入 QQ 空间、运维、视频、微信、通话、微服务，
> 并新增微博/贴吧/知乎内容流；空闲时随机选择内容消费。

## 1. 范围

### 要做

```text
QQ 空间：发说说 + 熟人点赞/评论
运维：只读 → agent → 有限写 → 可写体系
B 站 / 抖音：搜索、解析、摘要
微信：OpenClaw 接入
语音/视频通话
微服务：自有 Web 接入
微博 / 贴吧 / 知乎：只读内容流
随机内容消费：读书 / 贴吧 / B站 / 微博 / 知乎
```

### 不做

```text
不发帖/评论/点赞（除 QQ 空间熟人授权）
不做验证码绕过、不做反爬对抗
不保存平台密码
不做直播/打赏/支付
```

## 2. 内容流复用读书链路

```text
公开页 URL
→ 抓取（HTTP/Playwright）
→ 正文提取
→ 1000 字分块
→ summarize_chapter
→ book_memory / reading_queue
→ 按 offset 续读
```

复用：

```text
book_queue：offset / status / total
book_memory：摘要/读完
reading.summarize_chapter：摘要
v29.4 规则：自动流程只入库，不主动发摘要
```

不新建一套内容进度表；用 source 前缀区分 `weibo:` / `tieba:` / `zhihu:`。

## 3. 随机内容消费

池子：

```text
本地读书
贴吧
B站
微博
知乎
```

规则：

```text
权重可配，读书默认略高
同一 source 不连续选
有冷却（默认 30 分钟）
失败/空内容换源
自动流程不刷屏
```

命令才回摘要：

```text
!feed random
!feed weibo
!feed tieba
!feed zhihu
!feed bilibili
!book next
```

## 5. 开发思路

### 5.1 先只读，后写入

- 微博/贴吧/知乎/B站/抖音先只读。
- QQ 空间写入单独授权、限熟人、可审计。
- 运维写入必须审批 + 回滚点。

### 5.2 内容源统一接口

```python
class ContentSource(Protocol):
    name: str
    async def list(self, query=None, limit=10) -> list[dict]: ...
    async def fetch(self, url: str) -> dict: ...
```

每个 adapter 只负责“列表/正文”；分块、摘要、入库统一走读书链路。

### 5.3 Cookie/限速

- Cookie 只从 `.env` 读，不写日志。
- 每源独立 token bucket；默认 1 req/3s。
- 429/验证码：停止并提示，不绕过。

### 5.4 随机消费

```text
idle tick
→ 读权重 + 冷却
→ 过滤不可用源
→ 加权随机
→ 选一个源
→ 抓一页/一段
→ 分块摘要入库
```

不自动发摘要；只有 `!feed`/`!book next` 才回。

### 5.5 反爬边界

- 不破解验证码、不伪造登录、不绕风控。
- 只抓公开页；遵守 robots/平台条款。
- 失败就降级/停，不硬刷。

## 6. 风险

- 平台接口变动/封禁：adapter 隔离，失败换源。
- Cookie 泄漏：只读 .env，日志脱敏。
- 内容安全：敏感内容过滤；不主动传播。
- 运维误操作：只读先行，写入审批。
- 随机成瘾/刷屏：冷却 + 自动静默。

## 7. 总验收

```text
1. !feed weibo/tieba/zhihu 能读一页并入库
2. 本地读书 offset 续读不变
3. 随机池五源；同源不连续；失败换源
4. 自动流程无摘要气泡
5. B站/抖音失败不编造
6. 运维写入必须审批
7. QQ空间只影响熟人白名单
```
