# v38.0.0 · systemd 服务化

## unit 文件

```ini
[Unit]
Description=TomoriNao QQ Bot
After=network-online.target mysql.service
Wants=network-online.target

[Service]
Type=simple
User=jyoushitou
WorkingDirectory=/home/jyoushitou/NapCat-Pyhon
ExecStart=/usr/bin/python3 run.py
Restart=always
RestartSec=3
# 崩溃循环保护：10 分钟内超过 5 次就不再重启
StartLimitIntervalSec=600
StartLimitBurst=5
# 资源边界
MemoryMax=2G
CPUQuota=150%
# 日志
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

## 关键取舍

| 取舍 | 决定 | 原因 |
|---|---|---|
| `Restart=always` vs `on-failure` | `always` | 她自己退出（`!exit`）也应该被拉起？**不**——见下 |
| `!exit` 与 systemd | 加 `NAO_SYSTEMD=1` 环境变量，`!exit` 时**改走 `systemctl stop`** | 否则 `!exit` 后 3 秒又活了 |
| 崩溃循环保护 | 10 分钟 5 次 | 配置错时不要无限重启烧 CPU |
| 内存上限 | 2G | 浏览器 + OCR 峰值约 500M，留足余量 |

## 验收

- [ ] `systemctl enable --now` 后开机自起
- [ ] `kill -9` 进程，3 秒内自动拉起
- [ ] `!exit` 后**不会**自动重启（走 stop）
- [ ] `journalctl -u nao-bot -f` 能看日志
- [ ] 连续崩溃 5 次后停止重试并留下日志

# v38.0.1 · 看门狗与自愈

## 三层看门狗

| 层 | 检查什么 | 超时后 |
|---|---|---|
| 进程层 | PID 是否存在 | systemd 自动拉起 |
| 心跳层 | `cfg.last_heartbeat` 是否更新 | 应用内重启（`os.execv`） |
| 业务层 | 队列是否积压 / 连接是否僵死 | 降级（不重启） |

## 应用层看门狗

```python
async def watchdog():
    """30 秒检查一次：心跳超过 180 秒没动就重启进程"""
    while True:
        await asyncio.sleep(30)
        idle = _time.time() - cfg.last_heartbeat
        if idle > 180:
            log_err(f"看门狗：心跳 {idle:.0f}s 未更新，重启")
            os.execv(sys.executable, [sys.executable] + sys.argv)
```

## 业务层降级（不重启）

| 现象 | 降级 |
|---|---|
| MySQL 连不上 | 记忆走内存兜底，回复继续 |
| NapCat 断连 | 消息入队，等重连补发 |
| 模型超时 | 豆包兜底 → 傲娇短句 |
| 浏览器卡死 | 杀掉子进程，读书跳过本次 |

## 验收

- [ ] 手动冻结进程（`kill -STOP`），180 秒后自愈
- [ ] MySQL 断开后仍能回复（降级模式）
- [ ] 重启后状态从库里恢复，不丢记忆
