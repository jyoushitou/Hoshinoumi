# v18 系列 · 情感的深刻度

> 前置：v17（执行模型 + 情绪/声线）｜预估 9 天｜**四个次版本**
>
> **核心命题**：人不是「24 小时清零」的机器。
> 今天被骂一句，明天还记着；被温柔对待一次，能记好几年。
> 记忆和情绪都该有**分量**：轻的很快淡，重的留得久。

## 现在的问题

```
mood 每小时往基线回归  →  睡一觉，昨天的气没了
记忆全按 importance=2  →  「你妈住院」和「今天吃了面」一样重
情绪只影响当次回复      →  昨晚吵架，今天她像没事人
```

**结果**：她的记忆是「平的」，所有事一样重，所有情绪一样短。

## 目标：三档分量

| 档 | 例子 | 记忆留存 | 情绪衰减 |
|---|---|---|---|
| **轻** | 今天吃了什么、随口吐槽 | 7 天 | 半衰期 1 天 |
| **中** | 工作不顺、和朋友闹别扭 | 90 天 | 半衰期 3 天 |
| **重** | 亲人离世、重病、重要约定、表白/分手 | **长期（不清）** | 半衰期 5 天 |

**「重」的记忆不按天删**——它进「长期记忆」区，检索时永远高优先级。

## v18.0 · 记忆分量（3 天）

| 单元 | 内容 | 验收 |
|---|---|---|
| U1 | `memories.weight`（0~1）+ `kind`（轻/中/重） | 旧行默认 0.5 |
| U2 | 写入时判定：关键词 + 模型打标 | 「我妈住院了」判重 |
| U3 | 检索按 `weight` 加权（重的更容易被想起） | 同类查询重的排前 |
| U4 | `!memory` 显示分量 | 看得出哪条是重的 |

**判定规则（先规则后模型，省 token）**

| 信号 | 判定 |
|---|---|
| 亲人/生病/去世/分手/结婚/生日 | 重（0.9） |
| 工作/学业/吵架/承诺 | 中（0.6） |
| 其余 | 轻（0.3） |

**模型打标只在规则不确定时调用**（比如「他说了一句让我愣住的话」）。

## v18.1 · 情绪跨天保留（2 天）

> 从 v17.17 挪过来，作为本系列的第二个单元。

| 单元 | 内容 | 验收 |
|---|---|---|
| U1 | 情绪标签单独存（`emotion` / `emotion_at` / `power`） | 跨天后读得到 |
| U2 | **跨天不清零** | 连续两天 `!state` 情绪一致 |
| U3 | 半衰期 3 天（强烈 5 天） | 第 2 天剩 ~63% |
| U4 | `detect_emotion` 优先读存的标签 | 语音语气和昨天一致 |

**衰减公式**：

```python
factor = 0.5 ** (1.0 / half_life_days)
power *= factor ** days_elapsed
if power < 0.15:  # 消散
    return "平静"
```

## v18.2 · 回忆触发（2 天）

> 重记忆不是「存着等检索」，而是**会自己冒出来**。

| 单元 | 内容 | 验收 |
|---|---|---|
| U1 | 每天最多一次「突然想起」 | 不刷屏 |
| U2 | 只挑 `weight ≥ 0.7` 且 7 天没提过的 | 不重复念叨 |
| U3 | 提起时带时间：「上周你说你妈住院」 | 有时间感 |
| U4 | 她情绪低落时不提旧伤口 | 有分寸 |

**触发时机**：`idle_tick` 安静时，命中概率 20%，每天上限 1 次。

**红线**：不拿重记忆当谈资；不主动提创伤事件（除非主人先提）。

## 红线（整个系列）

- **重记忆不自动删**：只有主人 `!forget` 才能删
- 情绪**必须有消散路径**（上限 1.0，最低回到平静）
- 分量判定**宁可判轻**：判重了会让她反复提旧事
- 不做「情绪历史库」：只留最近一次情绪 + 强度

## 验收（系列整体）

| 项 | 标准 |
|---|---|
| 重记忆留存 | 30 天后还能检索到亲人/重病类记忆 |
| 轻记忆衰减 | 7 天前的「吃了面」不再被想起 |
| 情绪跨天 | 第 2 天聊天气氛仍受前一天影响 |
| 主动提起 | 一周内至少一次「突然想起」 |

## v18.3 · 收尾：彻底移除旧表

> v17.10 只做了第 1 步（停写）。到这里旧表已经只读不写一段时间了，
> 可以一次清干净——**这一步不可逆**。

| 步 | 做什么 | 检查 |
|---|---|---|
| 1 | 备份整库：`mysqldump ... > backup-before-drop.sql` | 备份文件非空、能 grep 到 `events` |
| 2 | 停读：旧 JSON 读函数改读新表，去掉 `events` 回退 | 日志里不再出现「回退旧表」 |
| 3 | 标旧行：`UPDATE events SET deleted_at=NOW() WHERE kind NOT IN (...)` | 行数对得上 |
| 4 | 改名留档：`RENAME TABLE events TO events_old_YYYYMMDD` | 旧查询全部报错即证明没漏 |
| 5 | 删合并逻辑：`repo_memory` 里新旧字段 merge 分支 | 单测仍绿 |
| 6 | 删 `store_v2` 回退分支 + 删 `NAO_LEGACY_WRITE` 开关 | `grep -r "NAO_LEGACY_WRITE"` 为空 |

**验收**：

- `SHOW TABLES` 里没有 `events`（只有 `events_old_*` 留档）
- `grep -r "FROM events" botv/` 结果为空或只剩注释
- 全量测试绿
- 跑 24 小时无「表不存在」报错

**回退方案**：只有第 4 步（改名）可逆——`RENAME TABLE events_old_* TO events`。
第 5、6 步删掉的代码靠 git 回滚。

**为什么放收尾版**：这类「删数据路径」的改动必须单独一版、单独验证，
和功能开发混在一起，出问题分不清是谁的锅。
