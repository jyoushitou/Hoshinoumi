# v22 系列 · 网关（三）限流 / 审计 / TLS

> 前置：v21（owner 鉴权）｜预估 4 天｜**两个次版本**
>
> v22 是网关上线前的最后一层：限流、审计、TLS、观测和压测。
> 做完这版，v23 多用户直接接在网关上。

## 目标

| 能力 | 内容 |
|---|---|
| **限流** | 每 owner token / IP 每分钟 60 次；超了 429 |
| **审计** | `gateway_log`：owner、时间、路径、状态、耗时、IP |
| **TLS** | 有证书走 HTTPS/WSS；本地开发可显式关 |
| **观测** | `!gw`：在线客户端、最近请求、限流命中 |
| **压测** | 限流/超时/后端不可达行为可复现 |

## 验收

```bash
# 限流
for i in $(seq 1 70); do curl -s -o /dev/null -w '%{http_code}\n' \
  http://127.0.0.1:27005/api/state -H "Authorization: Bearer $TOKEN"; done | sort | uniq -c

# 审计
mysql -e "SELECT owner,path,status,cost_ms,ip FROM gateway_log ORDER BY id DESC LIMIT 5"

# TLS
curl -s https://your.domain/healthz
```

- 默认 HTTPS；关闭 TLS 必须显式配置并打警告。
- 超限 429；后端断开 503；审计可按 owner 查。
- 网关挂掉时，本机插件仍可直连 127.0.0.1:7070。

## 与 v23 的边界

- v22 的 JWT 还是 `sub=owner`。
- v23 多用户引入 `users` / roles / 邀请码；v23.3 把 JWT 改成 `sub=user_id`，
  限流/审计按真实 user 统计。
- v22 的 `gateway_log` 表结构预留 `user_id` 字段，v23 直接填。
