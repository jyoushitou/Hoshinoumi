# v37 系列 · 微服务接入（自有 Web）

> 前置：v21 后端 API / v20 网关 / v23 电脑 Web｜预估 6 天｜**四个次版本**
> 目标：把她作为一个**微服务**融进你自有的 Web 服务网站——不是再部署一套独立进程，
> 而是成为体系里的一个服务：先找体系网关，找到就用体系的网关和连接池；
> 找不到/不是体系网关，才启内置网关 + 本地连接池，保证独立也能跑。

## 启动决策（核心）

```
启动
  │
  ├─ 探体系网关：GET {NAO_GATEWAY_URL}/api/gateway/info
  │    带 X-Nao-Probe: 1，超时 1s，重试 5 次（0.5/1/2/4s 退避）
  │
  ├─ 200 + system=="nao" + 签名/版本校验通过
  │    → 体系内模式：用体系网关；连接池借用体系的，**不自建**
  │
  └─ 5 次都失败 / 404 / 签名不对 / 版本不兼容
       → 独立模式：启内置网关（v20）；连接池用本地（现有 infra/pool）
```

**「不是体系网关」的判定**（缺一不可）：

| 检查 | 说明 |
|---|---|
| `system == "nao"` | 响应体必须带体系标识 |
| 签名 | `X-Nao-Signature`（HMAC，共享密钥）或 mTLS 证书链 |
| 版本 | `api_version` 在主版本兼容范围内 |
| 来源 | `gateway_id` 在允许列表（可配置） |

任何一项不通过都**不采用**，继续重试；5 次后回退独立模式。**失败关闭，不连野网关。**

## 两种模式

| | 体系内 | 独立 |
|---|---|---|
| 网关 | 体系网关（v20） | 内置网关（v20 本地实例） |
| 连接池 | **借用体系池**，`close()` 不关 | 本地池（`infra/pool.py`） |
| 注册 | 注册到宿主服务发现 | 不需要 |
| 监听 | 127.0.0.1 / Unix socket / 宿主指定 | 127.0.0.1 |
| 适用 | 融进自有 Web 服务 | 单机/开发/宿主不在 |

## 宿主契约（池怎么「借」）

| 形态 | 连接池 | 说明 |
|---|---|---|
| **同进程**（挂成宿主 ASGI 子应用/模块） | 宿主注入 `PoolProvider` | 直接借宿主连接；`close()` no-op |
| **独立进程**（微服务） | 宿主给 **pool proxy / 共享 DSN** | bot 不建池，每次 acquire 向代理借；`close()` 只还代理 |
| **独立模式** | 本地池 | 现有 `infra/pool.py` |

> 关键：**「用体系池」不是把宿主的池对象跨进程搬过来**；同进程靠注入，独立进程靠代理/共享 DSN。
> 两种都要求 bot **不初始化本地池**，否则就是双池。

## 关键设计

- **接入形态**：同进程挂成宿主 ASGI 子应用；或独立进程 + 宿主反代 `/nao/*` 到 `127.0.0.1`。
  两种都不改宿主路由前缀，宿主只多一条反代/挂载配置。
- **模式开关**：`NAO_DEPLOY_MODE=auto|system|standalone`（默认 `auto`）。
  `auto` 走上面的探测；`system`/`standalone` 强制，便于排障。
- **探针**：独立的小客户端，不依赖网关 SDK；1 秒超时；只读 `/api/gateway/info`。
- **多用户**：`user_id` 从网关 JWT 的 `sub` 来；每个请求按 user 隔离；连接池共享、按 user 做配额，**不按 user 建池**。
- **连接池抽象**：`ports/pool.py` 只暴露 `acquire()/release()/close()`；
  - `SystemPoolAdapter`：从宿主拿连接，`close()` 是 no-op；
  - `LocalPoolAdapter`：包现有 `infra/pool.py`。
  - 启动时**二选一**，并在日志/`!stats` 打 `pool=system|local`。
- **禁止双池**：体系模式下不初始化 `infra/pool.py`；启动断言 + `!stats` 显示池来源；
  宿主池的连接数指标应无额外一份。
- **内置网关**：独立模式才启动；复用 v20 的二进制/进程，监听 127.0.0.1 随机端口，
  把端口写进内部配置；体系模式**不启动**。
- **运行时不做模式切换**：体系网关中途挂了 → 标记 degraded、重试、只读降级；
  **不**在运行时启内置网关/本地池，避免双写/双池/脑裂。
- **监听**：默认 127.0.0.1；宿主可给 Unix socket 或指定端口；不绑公网。
- **安全**：体系模式走 JWT + mTLS/HMAC；探针失败关闭；不把宿主 token 写日志。
- **可观测**：`/readyz` 返回 `{mode, gateway, pool, db}`；`!stats` 加一行 `部署：system（池=体系）`。

## 验收

```bash
# 体系内
NAO_DEPLOY_MODE=auto NAO_GATEWAY_URL=https://web.example.com nao serve
# 日志：gateway=system pool=system
# 宿主池连接数不增加第二份；chat 正常

# 独立
NAO_DEPLOY_MODE=auto NAO_GATEWAY_URL=http://127.0.0.1:65530 nao serve
# 5 次探测失败 → gateway=internal pool=local；chat 正常
```

- 5 次失败 / 签名不对 / 版本不兼容 → 独立模式，不崩溃。
- 体系模式 `close()` 后宿主池仍可用；本地模式正常关池。
- `/healthz` 200；`/readyz` 在 DB/网关不可用时 503。
- 不出现「体系 + 本地」两套池同时存在。

## 风险

| 风险 | 处理 |
|---|---|
| 探到野网关 | 签名 + `gateway_id` 白名单 + 版本校验；失败关闭 |
| 双连接池 | 启动断言 + 指标；体系模式不初始化本地池 |
| 宿主池被误关 | `SystemPoolAdapter.close()` no-op；只借不拥有 |
| 运行时脑裂 | 不做运行时模式切换；只降级/重试 |
| 端口冲突 | 127.0.0.1 + 随机端口/Unix socket；端口写配置 |
| 宿主重启 | 注册 TTL + 重连；`/readyz` 反映 |

## 不做

- 不引入服务网格/Istio/Consul；用宿主已有的服务发现。
- 不做多租户；仍单主人。
- 不在运行时切换 system/standalone。
- 不把内置网关暴露到公网。
