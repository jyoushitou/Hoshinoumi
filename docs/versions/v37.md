# v37 系列 · 命令收敛与专用前端通道

> 插入位置：v36 Qoder / WorkBuddy 插件之后，v38 电脑 Web 之前。
> 编号：v33 多端推送 / v34 本机服务化 / v35 DSH / v36 Qoder / v37 命令收敛 / v38 Web。
> 目标：QQ 只保留必要短命令；详细配置、日志、用量、数据库、插件和定时管理，全部走自研专属前端。

## 背景

现在直接在 QQ 里发 `!db`、`!usage`、`!hooks`、`!cron`、`!plugins`、`!memory` 这类命令：

- 输出长，容易刷屏
- 破坏聊天节奏
- 配置类命令在手机上难操作
- 误触/误发风险高
- 多用户后权限边界更难控

v37 把「查看/管理」从 QQ 聊天流里拆出去。

## 目标

| 能力 | 内容 |
|---|---|
| QQ 短命令白名单 | 只保留极短、无大量输出的命令 |
| 详细操作迁移 | 配置、日志、用量、数据库、插件、定时、记忆，全部走专属前端 |
| 专属前端通道 | 自研 Web/桌面/客户端通过网关的受保护 API 调用，不再用聊天命令 |
| 命令注册表 | 每个命令声明 `scope=qq_short / client_only` 和最大输出 |
| 兼容与降级 | 旧命令在 QQ 返回一句「请到客户端查看」，不再输出正文 |

## QQ 保留的命令

只保留必要、短输出：

```text
!help      只显示 5 行以内的帮助
!status    一行状态
!ping      连通性
!stop      主人停止当前主动会话/退出
```

具体白名单在实现时定稿；原则是：

- 单条输出不超过 8 行
- 不做配置修改
- 不做列表/分页/日志/数据库查询
- 不做需要长参数的操作

以下命令从 QQ 移除，改为客户端：

```text
!db
!usage
!hooks
!cron / !cron:list
!plugins
!memory
!logs
!history（长历史）
!endpoints
!model
!channels
!tools
!scheduler
!transport
!gw（详细页）
```

QQ 收到这些命令时只回复：

```text
这个操作请在 Hoshinoumi 客户端里查看。
```

## 专属前端通道

不是“再做一个聊天窗口”，而是**管理通道**：

- 登录：owner / 后续 user 角色
- 网关：JWT + 限流 + 审计
- API：结构化 JSON，不解析聊天命令
- 页面：
  - 状态 / 用量
  - 记忆 / 事实卡
  - 定时 / 日程
  - 日志 / 审计
  - 插件 / 模型 / 通道
  - 数据库只读视图
- 所有危险操作：二次确认 + 审计
- 分页、搜索、导出在客户端做，不再把大段文本塞进 QQ

## 命令注册表

```python
class CommandSpec(Protocol):
    name: str
    scope: Literal["qq_short", "client_only"]
    max_lines: int
    requires_owner: bool
    mutates: bool
```

约束：

- `qq_short` 必须 `max_lines <= 8` 且 `mutates = False`
- `client_only` 不出现在 QQ 帮助里
- 未注册命令一律拒绝
- 旧命令保留别名，只返回迁移提示

## 验收

```text
QQ 发 !db / !usage / !hooks / !cron / !plugins
→ 只返回“请到客户端查看”，不输出正文

QQ 发 !help
→ 不超过 8 行

客户端登录后
→ 能看到状态、用量、日志、定时、插件、记忆

客户端未登录
→ 401，不返回任何管理数据
```

## 与后续版本的关系

- v37 只做“命令收敛 + 管理通道”，不实现完整 Web/桌面 UI
- v33 多端推送 / v34 本机服务化 / v35 DSH / v36 Qoder 保持在 v37 之前。
- v38 电脑 Web 在 v37 之后接入；后续客户端版本继续复用 v37 的 API 契约。

## 非目标

- 不是把 QQ 变成只读机器人
- 不是删除所有命令；`!help`、`!status`、`!ping`、`!stop` 仍保留
- 不是把管理功能做成聊天里的富文本
- 不是要求所有用户都装客户端才能聊天；聊天仍在 QQ
