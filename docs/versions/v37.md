# v37 系列 · 存储层契约与 native adapter

> 核心：把 MySQL / SQLite 与现有仓储包成 `StorageBackend` / `Repository` 实现。
> 核心 backend 是 native，不注册为插件。

```python
class StorageBackend(Protocol):
    name: str
    async def execute(self, sql: str, params: tuple) -> list[dict]: ...
    async def transaction(self): ...


class Repository(Protocol):
    async def get(self, user_id: str, key: str) -> dict | None: ...
    async def put(self, user_id: str, key: str, value: dict) -> None: ...
```

## 本层插件接口约束（v27 总纲）

> 跨版本总纲：[INTERFACE-PLAN-v27-v44.md](../INTERFACE-PLAN-v27-v44.md)

- 本版只开放**存储层**接口，不把其他层一起搬。
- 能力名：`storage.backend.<name>@1 / storage.repository.<name>@1`。
- 核心 native（MySQL / SQLite）保持 native，**不实现 PluginManifest，不进入插件表**。
- 第三方实现本层 Protocol，通过 v27 `PluginRegistry` 注册。
- 业务只依赖 Protocol；`get()` 拿不到时回落核心 native。
- 敏感资源走 v27 权限三档（0 拒绝 / 1 询问 / 2 允许），默认 1。
- 插件任务、线程池、DB 连接池由 v27 context 提供，不允许裸 `create_task` / 裸连库。
- 插件失败写 `plugin_errors`，连续失败自动停用。
- 插件 DDL 走 `migrations/`，只支持 MySQL/SQLite，表前缀 `plugin_<name>_`。
- 热更采用 worker 进程级快照；已启用插件在新 worker 自动加载。

## 实现步骤

| 次版本 | 内容 | 验收 |
|---|---|---|
| **v37.0** | `StorageBackend` / `Repository` 契约 | 业务只依赖接口 |
| **v37.1** | `MySQLBackend` native adapter | 现有 MySQL 行为不变 |
| **v37.2** | `SQLiteBackend` native adapter | 降级路径不变 |
| **v37.3** | 现有 repo_* 收口到 Repository | 业务不再拼 SQL |

> 第三方存储层实现见 [v38.md](v38.md)。

## 关键约束

- MySQL / SQLite 是核心 native，不注册为插件。
- 第三方 backend 失败由 v43 回退核心 backend。
- 核心存储只能启动前通过 `features.json` / `NAO_FEATURES` 关闭。
