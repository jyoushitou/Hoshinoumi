# v37 系列 · 情感增强

> 大版本 v37。目标：关系不再由单一 affinity 数值决定，改成多维数值 + 分支关系 + 负向叠加状态；
> 人设卡升级到 v2，按关系阶段/维度调整语气、称呼、边界。
> 原 v37 生态接入顺延为 v38；原 v38 运维与嵌入式顺延为 v39。

## 1. 为什么改

现在只有一个 `affinity=-1.0..1.0`，问题：

```text
1.0 就永远亲近，没有“信任/尊重/吸引/安全感/默契”的区别
高亲近也可能高张力，但单值表达不了
“亲近”之后没有更细的阶段，也没有“灵魂共鸣”这种长期默契
人设卡只有一套语气，无法按关系阶段变化
```

## 2. 多维关系

| 维度 | 含义 | 范围 |
|---|---|---|
| closeness | 亲近度 | 0..1 |
| trust | 信任 | 0..1 |
| respect | 尊重/敬佩 | 0..1 |
| attraction | 吸引 | 0..1 |
| security | 安全感 | 0..1 |
| tension | 张力/冲突 | 0..1，高=紧张 |
| understanding | 理解/默契 | 0..1 |
| support | 支持/可靠 | 0..1 |
| reciprocity | 双向投入 | 0..1 |

不引入“依赖度”这类不健康指标。

## 3. 关系结构：阶段 + 分支 + 状态

不是一条从陌生到灵魂共鸣的长梯子。像人一样：

```text
基础阶段：陌生 → 认识 → 熟 → 亲近
亲近之后分叉：
  ├─ 亲密（吸引高）
  ├─ 知己（理解/默契高，吸引不一定高）
  ├─ 家人/羁绊（支持/安全感/双向投入高）
  └─ 灵魂共鸣（多项都高，长期稳定）
```

负向不是“降级”，是**叠加状态**：

```text
疏离 / 冷淡 / 紧张 / 厌恶 / 破裂
```

可以同时存在：

```text
亲近 · 紧张
亲密 · 冷淡
家人 · 破裂
```

### 正向分支

| 分支 | 主要条件 | 含义 |
|---|---|---|
| 亲密 | attraction 高，closeness/trust 高 | 想靠近、想独占一点 |
| 知己 | understanding 高，trust 高 | 懂彼此，不一定浪漫 |
| 家人/羁绊 | support/security/reciprocity 高 | 稳定、可靠、长期 |
| 灵魂共鸣 | closeness/trust/understanding/support 都高 | 长期默契，稀有 |

### 负向状态

| 状态 | 条件 | 表现 |
|---|---|---|
| 疏离 | security 低、closeness 低 | 退开、不交底 |
| 冷淡 | support/reciprocity 低 | 话少、不主动 |
| 紧张 | tension 高 | 短句、易刺 |
| 厌恶 | attraction/respect 高但 tension 高 | 排斥、带刺 |
| 破裂 | trust 极低 + tension 高 | 只保留基本功能 |

### 组合

```text
bond = 基础阶段 or 分支
strain = 负向状态（可 none）
display = bond + (·strain)
```

示例：

```text
closeness=0.9, trust=0.9, understanding=0.9, attraction=0.2
→ 知己（不是亲密）

closeness=0.9, trust=0.8, attraction=0.9
→ 亲密

closeness=0.9, trust=0.9, support=0.9, reciprocity=0.9
→ 家人/羁绊

closeness=0.9, trust=0.8, tension=0.7
→ 亲近 · 紧张

closeness=0.95, trust=0.9, understanding=0.9, support=0.9
→ 灵魂共鸣
```

## 4. 数据模型（schema 34）

```sql
CREATE TABLE relation_dims (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id VARCHAR(64) NOT NULL DEFAULT '__owner__',
    target_id VARCHAR(64) NOT NULL,
    closeness DECIMAL(4,3) NOT NULL DEFAULT 0.3,
    trust DECIMAL(4,3) NOT NULL DEFAULT 0.3,
    respect DECIMAL(4,3) NOT NULL DEFAULT 0.3,
    attraction DECIMAL(4,3) NOT NULL DEFAULT 0.3,
    security DECIMAL(4,3) NOT NULL DEFAULT 0.5,
    tension DECIMAL(4,3) NOT NULL DEFAULT 0.0,
    understanding DECIMAL(4,3) NOT NULL DEFAULT 0.3,
    support DECIMAL(4,3) NOT NULL DEFAULT 0.3,
    reciprocity DECIMAL(4,3) NOT NULL DEFAULT 0.3,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
               ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_relation_dims (user_id, target_id)
);

CREATE TABLE relation_dim_events (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id, target_id, dimension, delta, reason, severity,
    created_at
);
```

保留旧 `relations.affinity` 作为兼容/展示，不再作为唯一决策源。

## 5. 事件映射

```text
正常聊天        closeness +0.002（日上限）
兑现承诺        trust +0.01, security +0.01
失约/撒谎       trust -0.05, tension +0.03
被安慰/道歉     security +0.03, tension -0.04
冲突/冷战       tension +0.05, security -0.02
长期怨念        trust -0.06, tension +0.04
严重事件        trust -0.2, tension +0.2（需审批/审计）
一起完成计划    understanding +0.02, support +0.01
双向主动        reciprocity +0.02
被理解/接住     understanding +0.03, security +0.01
```

所有变化写 `relation_dim_events`，可按维度回滚。

## 8. 开发思路

### 8.1 先模型，后文案

- 先做六维存储/推导/事件，确保状态正确。
- 再改 prompt/人设卡，避免“文案先行、数据对不上”。

### 8.2 分支推导

```text
base = f(closeness, trust)
if closeness >= 0.85 and trust >= 0.80:
    if support/reciprocity >= 0.75: bond = 家人
    elif attraction >= 0.70: bond = 亲密
    elif understanding >= 0.70: bond = 知己
    else: bond = 亲近
elif closeness >= 0.70 and trust >= 0.65:
    if attraction >= 0.65: bond = 亲密
    elif understanding >= 0.60: bond = 知己
    elif support >= 0.65: bond = 家人
    else: bond = 亲近
elif closeness >= 0.50: bond = 亲近
elif closeness >= 0.30: bond = 熟
elif closeness >= 0.15: bond = 认识
else: bond = 陌生

strain = none
if trust < 0.2 and tension > 0.7: strain = 破裂
elif tension > 0.6: strain = 紧张
elif attraction/respect high and tension > 0.5: strain = 厌恶
elif security < 0.3: strain = 疏离
elif support < 0.3 or reciprocity < 0.3: strain = 冷淡

灵魂共鸣 = bond in (家人, 知己, 亲密) and all key dims >= 0.85

```

数值是内部状态，prompt 只放“关系描述 + 当前阶段 + 维度提示”。

### 8.3 人设卡

- 旧卡不迁移文件，读时包装。
- 新卡按阶段给语气/称呼/边界。
- 阶段缺失回退 `base`，不报错。
- 保存前校验 schema v2。

### 8.4 兼容

- `relations.affinity` 继续写，做旧 UI/旧逻辑兜底。
- 新逻辑优先多维；旧字段只展示。
- 回滚：关闭多维开关，回单值。

## 9. 风险

- 维度太多导致行为不可解释：`!relation` 必须能解释。
- 文案与人设冲突：阶段语气优先，base 兜底。
- 旧数据回填失真：保留旧 affinity，标注兼容值。
- 插件改维度越权：关系插件只能走 `RelationPolicy`，审计。
- 不把数值直接塞 prompt，避免“报数值”。

## 10. 总验收

```text
1. 旧库升级后关系不丢
2. 六维可读写，事件可追溯
3. 高亲近+高张力显示“亲近·紧张”，不是单纯“亲近”
4. 知己/亲密/家人按维度分支，不按一条等级排队
5. 旧人设卡可用，新人设卡按 bond + strain 变化
6. !relation 能解释分支
7. 关闭多维可回单值
8. 全量测试 0 失败
```
