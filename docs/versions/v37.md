# v37 系列 · 情感增强

> 大版本 v37。目标：关系不再由单一 affinity 数值决定，改成多维数值 + 60 个关系标签（长期标签 + 短期状态）叠加；
> 人设卡升级到 v2，按关系阶段/维度调整语气、称呼、边界。
> 原 v37 生态接入顺延为 v38；原 v38 运维与嵌入式顺延为 v39。

## 1. 为什么改

现在只有一个 `affinity=-1.0..1.0`，问题：

```text
1.0 就永远亲近，没有“信任/尊重/吸引/安全感/默契”的区别
高亲近也可能高张力，但单值表达不了
“亲近”之后没有更细的阶段，也没有“灵魂共鸣”这种长期默契
人设卡只有一套语气，无法按关系阶段变化
```

## 2. 多维关系

| 维度 | 含义 | 类型 | 范围 |
|---|---|---|---|
| closeness | 亲近度 | 核心 | 0..1 |
| trust | 信任 | 核心 | 0..1 |
| respect | 尊重/敬佩 | 核心 | 0..1 |
| attraction | 吸引 | 核心 | 0..1 |
| security | 安全感 | 核心 | 0..1 |
| tension | 张力/冲突 | 核心 | 0..1，高=紧张 |
| understanding | 理解/默契 | 核心 | 0..1 |
| support | 支持/可靠 | 核心 | 0..1 |
| reciprocity | 双向投入 | 核心 | 0..1 |
| familiarity | 熟悉度 | 修饰 | 0..1 |
| comfort | 松弛/舒适 | 修饰 | 0..1 |
| honesty | 坦诚 | 修饰 | 0..1 |
| loyalty | 忠诚/站队 | 修饰 | 0..1 |
| shared_values | 三观契合 | 修饰 | 0..1 |
| humor | 笑点契合 | 修饰 | 0..1 |
| communication | 沟通顺畅 | 修饰 | 0..1 |
| patience | 耐心 | 修饰 | 0..1 |
| boundaries | 边界感 | 修饰 | 0..1 |
| shared_memories | 共同经历 | 修饰 | 0..1 |
| repair | 修复力 | 修饰 | 0..1 |

核心维度决定 base/facets；修饰维度影响标签、语气和提示，不单独决定阶段。

不引入“依赖度”这类不健康指标。

## 3. 关系结构：阶段 + 正向叠加 + 负向状态

不是一条长梯子，也不是“只能选一个分支”。

```text
基础阶段：陌生 → 认识 → 熟 → 亲近
亲近之后：可以同时挂多个正向标签
负向：独立叠加状态
```

### 正向标签（可叠加）

| 标签 | 主要条件 | 含义 |
|---|---|---|
| 亲密 | attraction 高 | 想靠近、想独占一点 |
| 知己 | understanding 高 | 懂彼此，不一定浪漫 |
| 挚友 | trust + respect 高 | 信得过、看得起 |
| 家人 | support + security 高 | 稳定、可靠、长期 |
| 搭档 | reciprocity + respect 高 | 一起做事很合拍 |
| 欢喜冤家 | attraction + tension 高 | 会吵，但散不了 |
| 灵魂共鸣 | 多项都高 | 稀有，长期默契 |

示例：

```text
亲近 + 知己
亲近 + 知己 + 搭档
亲密 + 欢喜冤家
家人 + 挚友
亲近 + 知己 + 家人 + 搭档
亲密 + 知己 + 灵魂共鸣
```

### 标签库（60 个）

长期标签（trait）由 20 维推导；短期状态（state）由事件触发，带 TTL。

#### 正向长期标签（32）

```text
亲密 / 知己 / 挚友 / 家人 / 搭档 / 欢喜冤家 / 灵魂共鸣
心动 / 偏爱 / 守护 / 默契 / 信赖 / 敬佩 / 欣赏
可靠 / 安心 / 松弛 / 好玩 / 共犯 / 树洞 / 军师
饭搭子 / 书友 / 歌友 / 游戏搭子 / 学习搭子
旅行搭子 / 深夜搭子 / 吐槽搭子 / 夸夸团 / 嘴替 / 损友
```

#### 正向短期状态（8）

```text
宠溺 / 惦记 / 护短 / 同频 / 互补
久处不厌 / 无话不谈 / 随叫随到
```

#### 负向长期标签（10）

```text
疏离 / 冷淡 / 紧张 / 厌恶 / 破裂
戒备 / 不信任 / 隔阂 / 客气 / 躲避
```

#### 负向短期状态（10）

```text
吃醋 / 失落 / 委屈 / 失望 / 怨念
冷战 / 尴尬 / 疲惫 / 不耐烦 / 被忽视
```

合计 **60**。

### 负向状态（独立叠加）

```text
疏离 / 冷淡 / 紧张 / 厌恶 / 破裂
```

可和正向标签共存：

```text
亲近 + 知己 · 紧张
亲密 · 冷淡
家人 + 挚友 · 破裂
```

### 组合

```text
base    = 陌生/认识/熟/亲近
facets  = 0..N 个正向标签
strain  = 0..2 个负向状态
display = base + facets + (·strain)
```

不是“取最高分支”，而是“当前关系由哪些部分构成”。

示例：

```text
closeness=0.9, trust=0.9, understanding=0.9, attraction=0.2
→ 亲近 + 知己 + 挚友

closeness=0.9, trust=0.8, attraction=0.9, tension=0.6
→ 亲近 + 亲密 + 欢喜冤家

closeness=0.9, trust=0.9, support=0.9, reciprocity=0.9
→ 亲近 + 家人 + 搭档

closeness=0.95, trust=0.9, understanding=0.9, support=0.9
→ 亲近 + 知己 + 家人 + 灵魂共鸣
```

## 4. 功能开关

`config/features.json` 增加：

```json
"emotion_enhanced": { "enabled": true }
```

规则：

```text
true（默认）→ 20 维关系 + 60 标签
false        → legacy 单值情感，完全保留原来的 affinity/TIERS
```

- 开关启动时读取；改动后走 worker 热更/重启生效。
- 关闭增强时（手动 false），不读多维表、不写多维事件，prompt 用原来的 `relation.describe`。
- 旧 `relations.affinity` 继续维护，保证随时可以关回去。
- 打开增强时，旧 affinity 回填 closeness/trust/security，后续仍写旧字段做兼容。
- 两种模式共用 `!relation`，但显示不同。

## 5. 数据模型（schema 34）

```sql
CREATE TABLE relation_dims (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id VARCHAR(64) NOT NULL DEFAULT '__owner__',
    target_id VARCHAR(64) NOT NULL,
    closeness DECIMAL(4,3) NOT NULL DEFAULT 0.3,
    trust DECIMAL(4,3) NOT NULL DEFAULT 0.3,
    respect DECIMAL(4,3) NOT NULL DEFAULT 0.3,
    attraction DECIMAL(4,3) NOT NULL DEFAULT 0.3,
    security DECIMAL(4,3) NOT NULL DEFAULT 0.5,
    tension DECIMAL(4,3) NOT NULL DEFAULT 0.0,
    understanding DECIMAL(4,3) NOT NULL DEFAULT 0.3,
    support DECIMAL(4,3) NOT NULL DEFAULT 0.3,
    reciprocity DECIMAL(4,3) NOT NULL DEFAULT 0.3,
    familiarity DECIMAL(4,3) NOT NULL DEFAULT 0.2,
    comfort DECIMAL(4,3) NOT NULL DEFAULT 0.4,
    honesty DECIMAL(4,3) NOT NULL DEFAULT 0.4,
    loyalty DECIMAL(4,3) NOT NULL DEFAULT 0.3,
    shared_values DECIMAL(4,3) NOT NULL DEFAULT 0.3,
    humor DECIMAL(4,3) NOT NULL DEFAULT 0.3,
    communication DECIMAL(4,3) NOT NULL DEFAULT 0.4,
    patience DECIMAL(4,3) NOT NULL DEFAULT 0.4,
    boundaries DECIMAL(4,3) NOT NULL DEFAULT 0.5,
    shared_memories DECIMAL(4,3) NOT NULL DEFAULT 0.2,
    repair DECIMAL(4,3) NOT NULL DEFAULT 0.4,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
               ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_relation_dims (user_id, target_id)
);

CREATE TABLE relation_dim_events (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id, target_id, dimension, delta, reason, severity,
    created_at
);
```

标签状态：

```sql
CREATE TABLE relation_tag_states (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id VARCHAR(64) NOT NULL DEFAULT '__owner__',
    target_id VARCHAR(64) NOT NULL,
    tag VARCHAR(32) NOT NULL,
    kind VARCHAR(16) NOT NULL DEFAULT 'state',
    strength DECIMAL(4,3) NOT NULL DEFAULT 0.5,
    reason VARCHAR(64) NOT NULL DEFAULT '',
    expires_at DATETIME NULL,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
               ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_tag_state (user_id, target_id, tag)
);
```

- `trait` 不落表，读时从 20 维推导。
- `state` 落表，带 `expires_at`，到期自动消失。
- 同一标签只保留一条，强度取最新。

保留旧 `relations.affinity` 作为兼容/展示，不再作为唯一决策源。

## 9. 开发思路

### 8.1 先模型，后文案

- 先做 20 维存储/推导/事件，确保状态正确。
- 再改 prompt/人设卡，避免“文案先行、数据对不上”。

### 8.2 叠加推导

```text
base = 陌生
if closeness >= 0.50: base = 亲近
elif closeness >= 0.30: base = 熟
elif closeness >= 0.15: base = 认识

facets = []
if closeness >= 0.60:
    if attraction >= 0.65: facets.append("亲密")
    if understanding >= 0.60: facets.append("知己")
    if trust >= 0.65 and respect >= 0.60: facets.append("挚友")
    if support >= 0.65 and security >= 0.60: facets.append("家人")
    if reciprocity >= 0.65 and respect >= 0.60: facets.append("搭档")
    if attraction >= 0.65 and tension >= 0.50: facets.append("欢喜冤家")
    if all(x >= 0.85 for x in (closeness, trust, understanding, support)):
        facets.append("灵魂共鸣")

strain = []
if trust < 0.2 and tension > 0.7: strain.append("破裂")
elif tension > 0.6: strain.append("紧张")
elif attraction >= 0.6 and respect >= 0.6 and tension > 0.5: strain.append("厌恶")
elif security < 0.3: strain.append("疏离")
elif support < 0.3 or reciprocity < 0.3: strain.append("冷淡")
```

数值是内部状态，prompt 只放“关系描述 + base/facets/strain + 维度提示”。

### 8.3 标签使用

标签不是全量塞 prompt：

```text
长期 trait：最多取 4 个（按强度/优先级）
短期 state：最多取 2 个（按强度/未过期）
总展示不超过 6 个
```

规则：

```text
trait 由20维实时推导，不落表
state 由事件写 relation_tag_states，TTL 到期消失
同标签不重复
正面/负面可共存，但冲突组合降权
```

不把 60 个标签一次展示；`!relation` 可分组查看全部。

### 8.4 人设卡

- 旧卡不迁移文件，读时包装。
- 新卡按阶段给语气/称呼/边界。
- 阶段缺失回退 `base`，不报错。
- 保存前校验 schema v2。

### 9.5 兼容

- `relations.affinity` 继续写，做旧 UI/旧逻辑兜底。
- 新逻辑优先多维；旧字段只展示。
- 回滚：关闭多维开关，回单值。

## 10. 风险

- 维度太多导致行为不可解释：`!relation` 必须能解释。
- 文案与人设冲突：阶段语气优先，base 兜底。
- 旧数据回填失真：保留旧 affinity，标注兼容值。
- 插件改维度越权：关系插件只能走 `RelationPolicy`，审计。
- 不把数值直接塞 prompt，避免“报数值”。

## 11. 总验收

```text
1. 默认 `emotion_enhanced=true`，走 20 维/60 标签
2. 手动 false 时行为和 v34 完全一致
3. 旧库升级后关系不丢
2. 六维可读写，事件可追溯
3. 高亲近+高张力显示“亲近 + 亲密 · 紧张”，不是单纯“亲近”
4. 知己/亲密/家人/搭档可同时叠加，不按一条等级排队
5. 旧人设卡可用，新人设卡按 base + facets + strain 变化
6. !relation 能解释每个标签
7. 60 个标签可推导/触发，且不会一次全塞 prompt
8. 短期状态到期自动消失
9. 关闭多维可回单值
10. 全量测试 0 失败
```
