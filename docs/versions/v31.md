# v31 系列 · 出站层插件接口

> 前置：v23 多用户 API / v26 通道层｜预估 3 天｜**三个次版本**
> 目标：把「消息怎么发出去、失败怎么重试/排队」收进 **Transport** 接口层。
> 默认仍是 WebSocket 出站（全局锁 + 断线入队）；以后加 HTTP/Webhook/消息队列只加适配器。
>
> **核心不插件化**：WebSocket 出站是 native Transport，不注册为插件；
> 插件只能新增 HTTP/Webhook/MQ 传输；卸载/失败时回退 WebSocket。

## 现在的问题

| 现状 | 问题 |
|---|---|
| `egress/outbound.py` 只认 WebSocket | 换传输要改调用方 |
| 锁/队列/echo/重试混在一起 | 不能按通道配 |
| 多个客户端直连 `ws.send` | 容易绕开出站口 |
| 主动推送要多入口 | 没有统一 Transport 难扇出 |

## 契约

```python
class Transport(Protocol):
    name: str                          # ws / http / webhook / queue
    async def send(self, endpoint: Endpoint, msg: Message) -> str: ...
    async def health(self) -> TransportHealth: ...
```

- `Endpoint`：`user_id` / `endpoint_id` / `channel` / `device_id`
- `Message`：`text` / `images` / `at` / `voice` / `quote`
- `TransportRegistry`：按 endpoint/channel 选 transport；统一 `send()`

## 关键设计

- **唯一出口**：所有发送走 Transport；禁止业务直连 `ws.send`。
- **默认 WS**：现有 `egress/outbound.py` 的逻辑原样包进去，行为零变化。
- **重试/队列**：transport 内做；写消息不重试，主动消息可重试。
- **多入口**：Transport 不决定「发给谁」；v31 多端推送（原 v28）负责扇出。
- **多用户**：endpoint 带 `user_id`；跨用户发送直接拒绝。
- **可观测**：`!transport` 显示 transport、在线、队列、失败、重连。

## 验收

```bash
!transport          # transport / 在线 / 队列 / 失败
```

- 切假 transport：单测不碰 WebSocket。
- 现有 QQ/Web 发送行为不变，回归全绿。
- 新增 HTTP transport：只写适配器 + 配置，不改业务。

## 不做

- 不引入消息队列/消息总线。
- 不让 transport 拼业务文案/查记忆。
- 不做跨用户广播。

## 风险

| 风险 | 处理 |
|---|---|
| 包装改变发送时序 | 先包一层，保留旧开关；基线测试 |
| 重试导致重复发送 | 幂等 key + 客户端去重 |
| 队列无限涨 | 有界队列 + TTL + 丢弃计数 |
| 绕开出站口 | CI grep 禁止业务 `ws.send` |
