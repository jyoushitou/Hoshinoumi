# v31 系列 · 记忆层契约与 native adapter

> 核心：把现有 BM25 / 仓储包成 `MemoryStore` / `Retriever` 实现，第三方接入在 v32。
> BM25 是核心 native，不注册为插件。

```python
class MemoryStore(Protocol):
    async def add(self, user_id: str, item: dict) -> str: ...
    async def delete(self, user_id: str, item_id: str) -> None: ...


class Retriever(Protocol):
    async def search(self, user_id: str, query: str, top_k: int) -> list[dict]: ...
```

## 本层插件接口约束（v27 总纲）

> 跨版本总纲：[INTERFACE-PLAN-v27-v44.md](../INTERFACE-PLAN-v27-v44.md)

- 本版只开放**记忆层**接口，不把其他层一起搬。
- 能力名：`memory.store.<name>@1 / memory.retriever.<name>@1`。
- 核心 native（SQLMemoryStore / BM25）保持 native，**不实现 PluginManifest，不进入插件表**。
- 第三方实现本层 Protocol，通过 v27 `PluginRegistry` 注册。
- 业务只依赖 Protocol；`get()` 拿不到时回落核心 native。
- 敏感资源走 v27 权限三档（0 拒绝 / 1 询问 / 2 允许），默认 1。
- 插件任务、线程池、DB 连接池由 v27 context 提供，不允许裸 `create_task` / 裸连库。
- 插件失败写 `plugin_errors`，连续失败自动停用。
- 插件 DDL 走 `migrations/`，只支持 MySQL/SQLite，表前缀 `plugin_<name>_`。
- 热更采用 worker 进程级快照；已启用插件在新 worker 自动加载。

## 关键约束

- BM25 是核心 native，不注册为插件。
- 所有接口强制带 `user_id`，禁止跨用户。
- 第三方检索失败/超时由 v43 回退 BM25。
- 核心记忆只能启动前通过 `features.json` / `NAO_FEATURES` 关闭。

## v31.3 · 帮助系统升级

### 问题

```text
build_cmd_help() 是手写静态列表
新命令 plugin/book/history/gw/relation 等没进去
help_text 大多为空，无法查单个命令
命令数量变化后帮助会过期
```

### 规则

```text
!help               按分类列出全部注册命令
!help all           完整列表（含说明）
!help <command>     单个命令详情
!help <未知命令>     返回“没有这个命令”
```

分类：

```text
基础 / 记忆 / 媒体 / 日常 / 阅读 / 配置 / 插件 / 运维
```

实现：

- `build_cmd_help()` 动态读取 `registry.COMMANDS`。
- 说明优先用 `Command.help_text`，没有就用函数 docstring 第一行。
- 分类映射集中维护，未知命令归“其他”。
- 不再手写命令文本。
- API `/api/help` 继续复用同一函数。

### 验收

```text
1. !help 包含 plugin / book / history / gw
2. !help plugin 返回安装/审批/列表说明
3. !help all 的命令数与 registry 一致
4. 新增命令不需要改帮助文本
5. 未知子命令不崩
```
