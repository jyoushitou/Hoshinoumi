# v31 系列 · 微信接入（OpenClaw / 龙虾）

> 前置：v17（调度器 + 出站层）｜预估 8 天｜**四个次版本**

## 目标

除了 QQ，她也能在微信里说话——**同一个人格、同一份记忆**，只是换了个入口。

```
QQ 里：  你：今天好累
微信里： 你：今天好累
        她：……（她记得 QQ 里那句「加班到十点」）
```

## 通道选型（已定）

| 通道 | 能力 | 限制 | 结论 |
|---|---|---|---|
| **OpenClaw（龙虾，个人微信）** | 单聊、图片、主动发 | 扫码授权；**违反微信 ToS，有封号风险** | ✅ **本版采用** |
| 企业微信 | 合规、可主动推 | 需企业主体 | ❌ 本版不做 |
| 微信公众号 | 被动回复 | 48 小时窗口、5 秒超时 | ❌ 本版不做 |

### 为什么是 OpenClaw

- 开源（[dingxiang-me/OpenClaw-Wechat](https://github.com/dingxiang-me/OpenClaw-Wechat)），扫码即可授权
- 手机端会弹「将新的 OpenClaw 连接到微信」，不需要做协议逆向
- 支持单聊、白名单控制

### 前提与风险（知情确认）

| 项 | 说明 |
|---|---|
| 微信版本 | 需要 **8.0.69+**，低版本扫码会失败 |
| 合规风险 | 属个人微信自动化，**违反微信服务条款** |
| 封号后果 | 账号可能被限制/永久封禁，**连带支付与社交** |
| 稳定性 | 协议或授权方式变动即失效，无官方支持 |

> **结论：只用小号跑。** 主号绝不接入。

## 红线（写死在代码里）

| 红线 | 原因 |
|---|---|
| **只用小号** | 封号不牵连主号 |
| 只响应白名单 | 不回应陌生人，降低被举报概率 |
| 不加好友、不进群、不发朋友圈、不群发 | 每一项都是高危动作 |
| 频率上限：≤10 条/分钟、≤500 条/天 | 超频是最明显的机器人特征 |
| 出现验证码/风控提示 → 立即停用并告警 | 硬刹车，不重试、不绕过 |
| 不保存微信密码，只存会话令牌 | 令牌失效重扫码即可 |

# v31.0.0 · 通道抽象层

## 为什么必须先抽象

现在所有发送都写死 QQ：

```python
ws.send(json.dumps({"action": "send_private_msg", ...}))   # send.py
```

微信的消息结构、发送方式、限速完全不同。**先抽接口，再接第二个通道**，否则会到处 `if channel == ...`。

## 接口

```python
class Channel(Protocol):
    name: str                       # "qq" / "wechat"

    async def send(self, target: str, msg: Message) -> str:
        """发一条消息，返回平台消息 id"""

    def supports(self, feature: str) -> bool:
        """at / image / voice / poke / recall / quote"""
```

统一的 `Message`：

```python
@dataclass
class Message:
    text: str = ""
    images: list = field(default_factory=list)
    at: str | None = None
    voice: bytes | None = None
    quote: str | None = None
```

## 迁移步骤

| 步 | 内容 |
|---|---|
| 1 | `channels/base.py`：接口 + Message |
| 2 | `channels/qq.py`：把现有 `send.py` 包一层 |
| 3 | `egress/outbound.py`：按 target 前缀选通道（`qq:` / `wx:`） |
| 4 | 现有 QQ 行为**零变化** |

**关键验收**：QQ 通道迁移完，v17 的基线测试必须全绿——否则说明抽象层改变了行为。

# v31.0.1 · OpenClaw 适配器

## 第一步是调研，不是写代码

OpenClaw 的接入形态还没确认，v31.0.1 的第一件事是把它搞清楚：

| 待确认 | 影响 |
|---|---|
| 接入方式：本地 HTTP？WebSocket？轮询？ | 决定我们是做 webhook 还是主动拉 |
| 消息结构：文本 / 图片 / 引用 / 群消息长什么样 | 决定解析层 |
| 发送接口：文本、图片、@、撤回分别怎么调 | 决定 `Channel.send` 实现 |
| 授权产物：扫码后拿到的 token 与账号标识 | 决定配置格式 |

拿到这些再动手，**别按猜的结构写一版然后全推倒**。

## 设计假设（待验证）

```
OpenClaw 本地服务（HTTP）
   ├─ 收：我们挂一个 HTTP 端点接收推送；若只能轮询则 1 秒拉一次
   └─ 发：POST 文本 / 图片
```

## 消息映射

| OpenClaw | 我们的 Message |
|---|---|
| text | `text` |
| image | `images[]` |
| quote / reply | `quote`（作为上下文注入，不当作引用回复） |
| 群消息 | 本版**不接**（只做单聊） |

## 配置

`data/wechat.json`（已在 `.gitignore`）：

```json
{
  "enabled": true,
  "endpoint": "http://127.0.0.1:xxxx",
  "token": "...",
  "self_id": "wxid_xxx",
  "whitelist": ["wxid_master"]
}
```

- 日志只打 `self_id` 前 4 位，不打印 token
- 掉线自动重连，**重连失败不影响 QQ**

# v31.0.2 · 身份统一

## 问题

QQ 和微信是两套 ID，不统一的话同一个人两边记忆、亲密度、日程全分开。

## 方案：绑定码

```
你（QQ）： !bind
她：     绑定码 A7K2（10 分钟内有效）

你（微信）：绑定 A7K2
她：     绑定成功，以后两边记忆是同一份
```

| 项 | 说明 |
|---|---|
| 绑定码 | 6 位，10 分钟有效，一次性 |
| 存储 | `events(kind='binding')`：主 ID ↔ 副 ID |
| 合并策略 | 记忆保留在主 ID，副 ID 读写都映射到主 ID |
| 解绑 | `!unbind` |

```python
def resolve_identity(channel: str, uid: str) -> str:
    main = bindings.get(f"{channel}:{uid}")
    return main or f"{channel}:{uid}"
```

**未绑定的人**：用自己的通道 ID 单独存，互不干扰。

# v31.1.0 · 能力矩阵与降级

| 能力 | QQ | 微信 | 不支持时怎么办 |
|---|---|---|---|
| 发文本 | ✅ | ✅ | — |
| 发图片 | ✅ | ✅（先上传） | 失败则只发文本 |
| @ 人 | ✅ | ❌ | 降级为纯文本「@名字」 |
| 语音 | ✅ | ⚠️ 待验证 | 不支持就不发语音 |
| 撤回 | ✅ | ⚠️ 待验证 | 不支持就跳过撤回机制 |
| 戳一戳 | ✅ | ❌ | 直接禁用 |

**原则**：能力缺失是**降级**，不是报错。她不会因为微信没有 @ 就不说话。

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `wechat_enabled` | false | 总开关 |
| `wechat_endpoint` | 空 | OpenClaw 本地地址 |
| `wechat_token` | 空 | 会话令牌 |
| `wechat_whitelist` | 空 | 允许对话的 wxid 列表 |
| `wechat_rate_per_min` | 10 | 每分钟发送上限 |
| `wechat_rate_per_day` | 500 | 每天发送上限 |
| `bind_ttl_min` | 10 | 绑定码有效期 |

## 验收

- [ ] QQ 通道迁移后，v17 基线测试全绿
- [ ] 微信能收发纯文本
- [ ] 微信能收图片并进入视觉链路

- [ ] 微信掉线时 QQ 完全不受影响
- [ ] 出现风控提示 → 自动停用并告警

## 风险与处理

| 风险 | 处理 |
|---|---|
| 账号被封 | 只用小号；封了换号，数据在库里不丢 |
| 协议变动导致适配器失效 | 适配器独立，坏掉只影响微信通道 |
| 扫码授权过期 | 检测到 401 → 停用并提示重新扫码 |
| 微信消息结构差异 | 解析层兜底：认不出就存原文，不崩 |
| 频率过高被风控 | 发送层统一节流（10/分钟） |
| **误把主号接入** | 配置里校验 `self_id` 不等于主号 QQ 对应的微信 |

## 与旧方案的关系

早先的微信规划走的是**企业微信 + 公众号**，并明确写了「不碰个人微信 hook」。
本版按实际需求改走 **OpenClaw（个人微信）**：旧方案与旧红线一并作废，
替代为本页顶部的「红线」一节——风险由使用者承担，代码层面只保证：
**小号、白名单、频率上限、风控即停**。
