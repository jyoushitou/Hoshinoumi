# v14 · 打磨与余量

> 前置：v11（感官）｜ 预估 3 天
> 条目来源：[V14-后续清单.md](../V14-后续清单.md)（A/B/C 分组，v14+ 自己的编号体系）

## 目标

两件事：**把人设变成可替换的角色卡**，以及把已上线功能的频率与边界调顺。

## 包含单元

| 单元 | 条目 | 内容 |
|---|---|---|
| U18 | B1 B3 | 发图与语音择时：不是每条都带图和语音 |
| U19 | B2 | 主动频率自适应：连续没回应就降频 |
| U20 | C1 C2 C3 | 解析与记忆精度收尾 |
| U21 | A1 A2 | 人设卡片化：人设、标签、生活模板、状态基线全部从角色卡读 |

## 实施步骤

### U21 人设卡片化（v14 的主菜）

1. 建 `personas/nao/` 目录，把现在硬编码的东西搬进去：

   | 现在的位置 | 搬到 |
   |---|---|
   | `ai/persona.py` 的 `LOCAL_SYSTEM_PROMPT` | `personas/nao/prompt.txt` |
   | `personality_supplement.txt` | `personas/nao/supplement.txt` |
   | `CLIP_IMAGE_TAGS` | `personas/nao/tags.txt` |
   | `life/events.py` 的 105 条模板 | `personas/nao/life.txt` |
   | `life/state.py` 的 `BASE` | `personas/nao/state.json` |
   | 硬编码称呼「主人」 | 卡里的 `master_title` 字段 |

2. 新增 `ai/persona_loader.py`：按 `NAO_PERSONA` 环境变量 → 配置路径 → 默认 `personas/nao/` 的顺序找卡
3. 任一项缺失就回退内置默认值，**加载失败不崩**（和现在 supplement 的处理一致）
4. 提供一个空白模板 `personas/_template/`，带注释说明每个字段写什么

### 其余单元

5. **发图择时（B1）**：AI 给了图片关键词后再过一道概率——30% 配图，同一人 10 分钟冷却一张，群里 20%，心情差 ×0.5
6. **语音择时（B3）**：与 B1 同一套概率闸门
7. **主动频率自适应（B2）**：连续 3 次没回应 → 基础概率 ×0.5；有回应每次 +10% 回升
8. **解析与精度（C1 C2 C3）**：日程支持「下个月/月底/这周末」；记忆指代词只在检索为空时提示；CLIP 残留清理

## 验收

- [ ] 只改 `personas/xxx/`，不改一行代码就能换掉整个人设
- [ ] 删掉某张卡里的 `life.txt`，启动不报错（回退默认）
- [ ] 连续 10 条回复里，配图不超过 3 条
- [ ] 主动 3 次没被理，第 4 次概率明显下降

## 风险

- **人设搬迁容易漏**：模板里还有 `{now}` `{tone}` `{profile}` 等占位符，搬的时候要一起带上，漏一个就 `.format()` 报错
- **默认值必须完整**：别人 clone 下来不配任何东西也要能跑，所以内置默认卡要保留一份在代码里
- 发图概率调低后，「她会发图」的存在感会变弱，先设 30% 跑一周看
