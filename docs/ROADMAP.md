# 发布路线图（次版本 / 小版本全拆）

> 每个 `x.y` 是一个**次版本**（一组相关能力），每个 `x.y.z` 是一个**可单独发布的小版本**。
> 小版本 = 一次能做完、能验证、能回滚的改动。

## 收尾约定

**每个大版本的最后一个次版本，统一用来修小 bug 和技术债**，不堆新功能。
例：v17.6（收尾修 bug）、v18.1（QQ 空间收尾）、v19.1（视频收尾）、v20.3（运维收尾）、v21.1（嵌入式收尾）。

## 依赖图

```
v17.0.x ──→ v17.1.x ──→ v17.2.x ──→ v17.3.x
                                        │
                    ┌───────────────────┼───────────────────┐
                    ↓                   ↓                   ↓
            v18.0.x → v18.1.x     v19.0.x → v19.1.x     v21.0.x → v21.1.x
            （QQ 空间）             （视频）              （嵌入式）
                                        │
                                        ↓
                                  v20.0.x → v20.1.x → v20.2.x → v20.3.x
                                  （运维通道）
```

- **v18 / v19 / v21 互不依赖**，v17 完成后可并行
- v20（运维）依赖 v17.2 的出站口与 v17.5 的表结构
- v20 内部严格串行（只读 → agent → 写 → 回滚）

## 发布节奏建议

| 周期 | 发什么 |
|---|---|
