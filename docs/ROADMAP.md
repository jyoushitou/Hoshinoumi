# 发布路线图（次版本 / 小版本全拆）

> **协作规矩（2026-11 起）**
>
> 1. **任何新功能，先写进 `docs/versions/vN.md` 的开发计划**，不先写代码
> 2. 计划里写清：要做什么、验收标准、涉及文件、风险
> 3. 只在**当前版本号**内迭代；已发布版本冻结，不回头改
> 4. 一个功能一个功能做，每做完一个停下来确认
> 5. 新发现的 bug 记进**当前开发版本的**「遗留问题」，不往已发布版本塞
> 6. 版本号**只增不减**；不插入重排已发布的版本。
>    例外：2026-11 多次插入（**v20 多用户**、**v24 插件管理**、**v25–v31 七层插件接口**、**v33 多端推送**、**v37 命令收敛**、**v55 嵌入式前端**）；
>    当前编号以本页表格为准，不再保留旧编号。


> 每个 `x.y` 是一个**次版本**（一组相关能力），每个 `x.y.z` 是一个**可单独发布的小版本**。
> 小版本 = 一次能做完、能验证、能回滚的改动。

## 多用户基线（v20 起，所有后续版本必须遵守）

> v18 及以前是单主人；v19 先做架构与对话底座；从 **v20** 起所有功能按**多用户**设计，
> 不再假设 `MASTER_QQ` 是唯一用户。

| 概念 | 定义 |
|---|---|
| `user_id` | 账号/租户：一个人类用户（Web/桌面/手机登录，或 QQ 私聊的人） |
| `identity` | 绑定到 user 的渠道身份：QQ 号 / Web 账号 / 桌面设备 / 手机 |
| `target_id` | 会话：私聊 = `user_id`；群 = 群号；Web = `thread_id` |
| `role` | `owner`（当前主人，最高权限）/ `admin` / `user` |

**硬规则**：

1. 每张业务表、每个查询、每个 API 都带 `user_id`；禁止跨用户读。
2. `MASTER_QQ` 只作为 owner 的 identity，不再是唯一用户。
3. 群聊：`user_id` = 群所属租户，`speaker_id` = 具体发言人；事实按 speaker 隔离。
4. 每个版本验收必须包含「两个用户互相看不到对方数据」。
5. 连接池共享，按 user 做配额；不为每个用户建池。
6. 存量数据迁移时全部回填到 owner。

**每个大版本开工前对照**：

- [ ] 新表有 `user_id`，查询带 `user_id`
- [ ] API 从 token/网关取 `user_id`，不信客户端
- [ ] UI 有登录态，换账号能切数据
- [ ] 验收含「两个用户互不可见」

## 依赖图

```
v17 执行模型 ──→ v18 记忆/情绪 ──→ v19 架构 + 对话底座
                                      │
                                      ▼
v20 网关核心 ──→ v21 网关鉴权 ──→ v22 网关安全 ──→ v23 多用户
                                                       │
                                                       ▼
v25 模型 ──→ v26 记忆 ──→ v27 通道 ──→ v28 工具 ──→ v29–v31 存储/调度/出站
                                      │
                                      ▼
v32 默认链路 ──→ v33 多端推送 ──→ v34 本机服务化 ──→ v35 DSH ──→ v36 Qoder ──→ v37 命令收敛
                                                                                    │
                                                                                    ▼
v38 Web ──→ v39 Linux / v40 Windows / v41 手机 / v42 手机独立 / v55 嵌入式
v18 ──→ v43 QQ 空间        v44–v47 运维（独立串行）
v18 ──→ v48–v49 视频        v50 微信 / v51–v52 语音视频
v22 + v34 ──→ v53 微服务接入 ──→ v54 systemd ──→ v55 嵌入式前端
```

- **v19 不依赖多用户**：先做架构、对话消息表、`!history`；v20–v22 先做网关，v23 再做账号隔离。
- **v20 核心**只做代理；**v21** owner 鉴权；**v22** 限流/审计/TLS。
- **v23 多用户**再加 `users`/`user_id` 隔离，并升级网关登录。
- **v25–v37** 用 v23 的多用户 API、走 v22 网关；v25–v31 是接口底座；v32 是默认链路；v33 是主动消息扇出；v34 是本机服务；v35/v36 是 IDE 插件；v37 收 QQ 命令。
- **v38–v55** 按域独立推进；Web/桌面/手机/嵌入式都复用 v33 的 hub 和 v34 的本机服务，跨域只共享 `memories` / `conversation_messages`。
