# 发布路线图（次版本 / 小版本全拆）

> **协作规矩（2026-11 起）**
>
> 1. **任何新功能，先写进 `docs/versions/vN.md` 的开发计划**，不先写代码
> 2. 计划里写清：要做什么、验收标准、涉及文件、风险
> 3. 只在**当前版本号**内迭代；已发布版本冻结，不回头改
> 4. 一个功能一个功能做，每做完一个停下来确认
> 5. 新发现的 bug 记进**当前开发版本的**「遗留问题」，不往已发布版本塞
> 6. 版本号**只增不减**；不插入重排已发布的版本


> 每个 `x.y` 是一个**次版本**（一组相关能力），每个 `x.y.z` 是一个**可单独发布的小版本**。
> 小版本 = 一次能做完、能验证、能回滚的改动。

## 收尾约定

**每个大版本的最后一个次版本，统一用来修小 bug 和技术债**，不堆新功能。

## 依赖图

```
v17.0.x ──→ v17.1.x ──→ v17.2.x ──→ v17.3.x ──→ v17.5
                                        │
   v18（情感的深刻度：记忆分量 + 情绪跨天）
        │  （是下面所有「表达类」系列的底座）
        ├──→ v20（QQ 空间）
        └──→ v19（App / Web 客户端）
        │
        └──→ v24（视频·B站）──→ v25（视频·抖音）
                                        │
v20（bash）──→ v21（agent）──→ v22（有限写）──→ v23（可写体系）
                                        │
                                        ↓
                          v26（微信接入）→ 与媒体链路互不依赖
                                        │
                            v27 语音 → v28 视频
                                        │
                            v29 systemd → v30 LITE/ARM
```

- **v18** 是记忆/情绪的底座：v19（公开表达）、v24/v25（看过什么）都靠它
- **v19（客户端）/ v20（QQ 空间）/ v25（视频）** 互不依赖，v17+v18 完成后可并行
- **v20 → v21 → v22 → v23 严格串行**（风险逐级放开，不能跳）
- **v27 语音**依赖 v26 与 v24 稳定后的媒体链路；**v28 视频**依赖 v27
- **v29 常驻**依赖 v17.5 的日志与观测；**v30 部署**依赖 v29
