# 从 v18.4 升级到 v18.20.0

> 适用：服务器上已经是 v18.4（或 v18.5–v18.16），要升到 **v18.20.0**。
> 核心变化：v18.17 把旧 `events` 基表迁进 `memories` 并改名，**必须先迁移数据库，再启动新代码**。
> 迁移不可逆；回滚要靠升级前的数据库备份。

## 0. 先备份（最重要）

停掉机器人后再备份，避免写入一半：

```bash
cd ~/NapCat-Pyhon
# QQ 里发 !exit，或：sudo systemctl stop nao-bot

# MySQL：
mysqldump -h 127.0.0.1 -u 你的用户 -p 你的库名 > ~/nao-before-v18.20.sql

# SQLite：
sqlite3 data/nao.db ".backup '$HOME/nao-before-v18.20.db'"

# 配置和角色卡一起打包
tar czf ~/nao-config-before-v18.20.tar.gz \
  config.local.json personas/ data/ 2>/dev/null || true
```

检查备份文件非空：

```bash
ls -lh ~/nao-before-v18.20.*
```

## 1. 取 v18.20.0 代码

把 `release/nao-v18.20.0.bundle` 传到服务器项目根目录，然后：

```bash
cd ~/NapCat-Pyhon
git status                 # 应该没有未提交的代码改动；config/data 是 gitignore 的
git fetch ./nao-v18.20.0.bundle \
  refs/heads/main:refs/remotes/bundle/main \
  refs/tags/v18.20.0:refs/tags/v18.20.0
git checkout v18.20.0
git describe --tags        # 应显示 v18.20.0
```

如果 `git status` 有本地代码改动，先 `git stash` 或备份，不要硬 checkout。

## 2. 装依赖

```bash
cd ~/NapCat-Pyhon
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -U pip
python3 -m pip install -r requirements.txt
```

`deploy/nao-bot.service` 默认用 `/usr/bin/python3`。如果用 venv，把 service 里的：

```ini
ExecStart=/usr/bin/python3 /home/jyoushitou/NapCat-Pyhon/run.py
```

改成：

```ini
ExecStart=/home/jyoushitou/NapCat-Pyhon/.venv/bin/python /home/jyoushitou/NapCat-Pyhon/run.py
```

## 3. 迁移数据库（一条命令，幂等）

```bash
python3 scripts/migrate.py --apply
```

它会依次做：

1. 建缺表（含 `cron_overrides`）；
2. 给 `memories` 补 `due_date` / `hit_count`，把 `kind` 放宽为 `VARCHAR`；
3. 补 `cron_tasks.rule/timing` 并迁移场景规则；
4. 把 `events` 全量复制进 `memories`，旧表改名 `events_old_YYYYMMDD`，建只读视图 `events`；
5. 补索引、导入内置场景。

想先看会改什么，可以不带 `--apply`：

```bash
python3 scripts/migrate.py
```

> `migrate.py` 可以重复跑：已迁过的库只会补缺，不会重复搬数据。

**迁移之后不要再用 v18.4 代码启动**，旧代码不认新结构；回滚见第 7 节。

## 4. 启动前自检

```bash
python3 scripts/preflight.py
```

退出码必须是 0。重点看：

- 数据库连接
- 表结构 / `memories` 列
- 环境变量（`NAO_*`）
- 端口 3001 / 60908 没被占用

## 5. 启动

```bash
# 前台先跑一次，确认能起来
python3 run.py
```

看到 WebSocket 监听、NapCat 连上后，在 QQ 里发：

```text
!version
!hooks
!cron
```

确认：

- `!version` 显示 `18.20.0`
- `!hooks` 能看到定时任务已挂载
- `!cron` 里晚餐 16:40、睡觉按明天工作日 23:00/23:30、起床工作日 7:30/周末 8:00、13:30 叫午睡起床
- `!backup run` 能生成备份（MySQL 要装 `mysqldump`）
- `!exit` 能在 3 秒左右退出；5 秒没退会触发看门狗

确认无误后切 systemd：

```bash
sudo cp deploy/nao-bot.service /etc/systemd/system/nao-bot.service
sudo systemctl daemon-reload
sudo systemctl enable --now nao-bot
sudo systemctl status nao-bot
journalctl -u nao-bot -f
```

## 6. 升级后验证清单

- [ ] `!version` = `18.20.0`
- [ ] `!hooks` 定时钩子数量与预期一致
- [ ] `!cron` 时间规则正确
- [ ] 引用一条旧消息，能带出原话或明确降级，不再卡 8 秒
- [ ] `!stats` 有定时行、缓存行、近 1 分钟完成数
- [ ] `!backup run` 生成 `backups/nao-YYYY-MM.db` 或 `.sql.gz`
- [ ] `!exit` 3 秒内回 shell
- [ ] 旧数据还在：`!memory`、日程、日记、书架各抽查一条

## 7. 回滚

代码回滚：

```bash
sudo systemctl stop nao-bot
cd ~/NapCat-Pyhon
git checkout v18.4.0
```

**但数据库不会自动回滚**。v18.17 已经改了表结构，必须恢复备份：

```bash
# MySQL：
mysql -h 127.0.0.1 -u 你的用户 -p 你的库名 < ~/nao-before-v18.20.sql

# SQLite：
cp ~/nao-before-v18.20.db data/nao.db
```

然后再启动 v18.4。没有备份就不要回滚数据库。

## 8. 常见问题

**`migrate_v18.py` 说没有 memories 表**  
先跑 `python3 scripts/setup.py`，再重新跑迁移预览。

**迁移后 `events` 查不到数据**  
`events` 现在是视图，映射 `memories`。用 `SELECT * FROM memories` 查；旧表在 `events_old_YYYYMMDD`。

**启动报 `Unknown column`**  
迁移没跑完或跑错库。确认 `config.local.json` 连的是同一个库，重跑 `python3 scripts/migrate_v18.py --apply`（幂等，已迁移会跳过）。

**端口被占用**  
`ss -lntp | grep -E '3001|60908'`，先停旧进程再启动。

**MySQL 备份失败**  
装 `mysqldump`（Debian：`sudo apt install mysql-client`），并确认 `config.local.json` 的 `db.*` 有权限。
