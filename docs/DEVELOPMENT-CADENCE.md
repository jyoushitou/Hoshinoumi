# 开发节奏约定

> 2026-11-14 起生效。适用于 v22 之后的每个大版本。

## 一个版本的标准节奏

```text
子版本开发
  ↓
冻结 + 验收（测试全绿 / 文档更新）
  ↓
1 天试运行
  ↓
约 1 天：下个大版本启动 + 新版本介绍视频
  ↓
进入下个大版本子版本开发
```

### 1. 子版本开发

- 每个次版本独立实现、验证、提交。
- 不把多个次版本混进一个提交。
- 验收以 `scripts/run_tests.py` + 对应版本验收项为准。

### 2. 冻结与验收

- 冻结后只修阻断问题，不加新功能。
- 更新版本文档、README 状态、迁移说明。
- 试运行前必须能回滚。

### 3. 1 天试运行

- 真实环境跑 1 天，重点看：启动、聊天、定时、日志、错误恢复。
- 试运行期间发现的问题记入当前版本文档。
- 只修阻断/安全问题；普通改进排到下个版本。
- 试运行结束给结论：通过 / 带条件通过 / 回滚。

### 4. 约 1 天：下个大版本启动 + 介绍视频

这 1 天不替代下个大版本的完整开发，只做三件事：

1. **下个大版本启动**：确认目标、拆次版本、排期、技术预研。
2. **新版本介绍视频**：3–5 分钟，演示本版本新增功能。
3. **试运行问题归档**：把问题分成 hotfix / 下版本 / 不修。

视频要求：

- 画面演示真实功能，不用纯 PPT。
- 至少覆盖：新增能力、使用方式、和上一版的区别。
- 不出现 token、secret、QQ 号、数据库密码。
- 输出到 `release/videos/REC-v<版本>-intro.mp4`（不进 git）。
- 视频发布前过一遍“无敏感信息”检查。

## 当前执行位置

|---|---|---|
| v22 | 试运行 | 试运行 1 天 → v23 启动 + v22 介绍视频 |
| v23 | 未开始 | 按 v23 子版本开发 |

## 例外

- 安全漏洞/数据丢失：立即 hotfix，不等试运行结束。
- 试运行无法进行（环境不可用）：记录原因，顺延试运行，不直接宣布通过。
- 版本介绍视频可以晚于“下个大版本启动”，但不能晚于下个大版本首次发布。
