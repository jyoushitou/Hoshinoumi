## 3. R 轨道：抽象画在哪

先分清什么会变。

| 会变 | 现状 | 抽象成 |
|---|---|---|
| 模型（DS → 豆包 → 以后换） | 两个几乎重复的函数 | `ChatModel` 端口 |
| 接入端（NapCat → 别的） | 业务代码直接摸 `ws` 对象 | `Transport` 端口 |
| 存储（MySQL → 别的） | 业务层到处写 SQL | `Repository` 端口 |
| 检索（关键词 → 向量） | `LIKE` 散在各处 | `Retriever` 端口 |
| 时间（测试要能伪造） | 到处 `datetime.now()` | `Clock` 端口 |

**不会变的**：对话流程、记忆召回、状态演化、关系推进——留在 `domain/`，不依赖任何外部库。

### 3.1 七个端口

```python
class ChatModel(Protocol):
    supports_vision: bool
    async def complete(self, req: ChatRequest) -> ChatReply: ...

class Transport(Protocol):
    async def send(self, target: Target, segs: list[Segment]) -> None: ...

class MemoryStore(Protocol):
    async def add(self, item: MemoryItem) -> None: ...
    async def search(self, q: Query, k: int = 5) -> list[MemoryItem]: ...

class Embedder(Protocol):
    def embed(self, texts: list[str]) -> "np.ndarray": ...   # (n, d) 矩阵

class Repository(Protocol): ...
class Retriever(Protocol): ...
class Clock(Protocol):
    def now(self) -> datetime: ...
```

三条铁律：领域层只 import ports；适配器实现端口、不互相调用；`main.py` 是唯一组装点。

### 3.2 依赖方向

```
adapters（可变）
  NapCat WS │ aiohttp │ MySQL │ bge │ TTS
        ↓ 实现
ports（稳定）
  ChatModel │ Transport │ MemoryStore │ Clock
        ↑ 依赖
domain（纯逻辑）
  对话 │ 记忆 │ 状态 │ 关系
```

### 3.3 目录

```
botv/
├── ports/        # 纯协议 + dataclass，零依赖
├── domain/       # 纯逻辑，无 IO
├── adapters/
│   ├── model/    # deepseek / doubao / vision / router
│   ├── transport/# qq_ws
│   ├── store/    # mysql_* / schema
│   └── speech/   # edge_tts
├── commands/     # 注册表 + 分文件
├── server/       # ws / http_api（薄壳）
└── main.py       # 组装
```

### 3.4 克制

> 只在「有两个实现」或「需要测试替身」的地方抽接口。

`ChatModel` 抽（已有两个模型）；`PromptBuilder` 不抽（永远一个实现）。

```

F1 ~ F7   ← 先止血，约 2 天
```
