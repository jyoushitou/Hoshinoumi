# 存储后端：备份与恢复（v17.11 U5）

> 两种后端各有各的备份方式。**换后端之前必须备份**。

## 先确认当前用的是哪个

```bash
python3 - <<'PY'
import sys; sys.path.insert(0, '.')
from botv.core.settings import storage_backend, sqlite_path
print("后端：", storage_backend())
print("SQLite 文件：", sqlite_path())
PY
```

启动日志里也有一行：`[存储] 使用后端：sqlite（文件数据库）`。

## MySQL

### 备份

```bash
# 整库（结构 + 数据），带压缩
mysqldump -h 192.168.0.50 -u TomoriNaoBot -p \
  --single-transaction --quick --default-character-set=utf8mb4 \
  TomoriNaoBotData | gzip > backup-$(date +%F).sql.gz

# 只备份表结构（换库/建空库用）
mysqldump -h 192.168.0.50 -u TomoriNaoBot -p --no-data \
  TomoriNaoBotData > schema-$(date +%F).sql

# 只备份某几张表（改动前的最小备份）
mysqldump -h 192.168.0.50 -u TomoriNaoBot -p \
  TomoriNaoBotData memories bot_states relations habits reading_progress cron_tasks \
  > tables-$(date +%F).sql
```

**检查备份不是空的**：

```bash
ls -lh backup-*.sql.gz
gunzip -c backup-$(date +%F).sql.gz | grep -c "INSERT INTO"
```

### 恢复

```bash
# 整库恢复（会覆盖同名表）
gunzip -c backup-2026-11-11.sql.gz | mysql -h 192.168.0.50 -u TomoriNaoBot -p TomoriNaoBotData

# 只恢复某张表（先删再导）
mysql -h 192.168.0.50 -u TomoriNaoBot -p TomoriNaoBotData -e "DROP TABLE IF EXISTS cron_tasks"
mysql -h 192.168.0.50 -u TomoriNaoBot -p TomoriNaoBotData < tables-2026-11-11.sql
```

**注意**：`TomoriNaoBot` 用户可能没有 `PROCESS` 权限，`mysqldump` 会警告但**不影响数据**（v17.4 实测见过）。

## SQLite

### 备份

```bash
# 推荐：用 sqlite3 的 .backup（在线一致快照，WAL 模式下也安全）
sqlite3 data/nao.db ".backup 'data/nao-backup-$(date +%F).db'"

# 没有 sqlite3 命令行时，直接拷文件（先停程序）
cp data/nao.db data/nao-backup-$(date +%F).db
```

**别用 `cp` 拷正在写的库**：WAL 模式下可能拷到半截。
要么停程序，要么用 `.backup`。

### 恢复

```bash
# 停程序 → 换文件 → 启动
mv data/nao.db data/nao.db.bad
cp data/nao-backup-2026-11-11.db data/nao.db
python3 run.py
```

### 顺带检查

```bash
sqlite3 data/nao.db "PRAGMA integrity_check;"     # 应输出 ok
sqlite3 data/nao.db ".tables"                     # 22 张表
```

## 换后端（MySQL ↔ SQLite）

**顺序不能颠倒**：

```bash
# 1. 备份当前后端（上面 MySQL 或 SQLite 对应那节）
#    备份失败就停，别往下走

# 2. 互导（默认 dry-run，只看不写）
python3 scripts/migrate_backend.py

# 3. 真搬
python3 scripts/migrate_backend.py --apply

# 4. 校验行数（脚本已打印，两边应一致）
#    不一致就回滚：删掉目标库/表，回到第 1 步

# 5. 改配置
#    config.local.json: "db": { "backend": "sqlite" }   ← 或 "mysql"
#    或者用环境变量 NAO_DB_BACKEND=sqlite

# 6. 启动并验证
python3 run.py
!version
!stats
```

## 回滚

| 情况 | 怎么做 |
|---|---|
| 刚换到 SQLite 出问题 | 改回 `"backend": "mysql"`，重启（MySQL 里的数据没动过） |
| 已经写了新数据 | 先 `migrate_backend.py --to mysql --apply` 把新数据搬回去，再改配置 |
| 数据搬坏了 | 从第 1 步的备份恢复 |

**关键**：换后端时**原后端的数据不要删**，至少留一周。

## 自动备份（建议加进 cron）

```bash
# 每天 04:30 备份，保留 14 天
30 4 * * * sqlite3 ~/NapCat-Pyhon/data/nao.db ".backup '/home/jyoushitou/backup/nao-$(date +\%F).db'" && \
           find /home/jyoushitou/backup -name 'nao-*.db' -mtime +14 -delete
```

MySQL 同理，把 `mysqldump ... | gzip > ...` 放进 cron。

## 与日志保留的关系

| 数据 | 保留 | 清理方式 |
|---|---|---|
| TXT 日志 | 180 天 | `txtlog.cleanup()` 自动删 |
| 数据库 `logs` 表 | 180 天 | `purge_db_logs()` 自动删 |
| **备份文件** | **你自己定** | cron 里 `find -mtime +N -delete` |

备份不会自动删——别让 `/backup` 把磁盘塞满。
