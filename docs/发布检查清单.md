## 为什么单独列「环境相关」

这几类东西**写错了不会立刻报错**，只会在换机器、换 Python 版本、别人 clone 时才炸：

| 类型 | 典型事故 |
|---|---|
| 依赖表 | 新包忘了加进 `run.py`，别人装完跑不起来 |
| 环境变量 | 换了名字没同步文档，配置不生效但没人知道 |
| 数据库迁移 | 代码先上线、迁移没跑 → `Unknown column` |
| 路径 | 用了绝对路径，换机器就找不到文件 |

这几项每次都要过，宁可多花五分钟。

## 正式版发布流程

```bash
# 0. 先把改动提交（脚本会检查工作区）
git add -A && git commit -m "..."

# 1. 预演（不改任何东西）
python3 scripts/release.py --version v16.0.0

# 2. 真发布
python3 scripts/release.py --version v16.0.0 --apply
```

脚本会依次做：

| 步骤 | 内容 |
|---|---|
| 1 | 检查工作区干净（有未提交就退出） |
| 2 | 跑静态检查 + 全部测试（不过就退出） |
| 3 | 打附注 tag `vX.Y`，并把 **`正式版`** 移到它上面 |
| 4 | 打包 `release/nao-vX.Y.Z.bundle`（**带 tag**） |
| 5 | 生成 `docs/RELEASE-NOTES.md`（相对上个版本的提交列表 + 升级/回滚命令） |

### 版本号约定

| 场景 | 例子 |
|---|---|
| 新功能、可换行为的改动 | `v16.0.0` |
| 修 bug、调参数 | `v16.0.1` |
| 只改文档 | 不打 tag |

### 「正式版」标签的含义

- `正式版` 永远指向**当前线上跑的版本**
- 用 `git describe --tags --exact-match 正式版` 看现在线上是哪个版本
- 回滚：`git reset --hard v14.1`

## 测试目录结构

```
tests/     功能测试（分模块 + 冒烟）
  test_chat.py      聊天链路：解析、分条、延迟、群聊闸门
  test_memory.py    记忆与检索：预算、BM25、时间线、画像
  test_life.py      她的生活：状态、事件、日记、关系、摩擦
  test_ai.py        模型与感官：反 AI 腔、超时、视觉、语音
  test_persona.py   角色卡：加载、切换
  test_reading.py   读小说：抓取解析、OCR、进度、分享
  test_infra.py     基础设施：线程池、连接池、事件、版本
  test_baseline.py  行为基线：重构前后不能变的行为
  test_smoke.py     冒烟：能启动、命令齐全、状态可注入

checks/    前置环境 + 迁移（与 botv 同级）
  test_env.py       依赖、环境变量、静态检查、目录结构
  test_migration.py 备份 SQL、去重键
```

一键跑：

```bash
python3 scripts/run_tests.py          # 两个都跑
python3 scripts/run_tests.py --fast   # 只跑 tests
python3 scripts/run_tests.py checks   # 只跑 checks
```
